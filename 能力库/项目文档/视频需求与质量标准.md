# 视频生产与质量标准

## 1. 当前生产架构

```text
html-only：Dify 生成内容和 HTML → 浏览器预览
black-frame：Dify 生成 HTML + 口播文案 → MiMo TTS/提供音频 → BGM、字幕、MP4
full：Dify 生成 HTML → HeyGen 数字人和口播 → BGM、字幕、MP4
```

`full` 中 HeyGen 负责数字人形象、中文口播和口型同步；`black-frame` 不调用 HeyGen。产品 UI、字幕、数据卡片、流程、CTA 和元素级动效均由 HTML/CSS/GSAP 制作。

## 2. 交付规格

- 平台：抖音、视频号、快手、小红书。
- 画幅：9:16。
- 分辨率：1080×1920。
- 帧率：25 或 30 fps。
- 时长：**不设目标时长**（真值见根目录 `AGENTS.md`「口径」）；文案写多长成片就多长，以最终口播真实时长为准，不通过加速掩盖超长内容。平台侧 25–35 秒只是习惯值，不是交付门槛。
- 语言：简体中文。
- 封装：H.264 MP4。
- 响度：约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。
- 音画时长差：小于 100ms。

## 3. 输出模式

- `full`：显示 HeyGen 数字人小窗（固定在右上角，几何写死，见第 4 节），并使用 HeyGen 口播音轨。
- `black-frame`（历史模式名，实际为无数字人模式）：必须零占位；不得出现数字人窗口、头像、黑帧小窗、纯黑保留区或等价空白窗口。删除窗口后必须回收左上/右上占位区域，顶部内容不得继续避让或留下空槽。使用 MiMo TTS 或用户提供的口播音频。
- `html-only`：只输出浏览器预览，不生成音频和 MP4。
- `black-frame` 仍必须保持真实口播驱动场景、字幕和元素级动画，不得退化成无音频的静态 HTML。

## 4. HeyGen 数字人小窗（仅 full）

小窗**固定右上角、全片不动**（2026-11-17 定）。原因不是审美，是可计算：位置一旦固定，
版面就能自动避让；位置由模型即兴决定时，避让只能靠人眼看。

| 项 | 值 |
|---|---|
| 尺寸 | 270×480（刚好是 HeyGen 9:16 输出的比例，不裁头） |
| 位置 | 距顶 120px、距右 44px → 占 x 766–1036 / y 120–600 |
| 圆角 / 层级 | 24px；`z-index:66`（低于字幕 70，字幕永远压在小窗之上） |

- 位置与尺寸的唯一真值在 `H01Z`（写进 `#stage` 的 `--pip-*` 变量），提示词里不许再各写一套。
- 右上角保留区里不放标题、kicker、角标、卡片、组件、数据与照片；顶部区文字右边界 718px。
- 本地 `sync_video.py` 按 `--pip-*` 自动让位：收不开宽度时把整块文字下移到小窗下方（y > 632）。
- 小窗必须持续可见；不淡出、不隐藏、不换位置。`black-frame` 线则必须零占位（见第 3 节）。

## 5. 单条视频内容结构

每条视频只讲一个核心主张，不按素材的时间顺序讲：

1. 第一句：直接给出 `distill.thesis`（判断句）。
2. 第二句：把结论推到代价、反常识或后果上。
3. 中段：按 `strategy.argument_order` 逐条展开，每个论点 1–2 句，先论点后证据。
4. 结尾一句：回收主张，可以被单独截出来当金句。

信息密度固定为：

- 1 个主张（`thesis`）。
- 支撑主张的论点（`arguments[]`），条数由素材决定；每条要么有证据，要么明确标记 `support=none`。
- 1 组最强证据。
- 1 个收束句（不强制 CTA）。

内容规则（提示词层，靠模型自觉）：

- 禁止时间线流水账：不按素材的时间顺序叙述，过程、行程、寒暄不写。
- 禁止照搬素材：用自己的话讲论点，原话只在关键句上短引用。
- 禁止漏讲主张：讲的每屏都要服务 `thesis`，`argument_coverage` 报清哪个论点落在哪句。
- 不设配额：论点数、句数、字数、屏数全部由内容和模型判断。
- 没有时长目标：文案写多长，成片就多长；`target_duration_seconds` 只作 HTML 编排参考，最终以真实 TTS 时长为准。

唯一的拦截项是"时间连接词成串"（≥5 处即判在按过程复述，触发一次自动改写）；其余（素材重合率、转述处数、自报覆盖、字数句数）只写进 `content_diagnostics`，提示但不阻塞。

中文口播按约 4.0–4.5 字/秒估算；估算值只用于编排，不用来裁剪内容。

## 6. UI 与组件

- 组件用可复用的高保真表现手法（同一套颜色、间距、形状语法），通过文案、数字、行业、流程变量适配内容；形态**只能取编号组件**（`U*`，见 §7.2 与 `components.css`），不自创图形。
- 不要求每次提供真实产品截图，但不得把生成示意图冒充真实产品截图。
- 示例数据必须标记“场景演示”或“示例数据”，但只在画面确实展示虚构数值或虚构界面时，于该处标 1 处；纯观点、情绪、叙事画面不标注，禁止每屏盖标注水印。
- UI 演示应表现完整动作：输入、筛选、点击、展开、状态变化、流程推进和 CTA。
- 字体、颜色、间距、圆角、阴影和组件层级由模型根据本次主题统一设计，不使用固定模板。
- 不接受默认卡片：组件形态必须由本屏要给出的证据推导——数字、对比、先后、状态变化、判词或画面；判定标准是“遮住文字后，画面结构本身仍在表达这一屏的意思”。
- 同一支视频内组件语法必须统一（圆角、描边、标签、间距同一套）；不同视频之间不得复用同一套组件骨架和配色。
- 生成端先做设计定调：一句话视觉隐喻、一个主色相 + 一个强调色 + 一组中性阶；形状语法（圆角、描边、标签形态）由这个隐喻统一，**字阶、间距和对齐不统一冻结**，由每一屏按自己的构图决定。全片只统一颜色、字体栈、圆角、描边、缓动和时长。
- **构图在分镜阶段分配，逐屏不同**：A08 为每屏写 `composition`（`family` / `text_zone` / `align` / `scale` / `why`），相邻两屏 `family` 不能相同，全片至少 `min(4, 屏数)` 种，首屏与末屏的 `family`、`text_zone`、`scale` 不能三项全同。单屏场景节点照账本执行（逐屏生成时账本随每屏一起下发），不各自即兴；`check_composition_variation.mjs` 量真实 DOM 复核。
- 排版：同屏文字层级、每行字数、标题行数和主对齐方式由构图决定，判断标准是层级清楚、断行自然、可读；四周留安全边，不贴边。
- 组件清单只有一份：`能力库/动效库/` 的编号库是受控白名单，模型按编号取用、在参数内调整（见 §7.2）；视觉风格不给清单，由本片隐喻决定，避免示例被当成模板。
- 每个场景的主内容垂直中心以 700–1100px 为舒适区、640–1160px 为硬边界；标题、正文、数据组件和当前字幕不得重叠。长标题显式断行，避免单字成行。装饰层（低透明度、渐变文字）不计入重叠。**这些由 `layout_composer` 在生成端保证**：标题均衡折行（`text-wrap: balance`，不再叠 `word-break: break-all`，否则会把词从中间劈开）、**字号 = 栏宽 ÷ 每行字数，而且主角色先要一行装下**（`solve_scale()`，输入只有栏宽、字数、硬换行、可用高度；不读 `data-composition-scale` 猜大小）、文字栏恒为 840（左 120、右 120 版心留白，一栏式之后不再有 780/760/900 的窄栏分支），`.scene-copy` 的直接子元素一律参与流式布局（模型写的绝对定位不生效）。**一行装得下就不许折行**（2026-11-19 定）：840 栏里 9 个字上 90px、10 个字 80px、11–12 个字 70px，13 个字以上才折成两行。折行前先降档把一行排满——不降档的话 110px 一行只放 7 个字，9 个字折成两行再被 `text-wrap: balance` 拉平，每行只用掉 550/440px，右边空出 290px，观众看到的就是「明明还能塞三个字却换了行」。
- 在视觉隐喻统一、组件语法统一的前提下，允许模型自由决定栅格、字阶、外边距、组件数量、动效形态和过场方式；不得使用运行时随机或与内容无关的漂浮、无限粒子。
- 不设常驻页眉、页脚、品牌角标、章节编号或水印层；画面只服务于当前这一屏的内容。
- 字幕不交给模型：HTML 里不出现字幕容器、条目和样式，统一由本地 `sync_video.py` 在渲染前注入；支持用 `字幕/手写字幕.srt` 完全接管文案和时间码。
- 同一场景内的状态切换必须重叠（先入后出）；成片不允许出现只有背景的空屏，哪怕一帧。渲染后由 `detect_blank_frames.py` 检测，`repair_blank_frames.py` 用前一帧修复孤立空帧（只判真正的孤立单帧；"先满、后归零、再回满"这类逻辑问题由 `check_html_timing.mjs` 拦，见 §7.3）。
- **照片与文字永不相交**：`layout_composer` 按照片矩形给文字让位；让不开时等比缩小照片（保比例、留 24px 间距），横向挤不出 240px 就改成上下分带。inset 照片（<85% 画幅宽）上不许压字。分带判据不是固定像素：照片宽度 ≥80% 画幅（900 宽的 `band` 也算）、上下任一侧让开之后还剩 ≥520px 字位，就算"分带"，文字整块落到另一侧。
- **每一屏的主视觉由照片或设计过的 HTML 背景承担**。图像计划（H01P）逐屏决定 `role`，**`role` 决定照片形态，不是一个名字**（H02SK 落版值，2026-11-17 起）：`band` 通栏横带 900×560（1.6:1，占屏约 24%，放上带或下带）；**2026-11-19 起左右并排整体删除**，`inset` / `portrait` / `thumb` 也全是**上下通栏横带**，只差高度：`portrait` 520 / `inset` 360 / `thumb` 300（`band` 按标题字数 600 / 420 / 300）。照片宽度一律 840，放上带或下带，文字占另一条整带；以前并排时文字栏只剩 300–440，标题被挤成 3 行 4 字、断行还落在词中间；`texture` 满屏降对比；`html` 不生成照片、由 CSS 背景和排版承担。**照片永远是小内容块，占屏最多四分之一**——以前 `large` 是 1080×900 通栏（47%），一张图吃掉半屏，文字只能挤进窄栏自己折行。`large` 现在等同 `band`，只作旧稿兼容。模型给的 `x/y/w/h` 不生效，构图要按这个形状写；**生图尺寸也不归模型选**：`size` 由 `role` 推导（`band` → `1536x1024`、`inset`/`thumb` → `1024x1024`、`portrait`/`texture` → `1024x1536`、`html` → 空），只留 gpt-image-1 认的三种尺寸。照片由本地 `generate_images.py` 调 GPT Image API 生成，HTML 用 `<img src="{{IMG:图片id}}">` 放进版面；无图屏写 `data-visual="html"` 和 `data-anim="bg"`。整片至少保留一张真实照片，图像不用于伪造产品界面。
- **一栏式版面（2026-11-18 定，唯一版式）**：画布 1080×1920，内容只有一栏——左 120、宽 840（右 960）、上 150、内容底线 **1533**。照片、组件框、文字同宽同栏，竖着往下排，整块在 150–1533 之间垂直居中。字幕占 1549–1670，内容一律不碰。
- 安全区（`check_html_layout.mjs` 报告，照片和文字都量）：左右 120（120–960）、上 150、下 1533。安全区之外只允许纯背景，不放任何内容元素。
- 字号解法（`layout_composer.solve_scale`，2026-11-19 定稿）：标题只有五档 **110 → 100 → 90 → 80 → 70**。**第一轮先找「主角色一行装下」的最大一档**——840 栏里 ≤7 字用 110、8 字 100、9 字 90、10 字 80、11–12 字 70，一行排满（810/840 以上）；**第二轮才退回「高度装得下的最大一档」**，那是字数超过一行上限（>12 字）或模型写了 `<br>` 硬换行时的必然折行，此时第一行按下面的切行点排。副角色一律从主字号按比例推：`lead` **0.70**（2026-11-19 从 0.90 降下来：0.90 时导语和标题只差 11px，成片里两行字看着一样大，观众会以为这一屏有两个标题）、`num` 等于标题、`note`/`label` 0.50、`accent` 0.70，正文 = 标题 × 0.40（地板 24）。`lead` 的可读下沿 46px，保证它严格是标题的 0.7，不会在标题落到 70 档时被顶到 60（那样主次又糊成一样大）。模型不写 px、不选档位。
- 标题换行由代码定，不交给浏览器（2026-11-19 定）：`H02SK` 对超过 12 个字的 `title` / `lead` 先按标点切段、写死 `<br>`（标点跟着前一个分句；切点取最接近均分的位置；没有标点就按字数均分，12 字以内不切）。`layout_composer` 再用「最长那一行」反算字号上限：840 栏、最长行 8 字 → 105 → 100 档；11 字 → 76 → 70 档。以前 14 个字的标题一律吃 110px（7 字/行），第 8 位恰好是逗号，`line-break: auto` 的避头尾让 7+7 不成立，`text-wrap: balance` 再把三行拉成 5/5/4——「取消的是强制性，不是反对努力」折成「取消的是强 / 制性，不是 / 反对努力」，词被劈开、逗号夹在中间。纯汉字 14 字碰巧能 7+7，所以最后一屏「看着没问题」，那是巧合，不是规则。

- 照片只有一种落法：**上下通栏横带，且照片与文字是一组**（2026-11-19 定，左右并排已从生成端删除）。宽度一律 840（左 120 到右 960），高度看 `role`：`band` 按标题字数 600 / 420 / 300、`portrait` 520、`inset` 360、`thumb` 300、`texture` 620。整组（文字块 + 24 + 横带）在 150–1533 里垂直居中，谁在上由 `slot` 决定，两者间距**恒为 24**。
  **只有 `full` 才是满屏**（2026-11-20 定）：`texture` 以前被当成满屏底纹写 1080×1920，`layout_composer` 又用 `slot != "full"` 判断分带，认定这屏不需要让位，media_fix 再把满屏图压成横带时 anchor 已被重置——文字就压在照片上（s06 实测正文 96px 整块落在图里）。现在 `texture` 和别的 role 一样落横带，`full` 在 `H01PV` 早已归一成 `band`，生成端写不出满屏照片。
  排版用 flex 列实现，不用绝对定位算坐标：文字块的真实高度只有浏览器知道（换行、字体度量），自己算出来的 top 和真实高度差几十像素，就会变成「规则写 24、实际 200」——2026-11-19 之前那个 300px 的空隙就是这么来的。照片永远在安全区之内，「贴画布边」在生成端就写不出来。
- 视觉风格、色彩、字体搭配、版式和质感全部由模型根据内容决定，不套用固定模板，也不规定方向。若用质感层，用 `#stage` 伪元素实现，z-index 低于字幕 70，不新增带 `scene` 类名的 DOM 节点。
- 字体只用已声明 `@font-face` 的无衬线字体（PingFang SC、Noto Sans CJK SC、Microsoft YaHei 等），不引入未声明的衬线字体。
- **组件永远跟着自己那一屏的明暗走**：`components.css` 的 `--ui-*` 由 `layout_composer` 按每屏 `data-bg-tone` 发一份，根节点写错也不影响；组件字号地板 `--ui-scale`（下限 1.55，24px 基准 ≈ 37px），窄栏（<560px）里 `.ui-grid` 退成单列、`.ui-steps` 退成纵向，不硬塞多列。**卡片字号另有一把尺**（2026-11-20 定）：`layout_composer` 每屏发 `--ui-card-title` / `--ui-card-body`，等于**本屏主字号 × 0.6 / 0.4**，`.ui-card` 的 `h3` / `p` 读它们。以前 h3/p 是 `34 / 24 × --ui-scale`，34:24 不是 0.6:0.4，同一个系数永远对不齐——主字号 80px 时实测落到 56.1 / 39.6（0.700 / 0.495），卡片和标题的层级差看不出来。**`.scene-copy` 本身发 `color: var(--ui-ink)`**：组件里没显式上色的元素（`.ui-table` 的 `td`、`.ui-toast`）以前继承到文档默认黑，深底上整行看不见——成片里就是"组件列表是空的"。
- **HTML 只做文字和动效；界面元素只能取编号组件**：`U01–U17`、`U20`、`U48–U53`（信息卡片、步骤条、网格面板、状态标签、数据行、便当网格、瀑布流、名片、滑动行、色格阵、聊天气泡、表格、柱状图、折线、价格表、通知条、头像组、时间轴、播放器、文件卡、地图卡、目录页、表单、标签云）由 `components.css` 提供，模型只填文案和数字，不写样式、不自创图形；编号之外的图标、插画、线条、色块、进度条一律不许画。具象视觉由照片承担；`role=html` 屏靠字号、断行、对齐和留白承担画面。
- **没有全片底色层**（2026-11-14 定）：不许再出现 `#background-layer` 这种"整片共用一层底"的结构，也不许让模型现场写背景 CSS/JS。每一屏的底色由该屏的背景卡编号（B 系列）**自带**，卡在 `presets.json` 里有 `surface=opaque`、`base`（底色）和 `ink`（字色三件套）。
- **版面由 composition 枚举本地生成**（2026-11-14 定）：场景节点不写文字的字号/字色/位置/行高/对齐，只把 `composition` 的 `text_zone` / `align` / `scale` 抄进 section 的 `data-composition-*`，文字元素打 `data-role`（title/lead/body/note/num/label/accent）。`sync_video.py` 调 `layout_composer.py` 按枚举 + `data-bg-tone` 生成 `[data-scene] .scene-copy` 作用域的 CSS。**字号不用枚举、也不让模型选**（2026-11-17 定）：由 `solve_scale()` 按上面那条几何规则算出来，模型给的 `scale` 文本只剩 `vertical`（竖排）一个有效值；字色由每屏背景卡的 `ink` 生成。
- **背景只有一族**（2026-11-16 定）：全部是 canvas 动态卡（B23–B39），每张自带底色与字色三件套；不再有深色/浅色两族。**模型与骨架都不判色、不写 `data-bg-tone`**：`H02SK` 按背景卡的 `ink` 把 tone 落在 section 上，`sync_video.py` 再把根节点对齐到多数屏的 tone，字色与 `--ui-*` 由本地生成。
- 背景卡全部是 canvas（B23–B39），图案画在离屏画布上，再铺 `base` 底色合成，**画布自身必须不透明**；重绘走 `hf-seek` 的 `e.detail.time`，不用 `requestAnimationFrame`/`setInterval`/`Math.random` 当驱动。`.scene` 外壳、`data-scene`、`data-sentence-ids`、`data-start`、`data-duration` 必须保留，字幕与时长同步依赖它们。
- **文字不能直接坐在密集图案上**（2026-11-16）：高密度背景族（`bg_family` 是 `block` / `line` / `dot`，例如棋盘、扫描线、网点）与文字同屏时，文字块必须有自己的可读性保障。`H02SK` 把族写进 `data-bg-family`，`layout_composer` 给 `.scene-copy::before` 生成向外的径向柔光。**垫层跟着文字走，不跟着容器走**：`.scene-copy` 是 `height:auto` 的内容盒，柔光只比文字块外扩 56/44px；以前容器被 top/bottom 拉成 780×1420，柔光就成了一块占屏 80%、字只占中间一小条的暗块。判据是"字看得清"：垫层压掉的是背景的局部权重，不改背景卡密度；这一层还救不回来，说明背景卡选错了，换卡而不是继续叠遮罩。半屏照片（`slot` 是 `top`/`bottom`）与背景卡的接缝由同一条链路做 240px 渐隐，两件事不要混成一层遮罩。
- 每屏两层：底层（照片，或底色与光）、顶层（文字）。无图屏不靠画结构撑画面，靠字级、断行、留白和一句够狠的话；只有小标题加几行小字、又没有照片的屏属于不合格。
- **每屏至少三层信息**：标题（主张）+ 支撑（1–3 行）+ 视觉锚（数字/标签/对比/可引用句）。只有标题和一句说明的屏视为内容不足，应拆屏或补支撑，不得靠放大字号和留白凑时长。
- **内容块垂直居中**：内容少时整体在安全区内居中，不允许顶到顶部 200px 处、下方空一大片。
- **元素间距**：标题/支撑/视觉锚之间至少 32px；照片横带与文字带之间 24px；满屏图上的文字块与画面边缘保持 90px 安全边。

## 7. 动效要求

每个中段镜头必须包含语义相关元素级动画。整片不应出现长时间静止：每屏至少一次可见变化，变化由语义触发，不按固定秒数凑，优先使用：

- 信息逐项入场。
- 数字递增。
- 搜索结果逐条出现。
- 路径逐步点亮。
- 鼠标点击和页面状态变化。
- 局部放大或焦点标注。
- 语音关键词高亮。

动作工艺基线：

- 入场幅度由元素尺寸和构图决定，以“看得见”为准，不设固定像素上限，也不用个位数像素的微动凑数；单次时长由幅度决定，逐项 stagger 60–100ms；同一屏缓动不超过 2 种。
- 每个场景至少 2 个可寻址的组件级动作，其中至少 1 个必须是状态变化（数值、进度、选中、展开、路径点亮、状态标签切换）；只有位移加淡入不算。
- 每屏只设一个主运动（`priority=main`），其余为次级；次级在主运动落定后 80–160ms 跟随。
- 动效时间按真实词触发：`start_trigger` 为 `word:关键词` 的节拍写成 `at(cue('s04','关键词',1.2))`，由本地注入的 `window.__cue` 换算成秒，不手猜。
- 动作在场景内要分布开，不得全部挤在开头 0.5 秒；口播说到之前或同时，画面给出对应变化。
- 过场由转场设计节点逐切点决定：切在哪个语义停顿、用哪种 PT 类型（`PT01–PT15`，清单见 `sync_video.py` 的 `__ptList`）、多长，由语义定；硬切也是合法转场，不必每屏都加动画。
- 场景显隐由页面自己驱动（按 `data-start` / `data-duration` 计算），本地不再注入兜底运行时；页面没写驱动就是全部场景叠在一起，契约检查会拦。
- **同一 scene_id 只能出现一次，scene 只引用分镜里存在的 `sentence_ids`。** 单屏场景节点只输出自己那一屏；合并阶段按分镜去重、丢弃越界 scene 并校正句子锚点。成片不允许出现 0.12s 级别的闪屏，也不允许一屏停 7–8 秒后长时间静止：单屏时长应跟句子窗和内容量匹配，异常时先修分镜/合并，不要靠拉伸动画掩盖。

### 7.1 页面节奏与页面边界（2026-11）

- 页数、每页讲几句不设配额，由分镜导演按内容和口播决定；不要求“一页一句”或“一页三句”。
- 每一屏必须写 `data-voiceover`，逐字等于这一页实际说到的那段口播原文。合并阶段从分镜的 `voiceover_text` 自动注入，模型不用额外维护。
- 本地 `sync_video.py` 用这段原文在真实词级时间码里定位页面起点；页长 = 下一屏起点 − 本屏起点。不再按作者期时长在句子内部按比例切。
- 页面切换要落在真实口播的换气/语义停顿上。切在词中间，或一页只有 2 秒却塞 4 个信息点时，先修分镜，不要靠拉伸动画掩盖。
- **每屏第一帧是纯背景**（2026-11-11 改）：照片、组件、文字全部从无到有，由动效入场；允许首帧只有底色和光，但不允许首帧只有字幕。所有可见元素必须在场景开始后 1.2 秒内开始入场。
  实现落在 `H02SK`（2026-11-18 晚）：凡是 1.2s 内就有卡开场的层，模板在屏起点统一补一句 `timeline.set(sel, {opacity:0}, at(0))`；没有卡覆盖的层由模板补一条最保守的入场（屏首不可见 → 0.35s 起淡入 0.5s），同时在 section 上写 `data-motion-skipped` 点名 `H02S` 该补哪一条——**每个内容层都必须有入场，照片也一样**，不许直接出现在画面上。
- 图片层不得在屏内出现 `opacity 1 → 0 → 1` 的回落；进入屏的视觉承担者不得先归零再淡入。转场只许一个方向。
- **屏内动作必须让开转场窗口**（2026-11-19 定）：进入屏在 `data-pt-dur` 秒内被快照/遮罩盖着，这段的动作观众看不见。`sync_video` 从 `__pt(...)` 调用里把每屏的转场时长写到 `data-pt-dur`，`patchTimeline` 把落在窗口内的动作统一抬到窗口之后。以前 T26 的 1.0s 入场整段落在 flip3d 的 0.92s 里，转场一结束元素已经到位，成片里就是「转场完直接出现」。
- **屏内 builder 的位置是相对秒，骨架/转场 builder 是绝对秒**：按 builder 形参判定（`function(timeline, at)` = 相对，`function(timeline)` = 绝对），相对秒无条件补屏起点。以前用「位置 < 屏起点」去猜，11.7 秒的长屏后半段永远猜错，整条动作提前一个屏起点（s02 的 chip 本该 11.52s 出场、实际 8.33s 就冲出去了，屏尾 4.7 秒全静止）。
- 转场脚本的位置必须是绝对秒：builder 第一行写 `timeline.__absolutePositions = true`，用 `__sceneStart(to_scene)` / `__cueAbs(...)`；不要把 `__cue()` 的相对秒直接当绝对位置，也不要用代理对象 + CSS 变量写 scene 的 `opacity`。

禁止：

- 静态 PNG 直接当作完整动效镜头。
- 只做整图缩放、循环呼吸、随机漂浮或无限粒子。
- `yoyo`、`repeat` 等往复或循环动作（黑帧 04 的 H02S 和 A10 都明令禁止，H03 会报警告）。
- 动效的方式、节奏和动作形态由动效设计师根据画面决定，不设动作类型配比。H03 只报告哪些组件没有任何动作（覆盖率），不规定做多少。
- 动效纪律（H02S 写入提示词）：不按 `scene_purpose` 发固定配方，动作由这一屏的内容和口播重音决定；每屏至少两种动作族（入场、状态、结构、绘制、空间、文字、模拟交互），全片至少覆盖五种；每屏结尾留一小段 hold；全片至少三种不同开场，并复用骨架定的 2–3 个母题动作。
- **文字出现方式完全交给模型**：不提供样式清单，不要求每屏按同一套顺序入场。只约束结果：相邻两屏的文字出现方式必须一眼看出不同；全片不同做法不少于 min(4, 屏数)；至少部分屏在 t=0 没有文字，由照片或设计背景先撑住；禁止把“半透明变实”或“浅灰变强调色”当入场，文字从不可见开始时必须同时有另一种看得见的形态变化。
- canvas 图层由时间线驱动：`bgkit.bind()` 用哑 tween 读 `timeline.time()` 重绘，`hf-seek` 兜底；**不要把绘制挂在 `onUpdate` 回调里**（会被 seek 抑制，画布全空）。GSAP 的直接属性动画仍只作用于 DOM 元素。
- 所有元素同时出现后长时间静止。
- 无语义的幻灯片硬切。
- 随机时间和无限循环。
- **对整屏图层做 `filter` 动画**（brightness/blur）：无头捕获会在滤镜起始帧拍到整帧黑屏，成片表现为单帧闪黑；压暗改用 opacity 或半透明遮罩。

动画必须由语音内容或明确时间线驱动。转场发生在语义停顿处，不在动作或关键词中间切断。

确定性质量门禁：

- 画面里出现的每个组件都要有自己的动作（进入 + 至少一次状态变化），整屏只有一个淡入等于没做动效；渲染后跑 `check_motion_profile.py --html index.html` 看逐屏报告，标"弱"的屏需要补主运动（只报告，不阻塞）；HTML 必须使用可寻址 GSAP 时间线的 `from/fromTo/to/set` 动作 API，循环批量生成的动作也要有明确目标和结束时间。
- `H03` 的 `motion_report_json` 会给出每组 `animated_elements / anim_elements` 与 `coverage`，未被任何动作命中的组件会列在 `uncovered` 里，作为人工复核信号（只提示，不阻塞）。
- 动效必须有目标、状态变化、开始/结束和语义理由；不能只有空泛的“出现”。
- 随机性只能发生在作者期变体选择（布局、组件、动效、过场各选一个变体），运行时禁止 `Math.random`、随机时间和随机颜色。
- 最终渲染前执行 `check_html_contract.py`、`check_html_timing.mjs`、`check_motion_variation.mjs`、`check_composition_variation.mjs`；渲染后执行 `check_final_video.py`。时间线检查拦整屏不可见、图片闪回和动作越界；动效差异只报告相邻同签名、文字/图片动作种类，不阻塞；构图差异默认只报告，加 `STRICT_COMPOSITION=1` 时相邻或首尾两屏同构会拦。技术时间轴、媒体时长、同步标记、动效时间线或无数字人零占位任一不达标就停止交付。

### 7.2 照片包裹、虚拟指针与背景动效（2026-11 放开）

此前正文一律不做图形。现在放开三样，各有明确边界：

- **照片包裹**：允许对照片块做圆角（≤30px）、整圈或单边描边（≤3px）、边缘受光、聚光跟随、轻微跟随倾斜（≤8°）。它是对已有照片的处理，不新增图形；**同一支片子只用一种包法**，不能每屏换。
- **虚拟指针**：原先靠鼠标 hover/move 触发的效果，改成由时间线给出指针坐标（归一化 0–1），再由 CSS 变量驱动视觉效果。视频里没有用户，指针是表演出来的，必须由 cue 驱动、有明确起止。
- **片头/过场背景动效**：仅限开场 3 秒内或两个场景之间，低对比、单次、不循环；正文屏仍以底色和光为主。禁止与字幕区重叠的强动效。
- **界面组件（卡片 / 网格 / 边框 / 图标 / 状态条）**：允许使用，但必须来自 `能力库/动效库/` 的组件编号，由组件样式库提供类名与结构；模型只选编号、填文案和数据，不手写图形。组件样式同一支片子只统一一套（圆角、描边、间距），不同片子不复用同一套骨架。

仍然禁止：卡片、列表、图标、图表、进度条等具象 UI；canvas/WebGL 铺满整屏、正文直接压在其上且没有留白和压暗层；无限粒子、随机漂移、循环呼吸。

实现白名单与展开代码见 `能力库/动效库/能力卡.md` 与 `presets.json`；运行时为 `成品/workflow_runtime/assets/vendor/motion-kit.js`，由 `sync_video.py` 在渲染前自动注入。

### 7.3 入场与图层所有权（2026-11-12）

「图片先以最终态闪一下、再入场一遍」和「元素在屏尾最后几毫秒才出现」是同一个根子：**同一层被两个地方写**，以及**入场被当成可选项**。

硬规则：

- **每个 `[data-anim]` 内容层（`media`、文字、组件、`scrim`）必须在自己屏内从不可见走到可见，走完一次入场**；屏的第一帧不得是它的最终态。不接受任何"直接存在"的内容元素。
- 唯一的例外是背景：`#stage` 的底色/光和本屏 `[data-anim="bg"]` 背景层必须第 1 帧就在（"背景直接存在"），不参与入场，也不允许晚于屏起点出现。
- **同一个元素只许入场一次**：不许先 `set opacity 1` 再 `fromTo 0→1`，也不许出现 `opacity 1 → 0 → 1`。
- **转场只动进入屏**：只对 `[data-scene="to"]` 这个 section 做整页覆盖（或调 `window.__pt`），**上一屏一个元素都不许碰**；起点必须是切点，写在切点之前等于演给不可见的元素看。硬切 = 这一刀什么都不写。
- 入场位置取屏内 0.15–0.6s；动效位置不得越过本屏结束，越界不再静默夹到屏尾，而是记违规并被门禁拦下。

拦截方式：

- `sync_video.py` 注入的 `scene-offset-runtime` 记录 `window.__motionViolations`：位置越界被夹到屏尾、转场写在切点之前（进入屏还不可见的时候）。装了 `__pt` 运行时的页面不判进入屏写入——那正是转场的实现方式。
- `check_html_timing.mjs` 逐帧（1/30）扫描每个 `data-anim`：首帧即最终态、没完成入场、`1→0→1` 闪回、背景不在屏起点，以及上面两类运行时违规，全部写进诊断；`H02SK` 渲染时已保证每屏至少一条入场，`STRICT_RENDER=1` 时才拦。
- `detect_blank_frames.py` 只判真正的孤立单帧（比紧邻前后两帧都暗、且两帧都亮）；多帧暗段和淡入淡出属于入场过程，不算，逻辑问题归 `check_html_timing.mjs`。

### 7.4 页间转场（PT 族，15 张）

- 由 `H01T` 逐切点选编号（`PT01–PT15`，清单以 `presets.json` 与 `sync_video.py` 的 `__ptList` 为准）与时长（0.35–0.6 秒），`H03` 按切点表生成 `window.__pt` 调用；同一支片选 3–5 种，相邻两刀不同种。
- 起点必须等于 `window.__sceneStart(to_scene)`；早于切点写在 `visibility:hidden` 元素上，成片就是硬切。
- 只动进入屏的整页 `[data-scene]`，上一屏一个元素都不碰；不要用透明度淡入代替位移。
- 帧内不放文字（字由 HTML 承载）。
- 双图 shader 转场那批已删除，不进生产；页间转场只走 `PT01–PT15` 这一族。原因见 `能力库/动效库/来源台账.md`。

## 8. 口播、音乐和字幕

- `full` 使用 HeyGen 口播；`black-frame` 使用 MiMo TTS/提供音频。口播始终是主时间线。
- Dify 只生成 `voiceover_script` 和 HTML；MiMo TTS 在本地统一入口运行，音频落为项目的 `媒体/口播.mp3`。
- 字幕文案：默认按口播完整句子切分；把自写 SRT 放到 `字幕/手写字幕.srt`（或 `字幕/最终字幕.srt`）时，完全以该文件为准，跳过自动切句。
- 先确定最终语音，再由句子或词级时间码驱动场景、字幕和元素动画。
- `媒体/口播.mp3` 的实际时长是唯一主时钟。场景从作者期时间等比映射到真实口播时长；每个场景再通过 `data-sentence-ids` 与字幕 `data-sentence-id` 锚到对应完整句子的真实起始时间；元素动效的相对偏移和相对时长使用同一比例。禁止对已校准场景、字幕或媒体时间二次缩放。
- 同步后场景总时长、根 `data-duration`、口播、BGM、成片视频和成片音轨必须一致；字幕不得越过成片结束时间。渲染后执行 `normalize_final_audio.py`，再执行 `check_final_video.py`。
- 说到搜索、数字、流程或 CTA 时，对应视觉元素同步出现。
- 全片字幕按完整句子呈现：每个 `。！？!?` 结束的完整句子单独一条，不按字数截断或拼接半句。
- 默认字幕规格（本地注入，可改）：中下方 `bottom:13%`，水平居中，**文字宽度随内容自适应**（`width:auto`，上限 80% 画布宽度，多行时自动换行），字号 45px、行高 1.35、字重 700、白色文字；无底板、无描边、无圆角、无内边距，只用双层柔和黑色投影保证亮背景可读。字幕不得用整条背景板或全屏遮罩。
- `full` 不遮挡数字人和产品 UI，`black-frame` 不遮挡产品 UI。
- 背景音乐不能压过口播，自动补齐到实际成片时长。
- ASR/HeyGen transcript 只提供时间码；字幕文字必须使用已批准 `voiceover_script` 自动校正同音字和错别字。若没有 transcript，本地 ASR 只作时间码回退，最终仍需人工检查断句。
- 本地 ASR 会重试两次；仍失败且项目有 `口播文案.txt` 时，`sync_video.py` 按完整句子和字数比例把音频时长分配给字幕与页面，并写 `字幕/估算说明.txt`。这是应急模式，页面切点和动效 cue 只能近似，不能当成交付标准；修好 ASR 或补 `字幕/口播时间码.json` 后必须重跑。

## 9. Storyboard 与动效计划

分镜至少表达：

- `voiceover_text`
- `argument_id`
- `visual_source`
- `visual_brief`
- `on_screen_text`
- `transition`
- `sync_rule`

动效计划必须与口播 cue 对应，不能先列后续信息，也不能只给通用“淡入/缩放”。`H02S` 自己写 `copy`/`components` 时就定了 `data-anim` 名字，动效段直接引用同一批名字；编号只能从 `motion_budget` 与目录清单里取。

## 10. 最终质量门禁

结构由生成端保证：`H02S` 输出单屏规格 JSON，`H02SK` 用固定模板渲染成唯一合法的 `<section>`，所以不存在"截断/未闭合/丢属性"的 HTML。本地检查器（`check_html_contract.py` / `check_html_layout.mjs` / `check_html_timing.mjs` / `check_composition_variation.mjs`）只把结果写进 `诊断/检查结果.txt`，**默认不拦渲染**。要恢复旧行为跑 `STRICT_RENDER=1`。

内容侧另有一条门禁：A12 判 `rejected` 时 A16 拒绝打包，`package_error` 里列出原因；`needs_changes` 不拦，留给人工改。

模型不直接写 HTML，结构问题在生成端就不存在；诊断只告诉你观感与时间线的告警。只有在环境层面（缺 Chrome / Node / HyperFrames）才停止。

- [ ] 画布为 1080×1920；场景构图、布局手法（flex/grid/绝对定位/全出血）由模型自由设计。
- [ ] 实际时长符合内容需要，音画时长差小于 100ms。
- [ ] 口播、场景、字幕和元素动画逐句同步。
- [ ] 每个中段镜头建议至少一次可见语义动效，具体动作和密度由模型根据内容决定。
- [ ] 相邻两屏的文字出现方式不同，全片没有把“半透明变实 + 位移”当成唯一入场。
- [ ] 相邻两屏、首尾两屏不是同一套构图骨架；全片构图族不少于 min(4, 屏数)（`check_composition_variation.mjs`）。
- [ ] 每屏有 `data-voiceover`（逐字等于这一页的口播片段），页长由下一屏起点决定，不按作者期时长在句内切。
- [ ] 每屏第一帧就是纯背景（底色 + `bg`），随后 0.6 秒内内容开始入场；每个 `data-anim` 内容层都有且只有一次入场，没有"首帧即最终态"，没有 `1→0→1` 闪回（`check_html_timing.mjs` 逐帧拦）。
- [ ] 转场脚本没有碰上一屏；只动进入屏整页、从切点开始；硬切就是什么都不写。
- [ ] 转场脚本位置是绝对秒（`__absolutePositions` + `__sceneStart`/`__cueAbs`），没有裸 `cue()` 或代理对象写 scene `opacity`。
- [ ] 无图屏（`role=html`）带 `data-visual="html"` 和 `data-anim="bg"`，背景是设计过的结构，不是纯色空白；整片至少有一张真实照片。
- [ ] 每个时刻只出现一条完整句子字幕，句末标点完整，无截断和半句拼接。
- [ ] 首句就是主张，不是过程描述；全文只讲一个主张。
- [ ] `argument_coverage` 覆盖 `argument_order` 全部论点，没有漏讲。
- [ ] 没有时间线流水账，没有整句照搬素材（回看 `content_diagnostics` 的 `chronology_words` 与 `verbatim_ratio`）。
- [ ] 字幕位置、80% 最大宽度、45px 字号、1.35 行高和无底板文字符合固定规格。
- [ ] 回看 `check_html_layout.mjs` 的报告：文字有没有互相叠压、内容有没有出界（报告不阻塞渲染）。
- [ ] `full` 必须保留 HeyGen 数字人小窗，且不遮挡关键内容；位置和尺寸由本次构图决定。
- [ ] `black-frame`（无数字人模式）零占位，不包含数字人窗口、avatar 角色、数字人媒体、黑帧小窗、纯黑保留区或等价空白窗口。

- [ ] 案例、价格、CTA 和产品事实已确认。
- [ ] 响度约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。

### revideo 批（2026-11-15）的适用边界

- **T24 弹簧落位 / T25 摇摆归位**：只给单个元素（卡片、图标、角标），不给整段文字；T25 的摆动幅度大，只用于小元素。
- **X39 推挤换屏 / X40 拉远离场**：必须**两屏同时在画面里**（入屏层 + 出屏层），只在一层上用时退化成普通位移，这时不要选。
- **W26 文字镂空照片**：字号 ≥180px；同屏不再放第二张照片；镂空后字必须认得出。
- **U39–U47 注入式图形**：卡自己往目标里画 SVG，目标必须是**有尺寸的空容器**；指到文字节点会盖住字。
- **UA09–UA16 代码块**：一行一个 `div[data-line]`，最多 8 行；行级 diff 要 `data-old` / `data-new`，选区扫要 `data-mark`。
- 这批卡都不碰 canvas，不与页间转场抢同一层。
