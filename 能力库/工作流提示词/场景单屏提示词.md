# 单屏场景（逐屏生成）

你只负责**一屏**的画面。这支片子的每一屏由**真实照片或设计过的 HTML 背景**承担主视觉。一次调用只写一屏：一个 `<section>`、一段 `<style>`。动效由动效节点统一写，转场由转场脚本节点写。

## 输入

- `scene_json`：{{#h02i.item#}}（本屏的分镜，含 `scene_id`、`sentence_ids`、`voiceover_text`、`on_screen_text`、`visual_brief`、`composition`、`index`、`total`、`prev_scene`、`next_scene`）
- `skeleton_html`：{{#h01s.text#}}（结构骨架与图片基础样式，只读）
- `art_direction_json`：{{#h01d.text#}}（色彩、字体、材质、光、纵深；**字号和间距不在里面**）
- `component_grammar_json`：{{#h01c.text#}}（文字块、字法、状态语言、`data-anim` 命名规则；这套语法里没有图形）
- `image_brief_json`：{{#h01pv.image_brief_json#}}（全片索引：查本屏的 `role` / `why` / `html_brief` / 图占多大 / 文字压哪侧 / 镜头怎么动）
- `composition_ledger_json`：{{#h00.composition_ledger_json#}}（全片构图账本：每屏的 `family` / `text_zone` / `align` / `scale`）
- `design_brief`：{{#h00.design_brief#}}（含 `composition_warnings`）

## 只写 `scene_json.scene_id` 这一屏（硬性）

- 输出**恰好一个** `<section>`，`data-scene` 等于本屏 `scene_id`。多写或少写都算错。
- `data-sentence-ids` 逐字抄本屏的 `sentence_ids`；`data-start="0"`；`data-duration` 写本屏口播的估算秒数（按 4.0–4.5 字/秒）；`data-visual` 写 `photo` 或 `html`。
- 不要写别的屏、不要写字幕、不要写 GSAP、不要写 `<script>`。

## 本屏视觉编号（硬性，H00 已经定好）

- `scene_json.visual_budget.background`：本屏背景编号。**必须用，不得换。**
- `scene_json.visual_budget.components`：本屏组件编号。**必须全部用上，不得换、不得加别的组件。**
- 背景写法（`visual_budget.background_tone` 决定用哪一族，**两族不能混**）：
  - 全部背景卡 B23–B39（B22、B33 不存在）都是 Remotion 来源的 canvas 动效卡：`<div class="scene-bg" data-bg="B23" data-anim="bg"></div>`，不要自己写 canvas，H02SX 会建。它们绘制在透明画布上，画面底色由 `#stage` 统一给（深场），不要自己加底色。
- 组件：照抄能力卡里的结构，只填文案/数字；**不要写这些组件的样式**，不要自己画卡片、网格、线条、色块。
- 每屏（包括照片屏）都必须有 `<div class="scene-bg ..." data-anim="bg"></div>`，不能只在 html 屏加。
## 文字只写结构和角色，样式由本地生成（硬性，2026-11-14 起）

**你不写文字的字号、字色、位置、行高、间距、对齐——一个都不写。** 这些由本地按分镜枚举生成。

你只做三件事：

1. **section 上抄四个枚举**（从 `scene_json.composition` 逐字抄，不翻译、不改写）：
   ```html
   <section class="scene clip" data-scene="s01" data-composition-zone="left-middle"
            data-composition-align="left" data-composition-scale="超大单行"
            data-bg-tone="dark" ...>
   ```
   `data-bg-tone` 逐字抄 `visual_budget.background_tone`（dark / light）。它决定这一屏的字色：深卡配浅字，浅卡配深字。
2. **文字包进一个 `.scene-copy`**，每个文字元素同时打 `data-role` 和 `data-anim`（**两个属性同值**）：
   ```html
   <div class="scene-copy">
     <h1 data-role="title" data-anim="title">主标题</h1>
     <p data-role="lead" data-anim="lead">一句话引子</p>
     <p data-role="body" data-anim="body">正文</p>
     <span data-role="num" data-anim="num">128</span>
     <span data-role="label" data-anim="label">标签</span>
     <em data-role="accent" data-anim="accent">强调词</em>
   </div>
   ```
   - `data-role` 归版面（本地生成样式），`data-anim` 归动效（动效节点按它找目标）。少写 `data-anim`，这一屏的文字就没有动效，或者动效挂到整个容器上把版面拆坏。
   - **`.scene-copy` 本身不要写 `data-anim`**：它是版面的定位壳，不是一个可动目标。
   - **不要写 `data-fit`**：字号已经由 `data-composition-scale` 的档位决定，再挂 auto-fit 会把字号改掉。
3. **只给照片/遮罩/组件写定位 CSS**（`.s01-media` 的 top/left/width/height、`.s01-scrim` 的渐变），选择器一律以 `[data-scene="s01"]` 开头。

`data-role` 只有这六个：`title` / `lead` / `body` / `note` / `num` / `label` / `accent`。字号档、字色、位置都从它们和四个枚举推出来。

**为什么要这样**：字色只能跟 `background_tone` 走，字号只能从档位取，位置只能从 `text_zone` 取——所以"白字压浅底""字号失控""每屏字色各写一套"在语法上就写不出来。

## 样式不能打架

每一屏是**独立一次调用**写出来的，最后会拼进同一个文档。所以：

- 除 `.scene-copy` / `.scene-bg` / `.media` / `.media-scrim` 这些公共类，你自己的类名必须带本屏前缀：`.s01-media`、`.s01-scrim`。
- 所有选择器必须以 `[data-scene="s01"]` 开头。不要写裸 `.title`、`p`、`h2` 这类全局选择器，会污染其它屏。
- 不要给 `[data-role]` 元素写任何 CSS，也不要覆盖 `.scene-copy` 的定位。

## 这一屏的构图按分镜执行

`scene_json.composition` 是分镜给这一屏的构图决定（`family` / `text_zone` / `align` / `scale` / `why`）。

- `text_zone` / `align` / `scale` 三个值**原样抄进 section 的 `data-composition-*`**，位置和字阶由本地按它们生成，你不要手写。
- 你负责的是**内容归到哪个角色**：哪句是 `title`、哪句是 `lead`、哪个数字是 `num`。这个判断决定版面层次。
- 对着 `composition_ledger_json` 检查：本屏不能和你紧邻的前后两屏（`prev_scene` / `next_scene`）同构；如果账本里它们和你 `family` 相同，说明上游没给够差异，照抄枚举即可，不要自己改数值。

## 先读 role：这一屏由谁承担画面

`image_brief_json.images` 里本屏那条有 `role` 和 `why`。先读它，再落版：

| role | 这一屏怎么做 |
|---|---|
| `large` | 照片是大幅内容块，占屏 55%–75%，**不许铺满**；四周必须看得到背景卡。文字压在没被照片占的那一侧。 |
| `inset` | 照片是内容块，占屏 40%–70%，**不是底图**；另一半给文字或背景。 |
| `portrait` | 照片是一个视觉锚（人物/物件/局部），文字绕开它。 |
| `texture` | 照片降对比做底纹，文字是主体。 |
| `html` | **不放 `<img>`，也不画图形**。纯文字屏：靠字号、断行、留白承担画面；`html_brief` 写这一屏的字怎么排。 |

## 照片怎么放

- 照片占位要给文字让路：`inset` 宽 40%–60%、`portrait` 30%–45%、`large` 55%–75%；不管哪一档，**文字那一侧必须留够 470px**。留不下就缩照片，不许把文字压在照片主体上。

- 图片引用一律写成占位符：`{{IMG:图片id}}`。本地渲染前会替换成真实文件路径，**不要写 `媒体/图片/...`、不要写绝对路径、不要写 data URI**。
- `full`：`<div class="s01-media media" data-anim="media"><img src="{{IMG:s01}}" alt="" /></div>`。
- `inset`：`<div class="s01-media media media--inset" data-anim="media">…</div>`，`top/left/width/height` 写在本屏自己的 `.s01-media` 上。
- `portrait`：图片是视觉锚，可以局部裁切、框、圆或异形；文字绕开主体。**容器必须写 `media media--inset`**（只写 `media` 会被基础类钉成满屏，你给的 top/right 反而不生效，照片会被甩到左边）。
- `texture`：图片降对比、降饱和或加遮罩做底纹，文字是唯一主体。

标准结构（`full` 示例，只换内容）：

```html
<section class="scene clip" id="s01" data-scene="s01" data-sentence-ids="s01" data-start="0" data-duration="4.200" data-visual="photo">
  <div class="scene-bg" data-bg="B23" data-anim="bg"></div>
  <div class="s01-media media" data-anim="media">
    <img src="{{IMG:s01}}" alt="" />
  </div>
  <div class="s01-scrim media-scrim" data-anim="scrim"></div>
  <div class="s01-copy">
    <p class="s01-kicker" data-anim="kicker">一句引子</p>
    <h1 class="s01-title" data-anim="title">这一屏的主张</h1>
    <p class="s01-body" data-anim="body">支撑主张的一句话</p>
  </div>
</section>
```

## html 屏：用编号组件 + B 背景，不自己画

`role=html` 的屏不放照片；画面由 `visual_budget.components` 里的 U 组件 + `visual_budget.background` 的 B 背景承担。

- 必须保留 `<div class="scene-bg ..." data-anim="bg"></div>`（带 `data-bg="B编号"`）。
- 组件结构照抄能力卡，只填内容；不要在屏内写这些组件的样式。
- 组件之外可以排标题/正文，字号、断行、对齐、留白自己定。
- **GSAP 插件已注入并自动注册**，可以按官方 API 直接用，不要再 `registerPlugin`：`SplitText`（逐行遮罩 mask）、`DrawSVGPlugin`（`drawSVG:'20% 80%'` 部分绘制）、`MorphSVGPlugin`（形状变形）、`MotionPathPlugin`（沿路径 + autoRotate）、`EasePack`（`RoughEase` 手绘抖动）、`CustomEase`（path 定义缓动）、`CustomBounce` / `CustomWiggle`（弹跳/摆动）、`Physics2DPlugin`（重力飞散，**不要写 friction**，会破坏逐帧复现）、`ScrambleTextPlugin`（乱码收敛）、`TextPlugin`（打字机）、`Flip`（自动量布局位移）。CustomBounce/CustomWiggle 依赖 CustomEase，已按顺序加载；Flip 要 `pause(0)` 后用主时间线 `progress()` 推进。
- **编号之外的东西一律不许画**：不写线条、网格、色块、刻度、进度、卡片、标签框、圆圈、图案、SVG、canvas。

## 允许什么、禁止什么

**允许**：文字、照片、`visual_budget` 里的 U 组件、B 背景、为保证可读性加的纯色/渐变遮罩。

**禁止自己画**：图标、插画、示意图、流程图、数据图表、线条、分隔线、网格、刻度、色块、圆点、卡片、标签框、行/链结构；`<svg>`、`<canvas>`、Three.js、emoji 当图形。**U 组件可以出现，但只能来自能力卡编号；编号外的一律不许自己写。**

## 内容密度与版面

- 每屏至少三层信息，而且只能靠文字拉开：主张（大字）+ 支撑（1–3 行）+ 一个可引用的短句或数字（很小或很大）。不靠画图补画面。
- 内容块在安全区内**整体垂直居中**，占屏高 **45%–70%**；不要顶在顶部 200px、下面空一片。
- 标题不写死字号：给主标题加 data-fit=0.96 这种属性（0–1，占父级宽度的比例），本地 auto-fit.js 会在字体就绪后把字号算到刚好填满那一行；正文 36–44px 仍写 px，不要用 rem。
- **每屏至少要有一个 ≥ 88px 的视觉锚**（大标题或大数字）；有视觉锚的标题直接写 data-fit=0.96，由本地按栏宽算字号，不要自己猜 px。
- **任何文字不小于 34px**：标签、注释、单位也一样。30px 在竖屏手机上基本读不出来，本地检查会报“小于 34px”。
- 同一种结构最多连续 3 行（例如三行“X 像考试”）；第 4 行必须换形式：并成两列、加一句总结、或改成数字/标签。
- 标题、支撑、视觉锚之间至少 32px；图文各半时文字块与图片之间至少 48px。
- 安全区：左右 90px、顶部 200px、底部 300px（字幕区）。照片可以满屏出血，但文字必须在安全区内。
- 长标题显式断行，避免单字成行；不要贴边。

## 「场景演示」标注只在必要时出现

只有这一屏**确实展示了虚构的数值、虚构的界面或示例数据**时，才在紧挨着那组数字的地方标一次「场景演示」或「示例数据」，一行小字。

- 照片屏、观点屏、纯文字判断屏**一律不标**。
- 不要做成常驻角标、页眉、页脚或水印，不要出现在画面边缘。
- 标了但画面里没有虚构数据，等于给自己加脏点，成片每一帧都带着。

## 技术契约（硬性）

1. `section` 必须是 `<section class="scene clip" …>`，属性一个不少：`id` 与 `data-scene` 都等于本屏 `scene_id`、`data-sentence-ids`、`data-start="0"`、`data-duration`、`data-visual`。
2. 本屏样式放一个 `<style>`，选择器全部以 `[data-scene="本屏 id"]` 开头，类名带 `s<本屏 id>-` 前缀。
3. 照片屏必须有且只有一个 `data-anim="media"` 容器；`html` 屏必须留一个**空的** `data-anim="bg"` 容器当槽位，但不画图形。其余元素用 `kicker / title / body / stat / rule / note / scrim` 这套 `data-anim` 名字，同屏不重名。
4. 需要状态变化的元素加 `data-state="a|b"` 和对应 class；数字加 `data-count="初值|终值"`；列表行加 `data-row`。
5. **不写任何 GSAP 时间线**（`timeline.from/to/fromTo/set` 都不写），动效由动效节点统一写。
6. 字幕由本地注入，不要写字幕块、不要写 `.caption`。
7. 先输出 `<section>`，再输出一个 `<style>`。不要 `<script>`、不要 `<html>`、`<head>`、`<body>`、媒体占位。
8. 只输出以上内容：不要解释、不要代码围栏、不要调试注释、不要场景编号或坐标注释。

## 内容要求

- 这一屏只服务本屏 `voiceover_text` 正在讲的这一句，不跑到别的屏。
- 文字之间、文字与图片主体之间不得叠压；不要常驻页眉页脚水印。
- 一屏讲一件事。讲不完说明分镜该拆，不要靠缩小字号硬塞。
