现在规则散在四处：`AGENTS.md` 铁律、`能力卡.md` 三条硬规则、`check_html_contract.py` 机器检查、`视频需求与质量标准.md`。
这页把它们收成一张表，标出冲突，并给出 v2 草案。

> 3. 模型**只写目标名，不写绝对坐标**；
> 4. **不再强制**「1 镜头 + 1 离场」，改成「一个主运动 + 切点前收束」。

## 一、现状：四组规则

### A. 写得最硬的（能力卡.md）

| # | 规则 | 现在还成立吗 |
|---|---|---|
| A1 | 只选表里的编号，参数不超范围 | 成立 |
| A2 | 每屏按「1 镜头(C) + 1 环境(D) + 1 主运动 + 2–4 次级 + 1 组离场(X)」组织，相邻两屏不同镜头/主运动 | **半失效**：环境 D 已全删；镜头只有 3 张，长片必然重复 |
| A3 | 禁 `requestAnimationFrame` / `performance.now` / `Math.random` / `yoyo` / `repeat` | 成立 |

### B. 视频制作层（AGENTS.md，10 条）

- 每屏主视觉由**真实照片或纯文字**承担，`role` = full/inset/portrait/texture/html；整片至少一张真实照片
- **HTML 只做文字和动效**；界面元素只能取编号组件，模型不得自创图形
- 构图逐屏不同（family/text_zone/align/scale），相邻两屏不同族
- 静态图不能当动效镜头，每屏必须有元素级动画
- 动画由语音或时间线驱动；禁止整图缩放、循环呼吸、无意义漂移
- 产品 UI 用模板组件，示例数据标"场景演示"
- 信息逐项入场/数字递增/路径推进优先于装饰
- 平滑长尾缓动 + stagger + 语音 cue；禁止无限循环
- 交付前查时长/音画/响度/字幕/运动量

### C. 机器检查（check_html_contract.py，会拦渲染）

- 禁 `performance.now` / `rAF`；禁 `Math.random`
- 必须有 GSAP 字面量动作 + `window.__timelines` 注册
- 必须有 `data-start` / `data-duration` / `data-scene` / `data-sentence-ids`
- **canvas 必须固定 1080×1920**，不能按 `getBoundingClientRect` 改尺寸
- **canvas 与照片同屏 → 报错**（"具象视觉归照片，canvas 只留背景氛围"）
- 全片都是无图屏 → 报错（至少一张照片）
- 动效选择器命中率低 → 拦

### D. 质量标准层（视频需求与质量标准.md）

- canvas 背景层写在 `#background-layer` 内，用 `hf-seek` 按 `e.detail.time` 重绘
- **canvas / 三维不由 GSAP 驱动**，改由 `hf-seek` 时间函数绘制
- 禁止 canvas / WebGL 全屏背景**铺满正文**
- 禁止卡片、列表、图标、图表、进度条等具象 UI（只能取组件）

## 二、冲突清单（按严重度）

| # | 冲突 | 谁和谁 | 影响 |
|---|---|---|---|
| 1 | **三维到底谁驱动** | D「canvas/三维不由 GSAP 驱动，走 hf-seek」 vs Z01/Z02 实现（GSAP 时间线 `onUpdate` 里 render） | 现在代码和文档直接矛盾，新人会写错 |
| 2 | **canvas 能不能和照片同屏** | C「canvas+照片=报错」 vs 之前讨论过的"照片做纹理" | 决定三维屏能不能吃真实照片 |
| 3 | **HTML 只做文字和动效** | B vs G02 重排、G03 共享元素、I01/I02 交互 —— 这些本质是 UI 结构与操作演示 | 规则已经被新卡事实突破，只是没改 |
| 4 | **模型写不写代码** | B「模型不写代码」 vs 新卡要求模型写 `data-flip-to` / `data-morph-to` / `data-pointer-path` | 措辞要改成"写数据、不写实现" |
| 5 | **每屏必须 1 环境 D / 1 组离场 X** | A2 vs D01 删空、离场只剩 5 张、G02/G03 屏常直接切 | 无法执行，等于没规则 |
| 6 | **相邻两屏不能同镜头** | A2 vs 只有 C01–C03 三张 | 30 秒以上的片子必然违反 |
| 7 | **禁循环 vs 背景/材质是周期函数** | A3/B vs B 系列 canvas 按 t 循环、材质叠加 | 视频里是单次，预览是循环，文档没写清适用范围 |
| 8 | **canvas 全屏铺满正文** | D 禁 vs Z 系列全屏 canvas + 文字压在留白 | 需要区分"铺满正文"和"留白处放字" |
| 9 | **编号复用** | 没有明文；已删 30+ 个编号 | 会不会和旧项目/旧提示词撞 |
| 10 | **先出样片才入表** | 经验文档 vs 这次 5 张批量审完一次入表 | 流程要允许"批量审阅后一次入表" |

## 三、v2 草案（12 条，替代上面四组）

### 内容层（4 条）

1. **整片至少一张真实照片**；无照片的屏必须由排版撑住（`role=html`）。
2. **每屏一个主运动**，其余是次级；相邻两屏的主运动不能是同一张卡。
3. **字由 HTML 承载**，任何 canvas / 三维里不放文字（字重、字距、字形卡都在 DOM 上）。
4. **动效由时间线驱动**：每个动作必须能被 seek 到任意一帧复现；禁 `rAF` / `performance.now` / `Math.random` / 循环。

### 技术层（4 条）

5. **canvas 固定 1080×1920**，按 `t` 重绘；一个 `<canvas>` 只服务一块区域。
6. **三维统一用 GSAP `onUpdate` 驱动**（与 5 同源），`hf-seek` 只做兜底；场景必须引 `three.global.js`。
7. **canvas 与照片不同屏**（默认）。要做"照片进三维"必须显式声明 `data-visual="3d-photo"`，走白名单放行。
8. **机器检查以 C 组为准**，其它文档不得写出与 C 组相反的规则。

### 授权层（4 条）

9. **模型写数据，不写实现**：只给编号 + 目标（`data-anim` 名）+ 时序；坐标、路径、目标框一律由场景 HTML 给。
10. **卡不测量布局**；唯一例外是指针类卡，且必须先临时显示隐藏场景量一次再还原。
11. **每屏的收尾**：切点前 0.3–0.5 秒必须有离场或收束动作，但不强制用 X 卡（G02/G03 的自带回位也算）。
12. **编号只增不改**：删掉的编号永久留空，不复用；候选期用临时名（`G03` 之前的状态），入表才发正式编号。

### 流程（保留，但合并成一条）

13. **加卡四步**：判重 → 出样片给用户看 → 写 `presets.json` + `能力卡.md` → 同步链（提示词→展开器→check）→ `render_card.sh` 出片。
    允许批量：一次审多张、一次入表，但每张都要有样片。
