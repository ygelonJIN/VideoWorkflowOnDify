# 能力库索引

`能力库/` 只放以后还会反复使用的长期资料：定义、提示词镜像、生产标准。
不放项目状态、操作入口、运行产物或临时输出。

## 目录职责

| 目录 | 职责 |
|---|---|
| `项目文档/` | 任意主题通用的标准：`用户输入事实与合规规则.md`、`内容选题与去重规则.md`、`视频需求与质量标准.md` |
| `工作流提示词/` | Dify YAML 里提示词的可读镜像，逐字一致 |
| `工作流代码节点/` | Dify YAML 里 Code 节点的可读镜像，逐字一致 |
| `动效库/` | `presets.json`（编号与展开代码，唯一源）、`能力卡.md`（人看的参数表）、`已有能力一览.md`（去重速查）、`候选评估.md`（外部来源评估）、`样片/` |
| `画面工艺/` | 画面与声音的工艺参考。**不进提示词、不约束模型方向**，只供人工查阅调优 |

## 镜像文件对应哪个节点

**不要在这里手抄映射表。** 提示词和代码镜像的 node → 文件对应关系，唯一源是
`成品/workflow_runtime/tools/sync_prompts_to_yaml.py` 的 `MAPPING` / `CODE_MAPPING`；
桌面端也直接读它。要知道某份镜像归哪个节点，查那个文件，或看 `ls 工作流提示词/`。

已知的两条边界：

- 黑帧版（04）是当前生产链路；数字人版（01）未迁移，文件名带 `_有数字人`。
- 旧文件不在 04 链路里：`场景组A–D提示词.md` 只对应 `Dify工作流/归档/04_黑帧口播_分组生成_分组版备份.yml`；
  `黑帧口播视频编排提示词.md`（单节点版）、`HTML批量草稿提示词.md` 只作历史参考。

## 输入提炼层（所有 Workflow 共用）

`A01 → A02 → A03` 产出 `brief.distill`，把任意形态的输入（聊天记录、会议纪要、文章、语音转写、清单、碎片想法）
先压成"一个主张 + 支撑它的论点 + 证据"，条数不设配额：

| 字段 | 含义 |
|---|---|
| `source_form` | 输入形态，用于判断是不是素材 |
| `thesis` / `thesis_source` / `thesis_type` | 一句话主张、来源、类型 |
| `arguments[]` | 条数由素材决定；每条含 `claim` / `evidence` / `support` / `strength` |
| `counterpoints` | 需要正面回应的相反说法 |
| `dropped` | 被丢弃的类别（寒暄、重复、跑题等） |
| `open_questions` | 素材没讲清、成稿不得编造的点 |

下游 `A04 论点排序 → A06 按论点写口播 → A07 拦流水账/照搬/漏论点 → A08 按论点分镜` 全部以 `distill` 为脊柱。
改这条链时，`结构化活动输入提示词.md`、`内容策略提示词.md`、`口播文案提示词.md`、
`口播自动扩写修订提示词.md`、`分镜导演提示词.md` 和对应 Code 节点镜像必须一起改。
