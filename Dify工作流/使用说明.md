# Dify HTML 视频工作流使用说明

三个 Workflow 的最后一步使用同一条命令：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/workflow_runtime/tools/run_dify_output.sh' 你的项目名
```

命令会自动打开 TextEdit。把 Dify 完整输出粘贴到 TextEdit，不要粘贴到终端。内容完整后自动继续，不需要回车、`END` 或读取剪贴板。

除了原始 JSON 输出，也支持完整的“视频内容生产资料”报告格式：只要内容同时包含 HTML 和批准包中的 `approved_script.voiceover_script`，脚本会提取口播并进入黑帧渲染，不再只生成 HTML 预览。

## TXT 保存位置

TextEdit 输入文件保存在：

```text
/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/Dify输出/项目名-年月日-时分秒-dify-output.txt
```

例如本次 `333` 的文件是：

```text
/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/Dify输出/333-20261023-165412-dify-output.txt
```

每次运行时，终端也会打印本次 `.txt` 的准确路径。

## 自动分流

| Dify 输出 | 自动处理 | 结果 |
|---|---|---|
| `html_document` | 检查 HTML、移除墙钟驱动、校准技术时间轴 | HTML 预览 |
| `html_document` + `voiceover_script` | TTS、同步字幕、渲染 | 零数字人/零黑帧占位的无数字人 MP4 |
| `html_document` + `heygen_response_json` | 下载媒体、同步字幕、渲染 | 带数字人最终 MP4 |

项目名建议使用唯一的 `请求编号`，不能包含 `/` 或 `\`。

## 仅生成 HTML

`03_仅生成HTML预览工作流.yml` 就是旧文件名 `dify-html-only-import.yml`：它是可直接导入 Dify 的“仅 HTML”Workflow，不是运行脚本，也不生成语音或 MP4。

导入：

```text

```

运行：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/workflow_runtime/tools/run_dify_output.sh' html-preview-20261023
```

输出：

```text
/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/HTML预览/html-preview-20261023.html
```

## 黑帧口播视频

导入：

```text
Dify工作流/02_黑帧口播无数字人视频工作流.yml
```

该 Workflow 不调用 HeyGen API，输出 `html_document`、`voiceover_script`、`approved_package_json`。它在 Dify 内只生成文案和 HTML，不生成音频；音频由本地统一入口生成。

执行边界：

```text
Dify（mimo-v2.6-pro）生成 HTML + voiceover_script
→ 本地 run_dify_output.sh
→ 本地 MiMo TTS（mimo-v2.5-tts）生成 媒体/口播.mp3
→ 本地按完整句子和真实转写时间码生成 字幕/
→ 本地 HyperFrames/FFmpeg 渲染 成片/最终视频.mp4
→ `normalize_final_audio.py` 标准化响度，`check_final_video.py` 校验最终媒体主时钟
```

字幕文字以 `voiceover_script` 为唯一真值，ASR/时间码只负责对齐；每个完整句子单独一条，不截断、不拼接半句。最终画面必须零占位：没有数字人、avatar 媒体层、黑帧小窗、纯黑保留区或等价空白窗口；具体构图由模型自由设计。

黑帧 Workflow 的 Dify 开始节点提供 TTS 可视化配置，不用在命令里写参数：

| 配置项 | 可选项/默认值 |
|---|---|
| TTS 供应商 | `mimo`（默认）、`macos`、`openai-compatible` |
| TTS 模型名 | `mimo-v2.5-tts`（留空也使用该值） |
| TTS Base 地址 | `默认（按量付费）`、`Token Plan - 中国`、`Token Plan - 新加坡`、`Token Plan - 欧洲` |
| TTS 声音 | `mimo_default`（默认）、`冰糖`、`茉莉`、`苏打`、`白桦`、`Mia`、`Chloe`、`Milo`、`Dean` |

默认声音是 `mimo_default`。本地 MiMo TTS 使用 `MIMO_API_KEY`，默认模型 `mimo-v2.5-tts`；Dify 选择的配置会写入 `approved_package_json.tts_config`，本地自动读取。

输出：

```text
/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/项目名/成片/最终视频.mp4
```

## Dify 配置

只有全合一 Workflow 需要 HeyGen 配置；仅 HTML 和黑帧口播 Workflow 不读取或使用 HeyGen API Key：

| 变量 | 说明 |
|---|---|
| `HEYGEN_API_KEY` | HeyGen API Key |
| `HEYGEN_API_BASE` | 默认 `https://api.heygen.com` |
| `HEYGEN_AVATAR_ID` | 数字人 ID |
| `HEYGEN_VOICE_ID` | 中文声音 ID |

Dify 的 Xiaomi MiMo 官方插件只提供 LLM，插件 manifest 明确为 `llm: true`、`tts: false`。因此：

- Dify 的 MiMo 插件使用 `mimo-v2.6-pro` 生成口播文案、HTML 和结构化数据。
- Dify 不生成音频，也不保存 `MIMO_API_KEY` 供本地 TTS 使用。
- 本地 `build_black_frame_project.py` 读取 `MIMO_API_KEY` 和 Dify 的 `tts_config`，通过小米 MiMo 平台的 OpenAI-compatible Chat Completions 音频接口调用 TTS。
- TTS 返回的 MP3 写入项目的 `媒体/口播.mp3`；本地转写只用于生成时间码，字幕文字仍以 Dify 的 `voiceover_script` 为准。
- 如果 MiMo TTS 返回 401，请检查本地 `MIMO_API_KEY` 是否为有效 Xiaomi MiMo API Key，以及 Key 类型是否匹配所选 Base 地址；不要把 Key 写入项目文件或日志。
- 如果以后要让 Dify 直接产生音频，也可以不用官方 TTS 插件，自己加 Dify HTTP Request 节点或自定义插件，在节点里配置模型名、Base 地址、声音和鉴权；但完整 MP4 的字幕、HTML 动画和 HyperFrames/FFmpeg 渲染仍需要本地完成。

## 提示词链路与质量门禁

当前提示词不是只负责“写一段文案”，而是按生产链路分工：

| 节点 | 职责 |
|---|---|
| A01 任意主题需求整理 | 把主题、原始文本或随口一句话和可选上下文整理成 Brief |
| A04 内容策略 | 只选一个有事实支撑的核心角度，排除不讲的内容 |
| A06 口播文案 | 生成完整口播和逐句字幕真值 |
| A08 分镜导演 | 建议生成 5–7 个场景，明确内容重点、visual_brief 和语义过场 |
| A10 动效导演 | 把分镜变成绑定句子的目标级动作、状态变化和过场 |
| A12 事实与合规 | 检查数字、案例、承诺、示例标记和发音风险 |
| H01 HTML 视频编排 | 读取 `approved_package_json`，自由设计 HTML、组件、排版和 GSAP 时间线 |
| H02 HTML 检查 | 检查技术时间轴、媒体占位、同步标记、简体中文和时间线驱动 |

H01 现在会读取 `approved_package_json`，不再凭空生成通用 HTML；A01 至 A12 也都会读取各自上游变量。每次运行可以通过 `request_id` 选择一个作者期变体，制造布局、组件、动效和过场差异，但运行时禁止 `Math.random`、随机时间和随机颜色。

最终本地 `check_html_contract.py` 只做技术与同步门禁：检查根画布、scene/字幕的 `data-sentence-ids`/`data-sentence-id` 句子锚点、字幕/媒体标记、统一媒体时长、GSAP 时间线和无墙钟/无运行时随机；不再规定组件数量、栅格、字号、颜色或页面布局。

## 当前仍保留的规则

内容输入已经改成主题优先：

- 可以只输入一句话、一个想法、一段经历或任意原始文本。
- 不要求品牌、产品、公司、行业、痛点、卖点或 CTA。
- 只有用户明确提供时，品牌、产品、人物、价格和行动建议才会进入事实字段。
- 随口输入不会被自动补成品牌故事、产品故事或商业转化故事。

仍保留的内容质量规则：

- 一条视频聚焦一个核心角度。
- 建议 5–7 个内容单元，最后一个单元可以是总结、`ending` 或 `summary`，只有用户明确要求时才强制 CTA。
- 标题 ≤16 字，屏幕主文案每个单元 ≤160 字。
- 每个单元有一个明确观点，优先使用用户已确认的细节、数字、步骤、对比或经历。
- 禁止编造事实、空洞口号、鸡汤、套话和时间线流水账。

仍保留的技术规则：

- 1080×1920、9:16、简体中文。
- 完整句子字幕、真实时间码、GSAP 时间线和媒体占位。
- 无墙钟驱动、无运行时随机。
- HTML 排版、组件、视觉和过场由模型自由设计。

## 自动修订与 JSON 容错

### 口播自动修订

`A06_生成口播文案` 的目标是 320–420 个字符、12–18 个完整句子；最终宽门禁为 80–500 个字符、至少 3 个完整句子。

第一次不通过时，Workflow 会携带 `copy_errors_json` 进入 `A06R_按错误自动改写口播`，再由 `A07R_复查自动改写口播` 和 `A07R_口播复查门禁` 复查。仍不通过时输出具体字数、句子数和错误内容。

### JSON 降级处理

- 分镜 JSON 无法解析时，根据口播句子生成基础分镜继续。
- 动效 JSON 无法解析时，生成至少 6 条基础语义动效继续。
- 合规 JSON 无法解析时，按 `needs_changes` 返回可诊断结果。
- 口播 JSON 无法解析时，返回可重试错误并自动改写一次。
- Brief JSON 不要求品牌、产品、受众、痛点或 CTA；缺失时使用通用主题字段继续，并在 `brief.normalization_warnings` 中记录，不把占位内容当成用户确认事实。

降级处理用于避免模型字符串引号、截断或尾逗号直接触发 `json.decoder.JSONDecodeError`，但不能绕过事实、主题和发布前人工复核。

## 技术约束与创作边界

- 画布始终为 `1080×1920`，这是输出规格，不是页面布局模板。
- 主要内容必须落在安全可读区域内；构图可以自由设计，但主内容垂直中心必须位于 740–1060px，文字、组件和字幕不得重叠。
- 内容少时可以留白，也可以扩展视觉元素，不强制放大或铺满。
- 完整版：必须保留数字人小窗；小窗、品牌和状态条的位置与尺寸由模型设计。字幕固定为 `bottom:24%`、62% 最大宽度、37px 字号、1.35 行高和小尺寸半透明底板。
- 无数字人版本（历史模式名 `black-frame`）：必须零占位。禁止数字人窗口、头像、人物媒体、黑帧小窗、纯黑保留区和等价空白窗口；删除窗口后必须回收左上/右上区域，顶部内容不得继续向右避让或保留空槽。
- 场景和字幕由 HyperFrames 时间线驱动，禁止墙钟驱动。
- `媒体/口播.mp3` 实际时长是唯一主时钟；场景先从作者期时间等比映射到真实时长，GSAP 相对偏移使用同一比例，transcript/ASR 字幕使用绝对秒。已经校准的真实时间禁止再次乘以 `timelineScale`。
- BGM 自动补齐到真实成片时长，最终 MP4 的视频、音轨和口播时长差必须小于 100ms。

## 常见问题

- `402 / Payment Required`：检查 HeyGen Credits、套餐和 API 权限。
- TextEdit 没有保存：在 TextEdit 按 `Cmd-S`。
- 想重新处理：换一个新的项目名。
- 同名全合一项目需要重渲染时：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/workflow_runtime/tools/run_dify_output.sh' 项目名 /path/to/dify-output.json --replace
```
