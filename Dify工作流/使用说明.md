# Dify 视频工作流使用说明

## 有哪几份 Workflow

| Workflow | 作用 | 输出 |
|---|---|---|
| `04_黑帧口播_分组生成.yml` | **当前默认**：图像计划 + 逐屏生成 HTML、本地 TTS 口播、MP4，不调 HeyGen；图片由本地 `generate_images.py` 调 API 生成 | `html_document` + `voiceover_script` + `image_plan_json` |
| `01_有数字人完整视频工作流.yml` | **04 + 右上角数字人小窗**：同一条 04 全链路（图像计划 / 编号分配 / 逐屏生成 / 真实口播），另接 HeyGen 出数字人，整片右上角常驻 270×480 小窗 | `build_package_json`（内含 `html_document` / `voiceover_script` / `image_plan_json` / `heygen_response_json`） |
| `归档/` | 02、03 已停用，只作历史备份（02 的能力由 04 接管）；01 的 04 派生前版本也在这里 | — |

两份都走同一条本地命令，按输出内容自动选 HTML 预览或最终 MP4：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh' 项目名
```

运行产物落在 `成品/项目名/`，模板与工具在 `runtime/`（只读，不往里写运行结果）。

## 黑帧口播（04，默认）

命令里**不用写项目名**，自动用时间命名，比如 `20261109-1130`。

## 一条命令出片（配了生图 Key）

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh'
```

打开 TextEdit，粘 Dify 完整输出，保存关闭。后面全自动：落图像计划 → 调生图 API 出图 → 配音 → 字幕 → `成片/最终视频.mp4`。
生图失败或某张被拒不会中断：缺图的屏照样出片，日志会点名缺哪几张，补完重跑即可。

## 没配生图 Key 时手动出图

## 1 准备

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh' --prepare
```

打开 TextEdit，粘 Dify 完整输出，保存关闭。生成：

```text
成品/20261109-1130/媒体/出图/全部提示词.txt
```

## 2 出图

复制 `全部提示词.txt` 里的提示词去出图，图全部丢进：

```text
成品/20261109-1130/媒体/图片/
```

文件名不用改，也不会被改。出片时按修改时间从早到晚对号，**最早那张算第一个有图屏**；`role=html` 的屏不占图片位，会被跳过。

图像计划里 `role=html` 的屏不需要出图，它们由 HTML 背景承担画面；出图清单里不会出现这些屏。

## 3 出片

手动放完图（没配生图 Key）时：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh' --skip-images
```

配了生图 Key 就**不要加 `--skip-images`**，同一条命令会自动出图再渲染。成片：

```text
成品/20261109-1130/成片/最终视频.mp4
```

## 要配的 Key

口播需要 MiMo：

```bash
export MIMO_API_KEY=你的key
```

已有音频就不用：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh' --skip-images --voice-file /path/to/口播.mp3
```

## 自动出图（配 Key 就生效）

配好后同一条命令直接出图 + 出片，不用 `--skip-images`、不用手动去即梦。

默认是**阿里云百炼**（qwen-image），只填 Key 就行：

```bash
export IMAGE_API_KEY=你的百炼Key        # 或 DASHSCOPE_API_KEY
export IMAGE_MODEL=qwen-image-3.0       # 可改，如 qwen-image-3.0-pro / qwen-image-2.1-turbo
```

- Base 不填时走百炼原生同步入口（`https://dashscope.aliyuncs.com`）。
- 想走 OpenAI 兼容入口就填业务空间专属域名：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`（老域名的 compatible-mode 没有 `/images/generations`，会 404）。
- Key 的读取顺序：环境变量 → `桌面端/.env` → `~/.zshrc` 等；桌面端「设置」里配的生图 Key 存在 `.env`，命令行也认。

换成别的服务商只改三行：`IMAGE_API_BASE` / `IMAGE_MODEL` / `IMAGE_API_KEY`。

火山方舟（即梦同源）：

```bash
export IMAGE_API_KEY=你的方舟Key
export IMAGE_API_BASE=https://ark.cn-beijing.volces.com/api/v3
```

OpenAI 官方：

```bash
export IMAGE_API_KEY=你的Key
export IMAGE_API_BASE=https://api.openai.com/v1
export IMAGE_MODEL=gpt-image-1
```


## 页面节奏（2026-11-09 起）

- 分镜不再按“一页几句”配额；模型自己决定页数和切点，但每屏的 `voiceover_text` 必须逐字等于这一页实际说到的那段口播原文。
- `R3` 合并时从分镜自动注入 `data-voiceover`，模型不用手写；本地 `sync_video.py` 按这段原文在真实词级时间码里定位页面起点，页长 = 下一屏起点 − 本屏起点。
- 页间转场写绝对秒：builder 第一行 `timeline.__absolutePositions = true`，用 `__sceneStart` / `__cueAbs`；不要把 `__cue()` 的相对秒直接当位置。
- 渲染前新增两道检查：`check_html_timing.mjs`（空页/图片闪回/动作越界，失败会拦）和 `check_motion_variation.mjs`（相邻页动效同签名，只报告）。

## 数字人版（01）

01 就是 04 加一路数字人：链路、能力编号、图像计划、逐屏生成、真实口播全部照 04，只是在 `R3 → R4` 之间插了一个 `H01Z` 写入右上角小窗，出口换成 HeyGen。

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/runtime/tools/run_dify_output.sh' 项目名
```

需要 `HEYGEN_API_KEY`、`HEYGEN_AVATAR_ID`、`HEYGEN_VOICE_ID`，生图还要 `IMAGE_API_KEY`（或 `DASHSCOPE_API_KEY` / 火山 `ARK_API_KEY`）。输出里必须有 `image_plan_json`，本地 `dify_auto_build.py` 会把它传给 `render_new_project.sh`，先补图再渲染。

01 与 04 的差异（小窗注入、出口换 HeyGen、`R2` 落版、`S1N` 归一）只有一处维护：
**`经验文档/能力层架构.md` §七** 的对照表 + 同步清单。改 04 之后照那张表同步，本文件不复述。

一句话记住边界：小窗几何（尺寸/位置）的唯一真值是 `H01Z` 的 `--pip-*`，文字避让由 `sync_video.py` 按 `--pip-*` 算；
规格写在 `能力库/项目文档/视频需求与质量标准.md` §4。

## 出问题

| 症状 | 处理 |
|---|---|
| 「没有 image_plan_json」 | 忘了加 `--prepare`，或 Dify 里还是旧版 YAML |
| 「这些图片没有生成」 | 有图屏的图没放全。配了生图 Key 会自动出，出错时日志点名缺哪张；手动出图时跑 `python3 脚本/ingest_images.py` 看缺哪张；`role=html` 的屏不需要图 |
| 「缺少 MIMO_API_KEY」 | 配 Key，或加 `--voice-file` |
| 图片没就位 / 生图报 401、404 | 401 = Key 无效或地域不对；404 = 模型没在控制台开通，或把 OpenAI 兼容入口填到了老域名（老域名只有原生入口，Base 留空即可） |
| 渲染失败 | 项目会移到 `失败项目/`，打开里面的 `失败原因.txt` |
| 某个节点报错，不想从头跑 | 桌面端顶栏「重载」重读 YAML，再在右侧详情点「从此节点重跑」：前面成功的 LLM/代码节点直接复用，不重新请求。容器；操作细节见 `桌面端/README.md` |
| 本地 ASR 不可用 / 没有时间码 | sync 会重试两次；仍失败时按口播文案估算并写 `字幕/估算说明.txt`，可先出片，修好 ASR 后重跑会精确对齐 |
| 想重跑同名项目 | 加 `--replace` |

## Dify 里

导入 `04_黑帧口播_分组生成.yml`（数字人版导入 `01_有数字人完整视频工作流.yml`，两份的两段式结构相同）。要装 `langgenius/opencode_go:0.5.2` 插件，LLM 节点默认 `gpt-6-luna`。2026-11-20 起改成两段式（`S1` 编剧 → `S2` 全片规格 → `R1/R2/R3` 代码车间），已经没有迭代节点：导入后确认画布上是 `S1 → S1N → S2 → S2N → R1 → R2 → R3 → R4`；节点名变了但能力层没变，出问题先看 `R4` 的诊断再决定重跑哪个节点。开始节点里选 TTS 供应商和声音，默认 `mimo` + `mimo_default`（数字人版不用 TTS，口播由 HeyGen 生成）。
