# 能力层架构（四层、谁生成谁、怎么加卡）

## 什么时候读

- 要加 / 删 / 改一张卡，或改 `presets.json` 的字段；
- 改了能力相关的东西但成片里"没生效"；
- 要动选择层（模型能选哪些编号）或转场类型；
- 想重造某一层之前。

只调某张卡的参数、不动结构，看 `经验文档/动效与能力卡.md` 就够。

## 一、四层，从上到下

```text
① 定义层  能力库/动效库/presets.json
          唯一源：编号 / 名字 / 族 / role / 参数 / 代码 / 来源 / note

② 选择层  04 YAML 的 H00 `CATALOG`、能力卡.md、组件卡.md、`S2` 提示词里的组件段
          全部由 能力库/动效库/gen_catalog.py 从 presets 生成

③ 展开层  04 YAML 的 `R1` 的 `TPL` / `DEFAULTS`
          由 能力库/动效库/sync_expander.py 从 presets 生成

④ 审阅层  能力库/动效库/样片/全卡审阅/<族>/<编号>-<名字>.mp4
          由 render_card.sh / make_review_reels.py 生成
```

**判断一条信息该放在哪一层**：模型要不要读它？要 → 选择层；运行时要不要执行？要 → 展开层；
只是给人看？→ 能力卡。定义层只放事实，不放说明书。

## 二、`presets.json` 的字段

必填：`id` `name` `family` `role` `layer` `status` `cap` `use` `avoid`。

| 字段 | 说明 |
|---|---|
| `id` | 编号，删过的不复用（清单在 `来源台账.md`） |
| `family` | 族，决定样片目录与能力卡分组 |
| `role` | **选择层的唯一依据**，见下表 |
| `status` | `ready` 进管线；`archived` 有实现有样片但不接生产；`needs-work` / `skip` 不进 |
| `cap` | 实现形态：`component-html`（HTML 结构）、`page-transition`（`__pt`）、其余是 GSAP 模板 |
| `params` | 卡里 `{{x}}` 的默认值；缺一个就展开失败 |
| `code` | 卡的实现：`{{sel}}` 目标、`{{at}}` 时间、`{{名字}}` 参数；组件卡写 HTML 片段；PT 卡留空 |
| `note` | 选择层的说明文字（背景/组件/PT 必填），模型靠它选 |
| `bg_family` `keywords` | 仅背景卡：视觉族（dot/line/ring/block/light/noise）与触发词 |
| `text_safe` `text_swap` | 可选。卡不能落在 `data-role` 文字节点上时写 `text_safe: false` + 同槽位替身编号。`add_card.py` 校验替身存在且同槽位，`sync_expander.py` 生成 YAML 的 `UNSAFE_TEXT`；判据见 `动效与能力卡.md` 第六节 |
| `title_max_units` | 可选。这张卡最多能落在几个字宽的标题上：字距/描边类卡会把行撑宽，超过就在动画中途折行（K25 的 `0.18em` 在 8 字/100px 标题上是 944px > 840 栏，先两行、字距收到 `-0.03em` 后跳成一行）。`add_card.py` 校验正整数，`gen_catalog` 发进 `catalog.motion_cards`，`sync_expander` 生成 YAML 的 `CARD_TITLE_MAX_UNITS`，`R1` 超限就丢卡并在 `data-motion-skipped` 点名重跑 `S2`（不换卡） |
| `provides` | 仅组件卡：`{锚点: 组件内选择器}`，声明这张组件对外暴露哪些可动元素（如 `{"tag": ".g"}`）。组件动效的兼容矩阵由它算出来 |
| `span` | 仅组件卡：`copy`（默认，进 840 文字栏）/ `full`（进 1080 通栏层 `.scene-ui`）。对话、表格这类"整幅界面"用 `full`，见下面「组件落哪一层」 |
| `needs` `target` `anchor` `bind` | 仅 `component_motion`：`needs` 写锚点（可夹带 ui/text 这类环境词）；`target` = `root` / `items` / `container`，决定动组件根、逐个动锚点元素、还是在内部找；`anchor` 是主锚点；`bind` 指定 `{{child}}` / `{{head}}` 用哪个锚点 |
| `trigger` | 可选，仅 `state_*`：`true` = 这张卡在说「发生了一件事」（点击 / 勾选 / 拖动 / 切换 / 状态灯）。同屏必须再配一条 `then` 才有结果，见下面「状态卡的落点与因果」 |
| `exit` | 可选，仅 `decoration`：`true` = 这张卡结束时元素真的消失（代码里必须有 `opacity:0`），只能用在屏尾 `out` 槽，`R1` 把它固定在切点前 0.5 秒 |
| `writes`（派生，不手写） | 由 `gen_catalog` 从 `code` 判：`content`（`textContent`/`innerHTML`）/ `overlay`（`createElement`/`appendChild`）/ `style`。`content` 的只能落文字节点或锚点 |

### `role` 的全部取值

| role | 进哪里 | 谁用 |
|---|---|---|
| `bg` | `catalog.background` | `S2` 选背景 |
| `component` | `catalog.component`（含槽位元数据）+ `组件卡.md` + COMPONENT_TPL | `S2` 选编号填槽位文字，`R2` 用模板渲染 |
| `entrance_text` / `entrance_block` | `catalog.motion.*` | `S2` 选入场 |
| `state_text` / `state_block` | `catalog.motion.*` | `S2` 选状态 |
| `component_motion` | `catalog.motion.component_motion` + `catalog.motion_by_component` | `S2` 只从组件自己的可用列表里配动效；`S2N` / `R1` 再按锚点校验 |
| `decoration` | `catalog.motion.decoration`（`exit: true` 的进 `catalog.motion.exit`） | `S2` 的 `deco` 槽（元素级装饰）与 `out` 槽（屏尾收束） |
| `page_transition` | `catalog.page_transition` | `S2` 逐刀给 `pt` 偏好；切点表 = specs 的相邻两屏；`R3` 逐刀生成 `__pt`（N 屏必出 N-1 条） |

**没有 `role` 的卡等于不存在**：不报错，但模型永远选不到。加卡后"没生效"，先查这一条。

### 能力契约（组件 ↔ 动效，2026-11-21）

组件和动效之间不再靠 `use` 里的一句说明，而是两份可计算的声明：

- 组件卡 `provides`：锚点 → 组件内选择器（`{"row": ".ui-row"}`）。
- 组件动效 `needs` / `target` / `anchor` / `bind`。

`gen_catalog.py` 算出 `motion_by_component`（组件 → 可用卡）：动效 `needs` 里的每个锚点都必须在组件 `provides` 里，`items` / `container` 还要求选择器非空。S2 只能从里面选；`S2N` 丢掉不匹配的动效并点名，`R1` 再把锚点解析成真实选择器（`items` 型动锚点本身，`container` 型把选择器填进 `{{child}}` / `{{head}}`）。**卡片不再回退到组件根**：找不到锚点就跳过，不会整块动。

锚点词汇表在 `能力库/动效库/contracts.py`（card / row / cell / bar / tag / node / path / head / line / dot / icon / badge / avatar / pin / field / bubble / screen / num / flow / svg）。加组件只写 `provides`，加卡只写 `needs`，矩阵自动更新；`add_card.py` 拒收没有宿主的组件动效。

**状态卡也走同一份契约（2026-11-21）。** `gen_catalog` 把每张 ready 卡的锚点写进 `catalog.card_needs`，`S2N` 用它校验目标组件有没有这个锚点，`R1` 把 `sel` 直接绑到组件声明的选择器上：

```text
S36（needs: ["num"]）→ 目标组件 U05 → sel = [data-anim="rows"] .v
```

以前 `sel` 停在组件根、卡自己在里面找 `.num`，找不到就回落 `_t`，把容器文字整块改写（s07 的标签被写成 `156`）。现在卡只动 `sel` 指定的那个元素；锚点对不上就丢卡并点名，`R1` 不再回退到根。`add_card.py` 也会拒收"声明了锚点却没有组件提供"的状态卡。

### 组件落哪一层：`span` 与通栏层（2026-11-21）

组件原来一律渲染进 `.scene-copy`（840 宽、left 120），而且 `.scene-copy > *` 有
`align-self:flex-start`，组件会**收缩到内容宽**。结果是 U11 聊天气泡在当前片里只有 367px 宽、
两条几乎等宽地叠着——看着是"两个小方块"，不是对话。

现在的分工：

- 卡上写 `"span": "full"` → `gen_catalog` 把它带进 `COMPONENT_TPL.span` → `R2` 把这段组件
  放进 `<div class="scene-ui">`（不进 `.scene-copy`），并在 `section` 上打 `data-ui-full="1"`；
- `layout_composer.build_scene_css(ui_full=True)` 读这个记号，给 `.scene-ui` 一条 1080 宽的横带
  （有照片时落在照片的对侧带），文字带自动让开；字号档位 `--ui-scale` 和文字栏里的组件同一套；
- `.scene-ui` 的样式只有"铺满 1080、内容居中"，具体长什么样还是 `components.css` 说了算。

加"整幅界面"类组件（对话、表格、列表）时给 `span: "full"`；单块卡片（U01/U15/U55…）保持默认，
它们本来就要在文字栏里和标题并排。**别用负 margin 把组件拽出文字栏**——那是这一版之前的路子，
换一屏的栏宽就崩。

### 组件的根必须唯一（2026-11-21）

`U04 状态标签` 的模板是**两个平级 `<span class="ui-chip">`**。以前 `R2` 只给片段的第一个
顶层节点挂 `data-anim`，于是：

- `UA03` 的选择器 `[data-anim="tags"] .ui-chip` 一个都选不到 → `R1` 那句"显示这一层"
  打在空集合上，包层永远停在 `opacity:0`：2109 第一页的「金额」整片不出现；
- 第二个 chip 没有任何卡覆盖，切点一到就是最终态：2109 第一页的「感受」、第五页的
  「也能体验」都是"一开始就直接出现"。

三处一起改（缺一条都不成立）：

1. `R2` 数片段的**顶层节点**，`>1` 就包一层 `<div class="ui-comp ui-comp-row" data-anim="…">`，
   `data-anim` 挂在包层上；单根的组件仍然直接挂在根上（不额外套 div）；
2. `components.css` 给 `.ui-comp-row` 定横向排布（`flex-wrap` + `gap`），它本来就是"一排"；
3. `R1` 的"把这一层显示出来"改打在**根**（`[data-anim="<target>"]`）上，不再打在按锚点
   收窄后的元素上——打在元素上会有两个后果：逐条 stagger 的第 2 项被提前显示、再跳回去闪一下；
   带锚点的状态卡（S36 的 `num`）甚至会让包层一直停在 0。

自查：加组件时模板可以有多个顶层节点，但**动效锚点必须在同一个根下面**；
`provides` 里的选择器要能在根内被 `querySelectorAll` 到。

## 三、加 / 删 / 改

### 加一张卡：先待审，审过才转正

**任何新卡（外部搬来的、自己新写的）都不许直接落进 `全卡审阅/`。** 顺序固定（整批转正的完整命令在下面「三之三」）：

```bash
# 1. 候选先进待审区，出 3 秒片给人工看；这里还不写 presets.json
#    来源整包多、要先体检的，用 admit.py（见「三之二」）
bash 能力库/动效库/render_candidates.sh <批次> 本批.json

# 2. 人看完，写 样片/待筛/<批次>/通过.tsv 点名（编号<TAB>名字，首行表头）

# 3. 通过件才走 add_card，然后过门禁
python3 能力库/动效库/add_card.py 本批.json --batch <批次>
```

`全卡审阅/` 只收**已通过**的确认片。没审过的片留在 `待筛/<批次>/`，审完清空。

```bash
# 3. 同上：通过件才走 add_card
python3 能力库/动效库/add_card.py 新卡.json --render
```

脚本做五件事：校验（role / 参数占位 / 背景族 / 组件类名 / PT kind / 样片）→ 写 `presets.json`
→ 跑 `gen_catalog.py`（目录 + 两张表 + `S2` 组件段）→ 跑 `sync_expander.py`（`TPL`/`DEFAULTS`）
→ 确认样片。任何一步失败都会停在原地，不会留下半生效状态。

### 删一张卡

```bash
python3 能力库/动效库/remove_card.py T27
```

对称走同一条链，并删掉样片与源工程。编号永久留空，删完把编号补进 `来源台账.md` 的"删过、不再复用"。

### 只改了定义

```bash
python3 能力库/动效库/gen_catalog.py      # 重生成目录与两张表
python3 能力库/动效库/sync_expander.py    # 重生成 TPL/DEFAULTS（模板变了才需要）
```

改完把 `Dify工作流/04_黑帧口播_分组生成.yml` **重新导入 Dify**，否则线上还是旧目录。

### 三之三、批量转正：候选落待筛，审过才进全卡审阅

一次转正 3–5 张是常态，整批外部来源会到十几张。**审阅物只有一处**：`样片/待筛/<批次>/`；
`全卡审阅/` 只收人已点名通过的片。三步，别一张张等：

```bash
# 1) 出候选片：只写 样片/待筛/<批次>/（工程、片），不碰全卡审阅
bash 能力库/动效库/render_candidates.sh 20261117-magicui2 本批.json

# 2) 人看片，点名通过 → 写 样片/待筛/<批次>/通过.tsv
#    格式：编号<TAB>名字，第一行表头（通过.tsv 一出现就代表"人看过了"）

# 3) 转正：写表 + 把通过.tsv 点名的片从待筛搬进 全卡审阅
python3 能力库/动效库/add_card.py 本批.json --batch 20261117-magicui2
```

**闸门在代码里，不在文档里**：

- `render_candidates.sh` 只会写 `样片/待筛/<批次>/`，没有别的输出路径；
- `add_card.py` 在**写表之前**检查每张卡是否有 `通过.tsv` 点名的候选片，没有就拒收并原样退出，
  表、目录、`TPL` 一个字都不改；
- 写表之后若 `gen_catalog` / `sync_expander` 失败，自动把 `presets.json` 回滚再重生成，
  不留半生效状态。

其它约定：

- 一批里 canvas 卡别超过 2 张（要同时改 `bg-kit.js`，返工得连带重渲）。
- 一个人手工写卡时一批 3–5 张：整批卡在同一个 `add_card` 里，任一张参数要调就得重跑这批。
- 已在表里的卡重渲仍走 `render_cards.sh <编号>`，输出到 `全卡审阅/`（那是复查，不是候选）。

## 三之二、进件流水线（admit.py）：多来源 → 待筛 → 转正

外部搬来的东西一律走这条链，不许直接写 `presets.json`。

```bash
cd 能力库/动效库/样片/待筛
python3 ../../admit.py scan   --src <来源目录> --batch 20261117-xxx     # 只体检，几秒
python3 ../../admit.py build  --src <来源目录> --batch 20261117-xxx --limit 12
python3 ../../admit.py render --batch 20261117-xxx --workers 4         # 并行渲染
python3 ../../admit.py keep   <slug...> --batch 20261117-xxx --family 入场
python3 ../../admit.py drop   --batch 20261117-xxx                     # 没留的连片带工程删
```

**分工边界**：`keep` 只做两件事——把结论写进 `待筛/<批次>/通过.tsv`、按族分配编号（自动跳过来源台账 §二 的删号）。
**卡代码必须人写**：`keep` 之后照机制重写成 `presets.json` 的卡，再 `add_card.py --json --render`。不存在"自动搬成卡"。

| 子命令 | 写哪里 | 绝不写 |
|---|---|---|
| `scan` | `待筛/<批次>/体检.tsv` | 任何卡文件 |
| `build` | `待筛/<批次>/源/<slug>/`（含 `hyperframes.json`） | `全卡审阅/` |
| `render` | `待筛/<批次>/<slug>.mp4` + `诊断/<slug>.log` | `全卡审阅/` |
| `keep` | `待筛/<批次>/通过.tsv` | `presets.json` |
| `drop` | 删 `源/<slug>/` 与 `<slug>.mp4` | 用户的原始来源包 |

### 源码库（不是页面、也不是片段）

像 mermaid 这种"一整套图形库"，没有可直接渲染的 HTML，搬的是它的几何：**别抄公式，跑它自己的代码**。
`oneshot/mermaid/` 是一份可复用的样子：

```bash
cd 能力库/动效库/oneshot/mermaid
node --experimental-strip-types --import ./bootstrap.mjs extract.mjs <源码 shapes 目录> ./shapes.json
python3 make_batch.py          # shapes.json → 本批.json（卡定义，含 sample.stage/js）
bash ../../render_candidates.sh <批次> 本批.json
python3 qa_batch.py <批次>     # 逐片量墨量与帧间变化，找空屏/静帧
```

三条经验：

- **影子依赖**（`shims/` + `loader.mjs`）：把 `d3` / `roughjs` / 配置 / 量测换成只记录不渲染的替身，
  再把 import 里写的 `.js` 指回盘上的 `.ts`，库里的几何函数就能原样跑在 Node 里。
- **描边靠类不靠属性**：这类库的样式多在 CSS 里，提取出的 SVG 必须自带一份最小 `<style>`，否则整片只剩标签。
- **取景只看几何、不看文字**：viewBox 要用"非 text 元素"的包围盒，否则标签一大，形状就被缩成小点。

### 来源形态与适配器

新增来源＝在 `能力库/动效库/adapters/` 加一个文件并登记进 `REGISTRY`，不改 `admit.py` 主流程。

| 形态 | 特征 | 处理 |
|---|---|---|
| 单页 HTML / 包目录 | `index.html` 是完整页面，或只是 `iframe` 壳 | `generic_html`：找真 composition、GSAP 与插件本地化、注入 `hf-seek` 驱动、统一 `index.html` 入口 |
| `<template>` 片段型包 | 非 index 的 html 只有 `<template>` | 要渲 `index.html` 外壳；只拷片段会零时长（见事故排查「候选片渲染」） |
| GLSL / shader | `.glsl`、`vec4 transition(uv)` | 只能进照片层或双图转场；页间转场走不了（见 §六） |
| 视频 / GIF / tsx | mp4、gif、webm、组件源码 | 不成卡：mp4/gif 只作参考，tsx 人工挑+重写 |

### 编号与命名

- 目录按 slug，编号按族，名字中文 2–5 字；
- `keep` 取"该前缀已用最大号 + 1"，跳过已用与台账 §二的删号；**删过的号永不复用**；
- `通过.tsv` 里记 `分配编号 / slug / 族 / 片 / note`，写卡时照它取号，不要自己数。

### 每一批的收尾

1. 卡写进表并 `check_catalog_sync.py` 过；
2. `来源台账.md` §五 加一行（来源、包数、通过数、未通过的编号或原因）；
3. `待筛/<批次>/` 整个删掉——**筛完即清**，结论在台账和 `presets.json` 里，不留中间产物。

### 来源标注：只认 `src`，必须带前缀（2026-11-17 定）

- 一张卡的出处只有 `src` 一个字段。**裸机制名不合法**——`camera-push`、`type-underline`、`state-check` 这种写法等于没记来源，
  那天查出 29 张就是这么标的（现已补成 `自建:xxx`）。
- `origin` 字段废弃：302 张里 294 张是 null，和 `src` 重复，别再往里写。
- 前缀清单、现存张数、核对脚本只在 `能力库/动效库/来源台账.md` §六，本文件不复述。
- **改完 `src` 要跑一遍核对脚本**：现存张数对不上，就是还有卡漏标或标错了。核对命令与前缀清单只在 `来源台账.md` §六，别把当时的张数抄进文档。
- 组件卡的 `src` 写 `components.css`，那指的是本地样式表本身；样式表的出处登记在文件头注释里，动手改样式库时顺手看一眼。

### 审阅的三条（2026-11-17 定，踩过一次）

- **审阅物是样片，不是跑分。** 人审的是 `待筛/<批次>/*.mp4`（1080×1920 / 3 秒 / 30fps）。
  对比度、动效占比、噪检这些数字只能当结论进台账，**不能当审阅物端给人看**——数字回答"够不够"，样片回答"长什么样"，两件事。
- **`scan` 判「不能提」就不要 build。** `scan` 用正则找 `gsap.timeline({paused:true})` / `__timelines`。
  自带 `t` 引擎、自己实现 `window.__seek(t)` 的包（`vibe-knowledge-video-skill` 就是）一律判「没有可 seek 的时间轴」，
  **这是形态不匹配，不是参数没调对**，改配置解决不了，只有重写引擎一条路。
- **外观片不留文件、不进 `待筛`。** 想让人看"那个包长什么样"，用它的 `window.__seek(t)` 逐帧截图合成 3 秒片，
  看完就删。它证明的是外观，不是可转正，所以不占样片位置、不写进台账的"通过"列。
  做法（外部脚本的两条前提见 `事故排查.md`「跑外部检查器」）：起无头 Chrome 打开页面，
  按 `t = i/30` 调页面自己的 `window.__seek(t)`，每帧 `Page.captureScreenshot` 存 `f%05d.jpg`，再合成：

```bash
ffmpeg -framerate 30 -i <帧目录>/f%05d.jpg -c:v libx264 -crf 20 -pix_fmt yuv420p -color_range tv <名>-3s.mp4
```

## 四、目录怎么进提示词

```text
gen_catalog.py
  → H00 选择层：CATALOG（background / component（含槽位）/ motion（只有编号）/ motion_cards（动效卡的 name/use/avoid）/ component_meta / motion_meta / motion_by_component / card_needs / state_meta / motion_needs / recent_usage / page_transition）+ COMPONENT_TPL（组件模板）。**每个族的每个可选编号都带卡级描述**（动效卡在 motion_cards，背景/组件/转场在各自条目 note/use/avoid），漏发由门禁点名
  → S2 一次看全片：每屏 bg / media / copy+beat / components（编号+槽位文字）/ state（可带 then）/ deco / out / transition
  → S2N 归一：编号必须在目录里、槽位条数对得上；组件动效过 motion_by_component；状态卡过 state_meta（落点与 then）；deco/out 过各自那一格；还按全片用量点名超额；拆出 image_plan
  → R1 按编号展开成 <script>：组件动效按锚点解析目标、状态卡按 state_meta 再验一次落点与因果，不匹配就丢弃并记录；out 单独按切点定位；R2 用 COMPONENT_TPL 渲染 <section>
```

归一只有两处：`S2N`（编号/槽位）和 `R1`（编号不在 TPL 就跳过并记录）。**不要为了"让模型多选几种"去改提示词里的清单**——清单从 catalog 来，改 presets 的 `role` 才是改选择层。

### 照片带入场的派生族 `entrance_media`（2026-11-21）

`entrance_block` 有 14 张卡，S2 只能从那里挑，于是 G09（Flip + `gridTemplateColumns` + 动 `_t.children` 的版面卡）落到了单张 `<img>` 上：整张卡退化成"屏首藏起来、2.6 秒后才淡入"，
成片里那段就是一块空占位板（`事故排查.md`「照片槽空着就是一块占位板」）。

修法不是加一条拦截，而是在选择层**派生一格**：

- `gen_catalog.py` 的 `media_entrance_ok()` 判据只看卡自己——只动根节点（不碰 `.children` / `Flip` / `gridTemplateColumns`、不按内部结构查元素）、不读元素自带属性（`getAttribute('data-…')`，照片框没有这些属性，卡会静默空转）、且 `needs` 里声明了 `photo/media/img/block` **或** presets 里写了 `media_safe: true`；
- 结果落进 `catalog.motion.entrance_media`，`S2` 提示词点名"media 只能用这一格，没有就留空（代码给默认淡入）"；
- `S2N` 拿它当 media 的唯一允许族（缺这一格时退回旧的 `entrance_block | entrance_text`，兼容旧目录），`R1` 再验一次并记 `skipped`；
- 想给照片加一种新入场：改卡的 `needs` 或给它加 `"media_safe": true`，然后跑 `gen_catalog.py`，**不要**改提示词里的清单。

### 状态卡不许把根元素重新藏起来（2026-11-21）

`state_*` 的职责是改变一个**已经可见**的元素。它一旦给根元素设了隐藏起始态，就成了第二张
入场卡：元素先出现在画面上，几秒后又缩回去/散开再飞回来。2026-11-21 s02 的实测是「三行被
打散重来、左右乱晃」——`UA18` 已经把它们推进来了，`S19 种子散布` 在第四个槽位又把三行
随机抓开（±220px、±12°、0.7–1.15 缩放、透明）再飞回去。

这不是"某张卡写坏了"，是**三处口径错位**叠出来的，所以三处一起改：

- **卡族写错**：`S19 种子散布`、`S23 节点综合变换`、`S31 折叠展开`、`X30 圆形裁切错落`
  的 `use` 里都写着"入场/进入/出现"，`role` 却是 `state_*`。已改到 `entrance_block`，
  样片跟着搬到 `样片/全卡审阅/入场/`。`S31` 额外标了 `media_safe: false`（压扁照片带不好看）。
- **规格里能出现同一个元素的两张入场**：`S2N` 原来不按 role 去重，S2 写两条 `body`
  就发两条 motion 打同一个 `data-anim="body"`（s04 的 T27+T28 就是这么来的）。现在
  `S2N` 一屏一个 role 只留第一条、同屏组件同名 `anim` 只留第一个，并点名 S2。
- **判重放错了层**：`R2` 原来靠正则从展开后的 JS 里猜"这张卡会不会藏元素"。
  猜不准（S19 的起始态是变量 `_from[i]`，认不出），还会误伤"逐条追加"这类动子元素的卡。
  现在 `R2` 不再判重——结构上已经不可能重复，同一件事只写一处。

新增卡时的门禁（`add_card.validate`）：`state_*` 卡只要对**根元素**（`{{sel}}`）写隐藏起始态
（`opacity:0` / `scaleY<0.2` / `clipPath` 全遮）就拒收；动已有子元素的必须在 `params` 里
声明 `child`；自己 `createElement` 出来的新内容（文案替换的新 span）放行。


### 状态卡的落点与因果 `state_meta`（2026-11-22）

状态卡以前只知道「有没有锚点」（`card_needs`），没有锚点的就原样落在模型给的目标上。目标是
组件根时，卡就在组件身上动手：那张「输入」状态卡一句 `_t.textContent = ''` 把三格指标整个清空、
再逐字写回同一个容器，成片里就是一行 **16px** 的「富豪财富集中」（`20261122-1412` s05）；
`S04 勾选` 往容器里 append 一个圆环，落在容器左边缘，看着像半空里冒出来的一次点击（同片 s04）。
2026-11-21 修过一次同类（`S36` 的「156」），但改的是**那一张卡**（把 `num` 写进 `card_needs`），
不是这一类——所以换一张卡又出一遍。

现在判据从卡自己的 `code` / `needs` 派生，写进 `catalog.state_meta`：

| 键 | 取值 | 由谁执行 |
|---|---|---|
| `writes` | `content` / `overlay` / `style` | `S2N` + `R1`：`content` 的目标必须是文字节点或组件声明的锚点；没锚点的 `overlay` 也不许落组件根 |
| `requires` | `text` / `item` / `block` / 空 | `S2N` + `R1`：`text` 只准落 `title/lead/body/note/…`；`item` 走 `card_needs` 的锚点解析 |
| `trigger` | `true` / 空 | `S2N` + `R1`：同屏必须有一条 `then` 落在**同一个** `data-anim` 上，否则整条（含触发卡）丢弃 |

为什么两层都判：`S2N` 管「规格里不该出现这种组合」，`R1` 管「就算有人绕过 S2N 手写规格也造不出坏 HTML」。
两层用的是同一份 `state_meta`，判据只有一处。

**"假交互"从此在规格里写不出来**：点击/勾选/拖动/切换/状态灯只是「发生了一件事」，
孤零零一次点击不是动效。`then` 不许再用触发卡（不许连成链），也不许换目标（那不算这个动作的结果）。
给不出结果就别用这张卡——丢弃并点名「重跑 S2」，不替它补。

2026-11-23：`S04 勾选` 标 `needs-work`，`needs` 从 `row` 改成 `check`；当前没有组件提供
`check`，所以它不进可选目录。补一个清单组件（`provides.check`）后再启用——不要再让勾选落在
表格表头或普通数据行上。

### 卡要看得到"用途"：`motion_cards` 与全族描述（2026-11-22）

`catalog.motion.*` 只发编号（47 张文字入场 / 21 张状态 / 79 张装饰 / …）。模型拿到的是
一串 `K43`、`S18`、`T29`，只能靠编号猜：一头是"老是那几张"，另一头是**乱用**——
`K50 打叉`（`use` = 划掉一个错误做法）被画在"原始部落分肉"上、`S18 数值映射条`
（`avoid` = 没有真实数值时会变装饰）被画在没有任何数字的屏上、`K43 括号`
（`use` = 右侧挂一句旁注）被画在根本没有旁注的屏上、`K45 荧光笔`（`use` = 一个关键词）
被压在一整句标题上。八屏里六屏挂着标注——每屏都挂，观众看到的就不是重点。

所以目录多发一格 `catalog.motion_cards`：`{编号: {name, family, use, avoid}}`，199 张可选卡
全在里面（约 13KB）。判据仍在 `presets.json` 的 `use` / `avoid`，选择层只是终于看得到。

**每张可选卡都带描述，这条由闸门守着**（2026-11-22 晚补）：`gen_catalog` 现在用一个
`card_desc()` 给**所有族**发描述——以前只有动效卡走统一函数，背景/组件/转场各自拼
name/note，加一族就会静默漏发，模型那边又退回"一串编号"。`check_catalog_sync` 双向查：
目录里每个可选编号必须有非空描述，描述表里不许有孤儿编号。加卡、加族漏发立刻红。

两个口径上的坑，记在这里免得再踩：

- **同一个字段名在不同族里含义不同——2026-11-22 已统一口径**。差别是这样的：动效卡的
  `use`/`avoid` 一直是"什么时候选 / 别选"，而背景/组件/转场的 `use`/`avoid` 原来写的是给
  **写卡人**的实现说明（"canvas 背景，由 bgkit 按 t 重绘""只填文案与数字，样式在
  components.css""只由转场脚本节点调用"），选择语义反而在 `note` 里。
  现在规定：**`use` 只写"什么时候选"，`avoid` 只写"什么时候别选"**；实现说明不进卡——
  那是模板（`R2`）和运行时（`bgkit` / `__pt`）保证的事，写在这里只会污染选择层。
  这次改写了 52 张（背景 13、组件 24、转场 15）；另外 22 张（`B37–B54` 背景、`U54–U68`
  组件）本来就是选择口径，没动。`note` 仍然写"这张卡长什么样"，和 use/avoid 一起发。
- **整族一字不差的 use/avoid 是族规则，不是卡描述**。`family_rules_of()` 会自动检测：
  整族完全相同就提到 `catalog.family_rules` 发一次、卡级条目不再重复。今天它是空的——
  这些族只是"多数相同"（组件 23/38、背景 avoid 13/21、转场 8–9/15），不够整齐，
  所以仍逐卡发。哪天某族真的统一了，它会自动出现，不用手改。

配套的三条机器门禁（`S2N` 与 `R1` 各执行一次，判据在定义层）：

| 门禁 | 判据 | 不然会怎样 |
|---|---|---|
| 标注不许落标题 | `deco.target == "title"` 直接丢 | 标题已经全屏最大，再压一道荧光笔/圈就是糊住它（`20261122-1559` s01） |
| 标注要抠着用 | 全片 `deco` ≤ ⌈屏数÷3⌉，相邻两屏不都写；`out` 同 | 八屏六屏挂标注，标注变装饰 |
| 比例条要真实数字 | `state_meta.requires_number`（`S02`/`S18`）：本屏文字里没有数字/百分比/倍数就丢 | 在"付出和获得之间"画一条 720px 进度条（同片 s03） |

语义本身（叉=否定、括号=旁注、圈=强调）机器判不了，只能靠 `use`/`avoid` 摆到模型面前 +
提示词写清"说不清在标什么就别写"。这条不要试图用关键词去拦：`20261122-1559` s02 的文案里
就有"没有明确对应"，照样不该打叉——语境不是关键词。

### 每屏的六个位置与全片用量（2026-11-22）

以前每屏只有五个位置（bg / 文字 / 组件 / 状态 / 转场），331 张卡里 80 张 `decoration` 一个都
上不去，五支片最后只用 62 张、组件 38 张只用 7 张。现在补两个位置：

- `deco`（0–1）：落**本屏已有元素**（`title`/`body`/组件/照片），用 `catalog.motion.decoration`。
  声明了 `needs: text` 的（K 族手绘标注：圈重点 / 划线 / 框注）只能落文字。`R1` 按
  「目标槽位 + 0.5」排序，保证它排在目标入场之后——deco 的第一件事是把目标显示出来，
  排在入场前会把还没出场的元素提前露一下再藏回去。
- `out`（0–1）：用 `catalog.motion.exit`（`exit: true` 且代码里真 `opacity:0` 的卡，
  目前 `X03` / `X05`）。不占内容槽位，`R1` 固定在切点前 0.5 秒；不许动标题（`S2N` 判）。

用量不去替模型换卡（§3.3 禁止），而是**把事实摆到它面前**：

- `motion_ledger.py` 扫 `成品/*/index.html`，写成 `能力库/动效库/usage_ledger.json`（每支片用过哪些编号、首页是哪张背景）；
- `gen_catalog.py` **每次生成时直接调 `motion_ledger.scan()` 现算**，不再读 `usage_ledger.json`；
  台账文件只作报告。所以没有「忘了跑台账」这一步，`gen_catalog --check` 也不查台账新旧；
- `catalog.recent_usage` = 最近三支用过的编号并集（值 = 出现过的片数）；
- `catalog.recent_openers` = 最近三支的首页背景（编号 + family）；
- `catalog.first_screen_background` = 首页候选，已排除最近 3 支的同一张、以及上一支同 family；
  `S2` 只让第一屏从这格选，模型拿不到被排除的编号；
- `S2N` 只点名不换卡（「全片超过 2 次的编号：…（重跑 S2）」），换不换仍由模型下次决定。


## 五、四层门禁

```bash
python3 能力库/动效库/check_catalog_sync.py
```

查八件事，任何一条不过退出 1：

1. 每张 ready 卡都有合法 `role`；
2. 背景卡有 `bg_family` + `keywords` + `note`；
3. 组件卡用的 `ui-*` 类在 `components.css` 里存在；
4. PT 卡的 `kind` 在 `sync_video.py` 的 `__ptList` 里；
5. `能力卡.md` / `组件卡.md` / H00 目录 / `S2` 组件段与 presets 一致（转给 `gen_catalog --check`）；
6. `TPL`/`DEFAULTS` 没落后（转给 `sync_expander --check`），以及哪些卡缺样片。
7. 能力契约：组件 `provides` 的锚点合法、选择器里的 class/标签真的在模板里；组件动效 `needs` 合法且至少有一个组件能接（没有宿主的孤儿在警告里点名）。
8. 每张 ready 背景卡都能在 `bg-kit.js` 里找到实现——`R1` 的 `CANVAS_BG` 直接从 `catalog.background` 派生，目录里有、运行时没有就等于选中一块空屏。
9. 状态卡 / 离场卡的声明自洽：`trigger` 只在 `state_*`、`exit` 只在 `decoration` 且代码里真有 `opacity:0`；会改写目标文字的卡必须声明 `needs=text` 或锚点（否则 `R1` 只能把它丢在组件根上，把组件清空）。
10. 展开契约回归（`check_expand_contract.py`）：把 S2N → R1 在本地跑一遍，断言「内容卡落组件根 / 触发卡缺 then / then 换目标 / out 落标题 / deco 落错元素」都被丢弃，「触发卡带 then / deco 落文字 / out 落组件」都保留。判据写在 `state_meta` 里，这条是它的回归线。

把它当成"改完才算改完"的最后一步。没有这道门禁，文档和目录两三周就会漂掉——以前就是这么漂的。

## 六、页间转场为什么只有 PT 一族

页间转场是 15 张编号卡 `PT01–PT15`，`kind` 全在 `runtime/scripts/sync_video.py` 的 `window.__ptList` 里（`iris / wipe-diag / curtain / blinds / zoom-cover / push-both / flip3d / flash-cut / whip / fade-through / squeeze / wipe-up / corner-reveal / slide-down / blur-in`）。数量以 `presets.json` 与 `__ptList` 为准，别抄进文档。
`PT` 卡不写 `code`，`cap=page-transition`，因此不进 `TPL`、不出单卡样片（页间转场要两屏才有意义，随片复核）。

页间转场只有 `PT01–PT15` 一条路（`role=page_transition` + `__pt`）。早先那批双图 shader 转场已经整族删除：
它们要 from/to 两张位图，和"整页推入"的现行模型接口不兼容。要复活那一套，先改转场模型（双图缓冲），
只把编号塞回提示词不会生效。原因与证据见 `来源台账.md` 第四节。

| 目录与展开 | `H00` → `S2` → `R1/R2` | 相同，另加 `H01Z` 注入小窗 |
| 小窗 | 没有 | `H01Z` 写死 270×480 @ top 120 / right 44，`--pip-*` 是版面避让的唯一依据 |
| 出口 | `R3 → R4 → VOICE02` 输出 HTML + 口播 + 生图计划 | `R3 → H01Z → R4 → H03_生成HeyGen请求 … H06_输出HTML与HeyGen结果` |
| 结论 | 默认生产线 | 要真人出镜时用；能力层改动两份一起变 |

因为两份共用能力层：**改了 `presets.json`，01 和 04 都会变**（这一点和 2026-11-16 之前的 01 不同）。

04 更新后同步 01 的清单（只这几处，别整份重抄）：

1. 骨架在 `R3` 里内联（固定模板，写 `black-frame`）；`01` 的 `H01Z` 在小窗注入时把根节点锁成 `full`。
2. `S2` 提示词里的右上角保留区段落（x 766–1036 / y 120–600）；
3. `R2` 的 `slot` 分支（数字人版横带只落下带，因为右上角小窗压着上带；04 是上/下带都行）。height 表 `FIXED_H` 与外壳生成那段两份逐字一致，别再单独改；
4. `R4` 的数字人契约检查块；
5. `S2N` 里不要恢复 `generated_image → reusable_ui_template` 的归一；
6. 出口（`H03`–`H12` 的 HeyGen 请求/轮询/打包）与 `H01Z` 本身（这两块 04 没有）；
7. **共用节点必须逐字一致**：`S1` / `S1N` / `S2` / `S2N` / `H00` / `R1` / `R2` / `R3` 在两份 YAML 里是同一套逻辑，改一份就同步另一份，改完用 `yaml.safe_load` + `compile(R1/R2/R3 的 code)` 各验一遍。

## 八、"卡加了但没生效"的四个原因（按概率）

1. `role` 没写或写错 → `add_card.py` 直接拒收（表里已经没有"不进目录"的角色了）；
2. 没跑 `gen_catalog.py` / `sync_expander.py` → 目录或模板还是旧的；
3. 跑了但没把 YAML 重新导入 Dify → 线上跑的还是旧版本；
4. 卡有 `code` 但参数缺默认值 → 展开时 `KeyError` 被静默跳过，成片表现为"完全不动"（`sync_expander --check` 会拦）。

## 九、回退

- 定义层回退：`git checkout -- 能力库/动效库/presets.json`，再跑 `gen_catalog.py`、`sync_expander.py`；
- 选择层/展开层是生成物，不要手存副本，"回退"就是回到旧的 presets 再生成；
- YAML 回退：`git checkout -- Dify工作流/04_黑帧口播_分组生成.yml`，然后重新导入 Dify。

## 十、结构由生成端保证：模型写内容，代码写 HTML

> 为什么不许"渲完再修"、不许兜底，见 `经验文档/设计原则.md`。

**模型不再直接写 `<section>`。** 一屏的 HTML 由固定模板渲染，模型只交内容与判断：

```text
S2（LLM）→ 全片规格 JSON：每屏 visual / bg / layout / media / copy / components / motion / transition
R2（code）→ 用模板渲染唯一合法的 <section> + 合并 R1 展开的动效脚本
```

模板负责：`data-scene` / `data-sentence-ids` / `data-start` / `data-duration` / `data-visual`、
`data-composition-*`、`scene-bg`、`scene-copy`、角色标签、图片占位、作用域 CSS 的校验。
模型负责：这一屏说什么、给什么角色、照片放多大、用哪个组件、要不要额外 CSS。

由此得到的保证（不是"检查出来再补"）：

- 标签永远闭合、属性永远齐全——模型交回来的 `copy` 是纯文本，直接转义；
- 组件片段先过标签平衡检查，不平衡就丢弃并记 warning，不会把整份文档带坏；
- `css` 只接受以 `[data-scene="本屏id"]` 开头的选择器，整段不合规就整段丢弃；
- 规格 JSON 解析失败时，用 `scene_json` 的文案渲染一屏最小但完整的场景。

各环节的加强方式（**不靠默认值顶替**）：

| 情况 | 加强手段 | 结果 |
|---|---|---|
| 口播空/非 JSON | `S1_门禁` 判不合格 → 退回 `S1R`，提示词要求严格 JSON | 由模型重写，不拼凑旧论点 |
| 合规 rejected | `S1_门禁` 退回 `S1R`，把 `s1_errors_json` 作为重写原因灌回去 | 不替模型软化措辞 |
| 分镜为空/屏数不足 | `S1` 出分镜、`S1N` 校验 `sentence_ids` 必须来自口播；`S2N` 只报错不补场景 | 让上游重做 |
| 缺屏/骨架截断 | 不合成：`R3` 报明确错误，回 `R3` 重做（骨架由 `R3` 内联） | 结构正确是生成端责任 |
| 编号不在表里 | 不换卡：`S2` 只能从目录里挑编号；`S2N` 丢弃并记 warning，`R1` 只跳过并记录 | 选错即暴露 |
| 背景不在目录 / 目录里有但画不出 | `R1` 的可绑定集合从 `catalog.background` 派生（不再写死 B23–B39）；`S2N` 对目录外编号丢弃并点名，`R2` 不再塞默认 B23 | 选了就一定画出来，选错就空着暴露 |
| 组件槽位没填满 | `S2N` 的 `fit_component_texts`：组数由给到的**完整组**决定，缺槽/不满组/空组整组丢；不补空串 | 不会渲染出空卡片 |
| 状态卡目标没有锚点 | `card_needs` + 组件 `provides` 校验；缺锚点丢卡并点名，`R1` 把 `sel` 绑到锚点元素 | 不会把整块文字改写成数字 |
| 转场漏刀 | 每刀必给 `pt` 偏好；切点表 = specs 相邻两屏；`R3` 逐刀生成 `__pt`，缺的按本片转场族补齐并点名 `S2` | 不猜、不补 |
| 规格解析失败 | 结构模板仍保证闭合；字段缺失不编造文案，交给 `S2` 重出 | 只认模型给的内容 |

判断一段逻辑该写成"检查"还是"保证"：**它能不能在生成时就把结果做对？** 能 → 改生成；不能 → 写诊断，别写成失败。
