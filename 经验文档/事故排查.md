## 渲染前的结构保证与诊断（2026-11-16 起不再硬拦）

结构问题现在**在生成端就写不出来**：`S2` 只输出全片规格 JSON，`R2` 用固定模板渲染成唯一合法的 `<section>`。
所以本地看到的 HTML 永远是闭合、属性齐全的；检查器只负责把观感问题写进 `诊断/检查结果.txt`，不阻断渲染。
要恢复旧行为（不达标就停）跑 `STRICT_RENDER=1 bash render.sh`。

| 问题 | 症状 | 现在怎么处理 |
|---|---|---|
| `scene` 缺 `data-scene` / `data-sentence-ids` | 动效与场景判定错位、字幕无法对时 | 生成端不会缺：`R2` 模板必填这些属性 |
| `canvas` 没写死 1080×1920、用 `getBoundingClientRect()` 改尺寸 | 画面糊、元素错位 | 诊断记录；契约检查器报出来，人工改模板（机器不改画布尺寸） |
| 内容出画布 / 过半场景开场空白 | 文字跑到画布外 | `layout_composer` 按枚举重算文字位置；诊断留记录 |
| 残留 `{{IMG:...}}` 占位 | 缺图 | 构建器替换成占位图或真实图；诊断列出缺哪张 |
| 某屏没图也没 `data-visual="html"` | 只剩文字和底色 | 规格里 `visual=html` 才会这么写；`R2` 必给 `scene-bg` |
| 引用的图片文件不存在 | 画面缺图 | 构建器按 `--allow-missing-images` 继续，诊断记录 |
| 相邻/首尾构图骨架相同 | 每页看起来一样 | 构图检查只报告；`STRICT_COMPOSITION=1` 才拦 |
| 文档被截断（缺 `</body></html>`、`style`/`script` 不配对） | 整片无法渲染 | 生成端不会产生这种文档：`R2` 用固定模板渲染，骨架由 `R3` 内联的固定模板保证完整 |
| 缺媒体占位（voice/BGM） | 同步口播时找不到元素 | `sync_video` 补 template 并升格成 `<audio>` |
| 全屏 builder 里没有这一屏 | 这一屏静止 | `R2` 生成时保证每个内容层至少一条入场：漏给的补一条最保守的淡入，并在 `data-motion-skipped` 里点名 `S2` |
| 内容入场前先出现一块深色板/空框 | 像占位图、加载骨架 | 生成端已治：层在屏首一律不可见，照片压暗改成随图一起动的子元素（见「照片槽空着就是一块占位板」） |

排查顺序：先看项目的 `诊断/检查结果.txt`（观感/时间线告警），再回 Dify 看那一屏的规格 JSON；
要复现具体问题就跑对应检查器，但它们只报告，不再替你决定停不停。

## 导入 Dify 报 YAML 解析失败（Missing closing "quote）

什么时候读：桌面端或网页导入 `.yml` 时弹 `DslError: YAML 解析失败：Missing closing "quote at line N, column M`，
而本地 `yaml.safe_load` 明明读得出来。

**PyYAML 通过不等于能导入。** 导入侧走的是 YAML 1.2 的 `yaml` 包（桌面端装的那份：`桌面端/node_modules/yaml`），
它对双引号标量的**折行续行缩进**比 PyYAML 严得多。

2026-11-20 踩的就是这个：改节点 `code` 之后用 PyYAML 回写，`width=100000` 折出的续行只缩进 2 空格，
而 `code:` 这个键在 8 空格下——续行不比键深，解析器认定标量到那里就结束了，于是报"引号没闭合"。
同一份文件 PyYAML 读得出 19 个节点，导入必失败。

两条修法，选一条别混：

1. **不折行**：`yaml.dump(value, allow_unicode=True, width=10 ** 9)` —— 长标量落成一行，没有续行就没有缩进问题；
2. **折行但续行比键深**：PyYAML 的 `indent` 参数管不到这个，只能 dump 完自己给续行补空格
   （键在 8 空格 → 续行补到 10，和 Dify 导出时的原形状一致）。

门禁：`node runtime/tools/check_dsl_parse.mjs`。它用导入那份解析器把
`Dify工作流/*.yml` 过一遍，解析不过就退出 1。这是**格式/环境**检查（导入一定会失败），
不是内容检查——内容那套仍然只写诊断。

## Dify 跑完没有任何输出

什么时候读：工作流显示跑完，但结果区是空的、没有内容可复制。

2026-11-07 之前的原因是**代码节点直接抛异常**：Dify 遇到异常会中止整条流程，结束节点根本没执行，所以既没有输出，也不知道停在哪。

现在的行为：

- `S1N` 打包失败（口播为空、合规判 `rejected`）→ 返回 `s1_errors_json`，由 `S1_门禁` 走 false 分支到 `E1_失败说明`。
- `S1RN` 复查不通过 → 返回 `s1rn_errors_json`，由 `S1R_门禁` 走 false 分支到 `E1_失败说明`。
- `S2N` 规格对不上分镜（漏屏、漏 `title`、编号不在目录）→ 返回 `s2_errors_json`，由 `S2_门禁` 走 false 分支。
- `R3` 合并出的 HTML 不完整 → 返回空 `html_document` 加告警，不中止。
- `E1_失败说明` 把这三个 `*_errors_json` 拼成一段可复制的说明，`E2_输出未完成` 收尾。

判断停在哪一步：

1. 先看结束节点输出里的「按下面列出的那一步去修」。
2. 仍为空，就在 Dify 运行记录里看哪个节点标红——那是唯一还没兜住的情况（模型节点报错）。
3. 本地入口会提示 `Dify 输出缺少完整 html_document`，说明上游确实没产出 HTML。

## Dify 输出超限：整组画面消失

什么时候读：契约检查报"有 N 句口播没有对应场景"、`<style>` 开闭不配对，或成片里某几屏完全没出现。

### 先认症状

| 症状 | 含义 |
|---|---|
| 合并后 `<section class="scene">` 数量少于分镜场景数 | 有几组只写了 CSS，没写到结构就被切了 |
| `<style>` 开/闭数量不等（如 5 开 2 闭） | 断在样式中间，后面所有标记被当成样式文本吞掉，页面看起来"全没了" |
| CSS 占 HTML 一半以上 | 正常应明显低于一半；过半说明结构没写出来 |
| `motion JSON` 报 `Unterminated string starting at char X`，X 接近总长 | 真截断（不是中文引号 bug，那个报 `Expecting ',' delimiter` 且位置在中间） |

### 原因

`S2` 一次要输出全片每一屏的规格 JSON，屏数一多（十几屏）就可能被截断。2026-11-06 调大上限之前，模型默认最大输出根本装不下：旧的分组架构下断在 CSS 里，样式没有闭合标签，后面的 `<section>` 全变成样式文本，本地只能看到残留的 1–2 个场景。

### 处理

1. **调大最大输出**。2026-11-06 已把每个 LLM 节点的最大输出设成 **128000**，并写进 YAML 的 `completion_params.max_tokens`，导入时一起生效，不用再手工重设；换模型时先确认新模型接受这个字段。
2. 屏数由分镜决定：屏太密先让 `S1` 把屏数收下来，不要靠拉长文案去撑。
3. 每屏 `copy` 控制在 2–5 条、单条别超 9 字——规格体积主要来自这里。
4. 判断修没修好只看一条：**合并后 section 数 = 分镜场景数**。CSS 好不好看是后话。

调大上限只是把断点往后推，不改变"每组越写越长"的趋势；真的再撞上，按 2、3 收窄输出。

## 场景没被识别导致重复/不消失

什么时候读：片头内容叠在一起、页面之间不消失、整片像好几屏糊在同一时间。

- 原因：模型把场景写成 `class="clip gA gA-scene"`，`scene` 只是后缀。旧逻辑要求 `scene` 独立成词，这些 section 没被当成场景，`data-start` 一直是 0，于是所有这类场景从 0 秒起同时显示。
- 2026-11-07 已修：`sync_video.is_scene_tag()` 改为语义判定——class 有独立 `scene`，**或**是带 `data-sentence-ids` 的 `<section>`，都算场景。
- 症状消失的标志：同步日志 `scene_tags` 等于页面里 section 的实际数量，且相邻场景的 `start` 首尾相接。

## 整屏空白：内容被排到画布外

什么时候读：某一屏只剩背景和字幕，但 HTML 里明明有内容。

- 原因：模型用绝对定位把整块内容放到画布外面（实测 `top 2150`，画布只有 1920），元素存在但看不见。
- 2026-11-07 已加自动回正：只在**整屏内容完全在画布外**（`bottom <= 0` 或 `top >= 1920`）时整体 `translateY` 拉回。不要按安全区（`top < 200`、`bottom > 1620`）平移：满版背景和光晕让包围盒必然从 0 开始，会把每一屏都往下推 200px，表现为整段下移、顶部留空（当天实测 12 屏全部 `translateY(200px)`）。
- 注意：必须在场景可见时测量。启动时一次性测量会失败，因为其他场景还是 `display:none`，量出来是 0。
- 运行时脚本改成"先移除旧块再注入"，否则老项目永远用旧版本（踩过：改了脚本但项目里还是旧的）。

## 渲染失败后怎么定位和续跑

什么时候读：本地命令报错、契约检查 FAIL、成片没生成。

### 三步定位

1. **确认跑的是新输出**：看 `成品/Dify输出/项目名-年月日-时分秒-dify-output.txt` 的时间戳。拿旧 JSON 重跑只会得到同一个坏结果，白跑一轮。
2. **看契约检查的 reason**：`缺哪些句口播没有场景` 说明丢组；`<style> 开闭不配对` 说明断在 CSS；`没有任何 GSAP 动作` 说明组脚本没写出来。
3. **到原始 TXT 里找断点**：搜 `<style` 和最后一个 `<section`，能看出断在第几组。

### 续跑

失败时项目会被整体移到 `成品/失败项目/项目名-时间戳/`，`媒体/口播.mp3`、`媒体/背景音乐.mp3`、`字幕/` 都还在。**移回 `成品/项目名/` 后直接在项目目录跑 `bash render.sh`**，不用重新 TTS、不用重跑 Dify。

只有一条别做：不要为了出片去改 `check_html_contract.py` 放行残缺产物——那正是它该拦的东西。

## 动效不动、黑屏、音画不同步怎么查

什么时候读：成片出现前段全黑（只有字幕和声音）、后半段没有动效、页面切换和语音对不上。

### 先看渲染日志里的四个数

`sync_video.py` 每次同步会打印：

```text
scene_tags=8 caption_cues=8 scene_span=46.080 timeline_scale=0.9804
```

- `scene_tags`：识别到的真实页面数（已排除 `gA-scene` 这类包裹层）
- `caption_cues`：字幕句数，应与 `scene_tags` 相等
- `scene_span`：作者期时间轴跨度，应接近口播时长
- `timeline_scale`：作者期到真实时长的缩放，通常在 0.8–1.25；出现 5 倍这种数字说明跨度算错了

### 五种已知症状

| 症状 | 原因 | 修法 |
|---|---|---|
| 日志出现"分镜/动效 JSON 被截断"，动作全被归一到 `s01` | Code 节点先把中文引号 “” 替换成 ASCII 引号再 `json.loads`；文案里一带引号，合法 JSON 就被自己的替换弄坏 | 2026-11-05 已修：先按原文解析，失败才退到替换版；`01`/`04` 的 YAML 和镜像都改了，需要在 Dify 里重新导入 |
| 前段黑屏、页面跳得比语音慢 | scene 判定把 `class="gA-scene"` 包裹层当成页面，页面数虚高，时间被平均分掉 | 用 class token 精确匹配（`"scene"` 必须独立成词） |
| 时间轴被压缩或拉长 | 模型把每个 scene 的 `data-start` 都写成 0，跨度取 `max(start+duration)` 只有 9 秒 | 所有 start 相同时按 duration 求和 |
| 后段完全没动效 | 模型的 `at()` 是场景内相对时间，但 GSAP 只有一条全局时间线 | `scene-offset-runtime` 在 builder 执行时加上所属场景的 `data-start` |
| 动作数正常但整片几乎不动、后段全静 | 动效 builder 直接传 DOM 元素（`el('s04', '.gB-kicker')` 这类查找助手），`scene-offset-runtime` 只认字符串选择器，场景起点没加上，动作全堆在 0–5 秒 | 2026-11-07 已修：`targetElement()` 同时接受选择器、元素和元素数组 |
| 动效写了但从不执行 | 选择器命中 0 个元素，常见是 `.gB [data-scene="s03"] …`——`data-scene` 就在 section 自己身上，加了前缀变成"找后代" | 运行时兜底改写成 `[data-scene="s03"] …` 再重试 |
| 整片完全静止，一条动效都没有（本地重跑旧输出也会复现） | 动效脚本用 `#s01` 当场景锚点。本地渲染会把 section id 改写成 `scene-s01`，`#s01` 命中 0 个元素，全部动作失效（2026-11-06 实际踩到：85 个选择器全落空） | `R3` 合并时已兜底改写成 `[data-scene="s01"]`；`check_html_contract.py` 新增门禁，选择器全部命中 0 个元素时直接 FAIL；本地 `build_black_frame_project.py` 的 `repair_scene_anchors()` 在写 `index.html` 前也会做同样的改写，所以旧 Dify 输出重跑同样能修好 |
| 某几屏**完全没有动效**，内容从切点就是最终态；`诊断/检查结果.txt` 报「`<script>` 开闭不配对」 | `R2` 的 `_fix_block` 正则以 `\Z` 收尾，最后一个 preset 块被丢弃时会把结尾的 `</script>` 一起吃掉；脚本于是「有开无闭」，包壳时又补一层 → 双开单闭 → 浏览器在第一个 `</script>` 收尾，脚本内容以 `<script>` 开头 → `Uncaught SyntaxError: Unexpected token '<'`，这一屏的 builder 根本不注册（2026-11-19 s01/s06 实测） | 2026-11-19 已修：`R2` 先剥掉上游自带的 `<script>` 壳再处理正文，最后只包一次，出片里永远恰好一对标签 |
| 动效"啪一下出现"，没有位移也没有过渡，像是根本没做 | 卡里写 `if (!window.CustomBounce) return;` 这类守卫，而插件没被注入 → 整张卡静默空转，只剩前面那句 `timeline.set(..., {opacity:1})`（2026-11-19 T13/T17/T18/T19 四张卡全中） | 2026-11-19 已修：四张卡改用内置 `back.out` / `elastic.out`；`add_card.py` 拒收「依赖 `GSAP_PLUGINS` 之外插件」的卡 |
| 同一元素「先出现 → 突然缩掉或消失 → 再展开」 | 一个 `data-anim` 上排了两张进入型卡，第二张把初始态（`opacity:0` / `scaleY 0.06`）重新写了一遍（2026-11-19 s05 的 `process`：29.66s 滑入，33.93s 又被压回去） | 2026-11-19 已修：`R2` 按顺序只保留每个 `target` 的第一张进入型卡，后面的丢弃并写进 `data-motion-skipped`；`S2` 提示词禁止把「从隐藏或远处重来」的卡压在已入场的元素上 |
| 前段一屏停 7–8 秒、后段一秒闪好几页、出现 0.12s 的空背景 | 出现了分镜里没有的 scene，或同一个 scene 写了两遍并自带编造的 `sentence_ids`，句子锚定失效，后面的屏被压到 0.12–1 秒 | `R3` 的 `sanitize_group` 按分镜去重、丢弃分镜外的 scene、把 `sentence_ids` 校正回分镜；本地 `build_black_frame_project.py` 的 `sanitize_scene_scope()` 对旧 Dify 输出也做同样修复；`check_html_contract.py` 与 `R4` 遇到重复 scene 或字幕里不存在的句子直接 FAIL |

### 逐屏动效报告

`check_motion_profile.py` 新增 `--html index.html`：除了整片静止窗口，还按屏输出平均/峰值变化率、可见帧数和"弱 / 偏静 / OK"标记。渲染后跑一次：

```bash
python3 脚本/check_motion_profile.py 成片/最终视频.mp4 --html index.html
```

只报告不拦截；"弱"的屏就是要补主运动的地方。

### 某屏看着没动、preset 条数却够

先看 section 上的 `data-motion-skipped`：有值就说明 `S2` 给的 `target` 不是这一屏的元素
（比如屏里只有 `lead`，它写了 `body`），`R2` 已经把那条卡拉到主文字上，需要重跑 `S2`。

再跑一次契约检查，看"动效目标不在本屏"那一条——它按屏校验，跨屏同名元素不算命中：

```bash
python3 脚本/check_html_contract.py index.html
```

原因、修法与卡的 `text_safe` 判据见 `经验文档/动效与能力卡.md` 第六、六点五节。

### 文字动效同质化怎么查

2026-11-09 起，动效编号（`S2` 选、`R1` 展开）不提供文字入场样式清单，每屏由模型按内容设计，只约束结果：相邻两屏不能一眼相同，全片不同做法不少于 min(4, 屏数)，且禁止把 `opacity 0.55~0.65 → 1` 或"浅灰变强调色"当入场。

回看时先看 `S2` 给这一屏挑的编号和 `beat`：如果每屏的 `reason` 都差不多，或者全是 `fromTo(... {opacity: 0.6, y: 30} ...)` 这种同一套入场，就是又退回模板了，重跑这一屏。

2026-11-09 起本地有 `check_motion_variation.mjs`：从真实 GSAP 时间线里逐屏抽“文字动作组合 / 图片动作组合”，相邻同签名、全片文字组合少于 4 种、图片运动少于 3 种会告警。`render.sh` 渲染前会跑一次（只报告，不阻塞）：

```bash
node 脚本/check_motion_variation.mjs index.html
```

它按组件 + 属性族统计，能看出“每页都是同一种擦除+位移”，但仍不能判断审美；最终还要人眼过一遍联系表。`check_motion_profile.py --html` 只能看整屏变化量，别拿它当文字动效的验收。

### 每页看起来一样怎么查

构图逐屏不同是硬要求：相邻两屏 `family` 不能相同，首尾两屏的 `family` / `text_zone` / `scale` 不能三项全同。落版时由 `R2` 写进 `data-composition-zone` / `data-composition-align` / `data-composition-scale`（取规格的 `layout`，缺省 `center-middle` / `center` / `两行块`）。骨架和 tokens 不写全局字阶和间距，字号与对齐由每屏按自己的构图定。

本地验收用 `check_composition_variation.mjs`（渲染前，默认只报告）：

```bash
node 脚本/check_composition_variation.mjs index.html
STRICT_COMPOSITION=1 bash render.sh   # 有重复就停
```

它逐屏量真实 DOM：画面承担者、对齐、文字左边界、标题顶边与字号、元素密度。相邻两屏落在容差内、首尾同构、或 80% 以上屏是同一个「对齐 + 左边界」组合，都会报出来。它只判“是不是同一套骨架”，不判好不好看；审美仍然靠联系表。

### 怎么自助确认

- `check_html_layout.mjs` 的报告里有 `motion` 段：`total`（时间线动作数）、`byScene`（每个场景的动作数与起止时间）、`missingSelectors`（命中 0 个元素的选择器）。
- 04 的 Dify 输出里带 `motion_report_json`：每组的 `actions`、`unmatched`、`coverage`、`uncovered`。`unmatched` 非空就先修选择器，不要先调提示词。
- 浏览器里验证：console 执行 `Object.values(window.__timelines)[0].getChildren(true,true,false).length`，数量为 0 说明时间线没建起来。

## 照片槽空着就是一块占位板（2026-11-21）

什么时候读：某一屏在照片/组件出现之前，画面里先有一块**硬边深色板**或**空框**，
像占位图、加载骨架；片子里"东西还没出来，但框先在那里"。

两块东西同时出了错，缺一个都不会有这个现象：

1. **槽自带的装饰先画出来了**：照片带的压暗渐隐原来是 `[data-media-slot]::after`，
   照片还没入场它就在（`--scene-base` 在 media 上取不到，落兜底 `#0b0f18`，
   360px 高的带子里 240px 是黑的）。现在改成 `.media` 的子元素 `.media-scrim`：
   动 `media` 子节点的卡会把它一起带走，装饰只能跟内容同透明度。
   `R2` 写元素，`layout_composer.build_scene_css` 写样式，两处要一起改。
2. **"首帧空屏"空转**：`R2` 里的隐藏规则只认 `at(≤1.2s)`，`__slot` 上线后卡里写的是
   `at(slot(...))`，解析不出数字 → 一个层都没藏。现在只要有卡覆盖就在 `at(0)` 藏起来，
   由卡自带的 `set opacity 1` 在槽位打开。

组件的 `border + var(--ui-surface)` 是同一个毛病（`.ui-card` / `.ui-bento-cell` /
`.ui-player` 都有），靠第 2 条兜住；纯文字层没有装饰，空着就是零像素，不受影响。

怎么确认修好了：改造后重跑 Dify 再渲，抽那一帧看——应该是"背景 + 字幕"，不是一块板；
或者查 HTML 里有没有 `set('[data-anim="media"]', {'opacity':0}, at(0))` 和 `.media-scrim`。

## 图片/文字"先排好又散开"、左右乱晃（2026-11-21）

什么时候读：某屏元素先正常入场、一两秒后又被斜着/散开重来，看起来像"手抖了一下"。

- 症状定位：那一屏的同一个 `data-anim` 上挂了两张卡，第二张是"从隐藏态带出来"的入场卡。
  2026-11-21 s02 的三行：`UA18 行逐条推进`（8.75s）+ `S19 种子散布`（10.12s，随机抓开
  ±220px、±12°、0.7–1.15 缩放再飞回）。
- 根因不在那张卡，在**卡族**：`S19`、`S23`、`S31`、`X30` 的 `use` 写着"入场"，`role` 却是
  `state_*`，于是被当成"状态变化"塞进 state 槽，和入场卡叠在同一元素上。
- 已治本（三处，缺一条都不够）：
  1. 这四张卡 `role` 改成 `entrance_block`（样片搬到 `样片/全卡审阅/入场/`）；
  2. `S2N` 一屏一个 role 只留一条拷贝、组件 `anim` 重名只留第一个；
  3. `R2` 删掉"靠正则猜 from 态"的判重（猜不到变量起始态，还会误伤追加类卡），
     `add_card.py` 拒收"给根元素设隐藏起始态"的 `state_*` 卡。
- 怎么确认：那一屏的 `motions` 里同一 `target` 只该有一条入场；`state` 槽里不该出现
  `entrance_*` 家族的编号（`S2N` 会报"不在本屏或不是状态族，已丢弃"）。

## 空页、图片闪回与动作越界怎么查

什么时候读：成片有整屏只剩字幕、图片出现后闪一下、动作跑到别的页上。

规则本身（首帧纯背景、每个内容层只入场一次、转场只动进入屏）写在
`能力库/项目文档/视频需求与质量标准.md` §7.3，这里只讲**怎么查、怎么定位**。

- `check_html_timing.mjs`（渲染前，`render.sh` 默认执行，失败会拦）：2026-11-12 起改成**逐帧（1/30）** seek，检查每屏在自己窗口内是否可见、每个 `data-anim` 内容层是否**有且只有一次入场**（首帧即最终态 = 没有入场，只告警）、是否出现 `1 → 0 → 1` 闪回、背景层是否第 1 帧就在、动作是否越界被夹到屏尾。原来的 0.2 秒抽样漏掉过 1 帧级的闪回（31.27s 实测），不要再改回抽样。
- 两个运行时违规（`window.__motionViolations`，同一份门禁会读）：动作位置越界被夹到屏尾；转场脚本在进入屏起点写透明度/缩放/遮罩（转场只许动离场屏）。
- 首屏 opening 是最常见的这条违规：转场节点会在 `s01` 上写一段"从上缘展开/从中心放大"的开场。首屏前面没有可交接的屏，**转场里不许出现任何 `s01` 的动作**；开场怎么进交给屏内 T 族入场。提示词已写明，见到就直接删掉那段 `fromTo`。
- `屏第一帧就是最终态` 里如果点名的是 `media`，是 `merge_screen_motion` 给没被动作命中的元素补的默认入场在作怪：它补的 `opacity 0 → 1 at(0.6)` 会盖在转场的滑入之上，成片表现为"照片晚一拍才出现"。2026-11-15 起 `media` 已从补入场集合里排除，`bg` / `scrim` 也不补。
- `detect_blank_frames.py`（渲染后）只判**真正的孤立单帧**（比紧邻前后两帧都暗、且两帧都亮），多帧暗段和淡入淡出不算。`repair_blank_frames.py` 直接复用它的判据，改判据只改 detect 一处。
- 典型症状与原因：
  - 整屏只有字幕：scene 的 `opacity` 被写成 0，或显隐驱动没在 seek 时更新。`__hfRenderState` 现在会调用页面的 `window.__updateScenes(time)`；页面自己的驱动要把这个函数挂出来。
  - 图片出现后消失 0.3 秒：转场淡入写的是 `cue()` 相对秒，却被运行时加了目标场景起点，落在屏尾；起止位置必须用绝对秒。
  - 图片四周露一圈：给 `.photo` 容器做了 `scale`，同时用同尺寸遮板盖住；容器放大后从遮板四周露边。缩放图片本体（`img`），不要缩放容器。
- 转场脚本必须写绝对秒：builder 第一行 `timeline.__absolutePositions = true`，用 `__sceneStart` / `__cueAbs`。不要把 `__cue()` 直接当位置，也不要用代理对象 + CSS 变量写 scene 的 `opacity`。
- 动效差异用 `check_motion_variation.mjs`（渲染前，只报告）：逐屏列出文字/图片动作组合，相邻同签名、全片种类不足会告警；它只看真实 GSAP 时间线，不替代人眼判断。

## 组件被推到屏幕底部、上方空一大片怎么查

什么时候读：某一屏文字挤在最上面、卡片/网格贴着字幕区、中间一千多像素全空；排版检查却只报"字号偏小""缺视觉锚"。

- 原因在本地排版生成，不在场景组：`layout_composer.py` 旧规则给 `.scene-copy > .ui-*` 写 `margin-top:auto`。一屏有三个以上子元素时，auto margin 会吃掉全部余量——文字钉在顶部，组件钉在底部。
- 2026-11-15 已删掉这条规则，只保留 `:only-child{margin-top:auto;margin-bottom:auto}`，多子元素靠 `justify-content:center` + `gap:26px` 成组居中。重渲染才生效，已有成片不改。
- 判断是不是这个原因：看 `index.html` 里有没有 `.scene-copy > .ui-grid{margin-top:auto}` 这类规则；有就是旧版本生成的。
- 伴随症状：排版检查的 `主内容垂直中心` 会跑到 1300px 以上（舒适区 700–1100）。

## 最后一屏没背景、卡片空一格、屏上冒出数字（2026-11-21）

什么时候读：某一屏只剩纯色底、双卡组件里有一张空面板、画面里凭空出现文案里没有的数字。

三条同源：**目录给了模型一个选择，但下游没有能力兑现它**。都在生成端修，不需要渲完再补。

- **只有一屏没背景**：`section` 上有 `data-bg="B51"`，但这一屏的 `<script>` 里没有对应的 `/* preset: B51 */` / `bgkit.bind`。原因是 `R1` 的可绑定集合写死了 `B23–B39`，而 `H00` 目录把 `B49/B50/B51/B53/B54` 也发给了模型；选了就一个 canvas 都不建。现在 `CANVAS_BG` 从 `catalog.background` 派生，目录给什么就绑什么。确认：`grep -c "bgkit.bind" index.html` 应该等于有背景的屏数；缺的那屏 `data-bg` 号不在目录里就是选错了，`S2N` 会丢并记 warning。
- **卡片空一格**：组件模板是双卡（如 `U55`：每卡 `h3`+`p`，共 4 段），规格只给了 2 段；旧 `S2N` 补空串，`R2` 照模板渲染出第二张只有边框的空卡。现在 `fit_component_texts` 按**完整组**切：缺的组整组丢，`texts` 有几组就渲染几张卡。确认：`index.html` 里不该出现 `<h3></h3>` / `<p></p>`；`s2_warnings_json` 里会写"槽位填不满，整条丢弃"，或者"只填了 1 组（默认 2 组）"。
- **屏上冒出数字（如 `156`）**：状态卡 `S36`（数字拆开，默认 `128 → 100+28`）落在了没有数字锚点的组件上。旧卡在目标里找不到 `.num` 就回落 `_t`，把容器（或第一个 chip）的 `textContent` 整个改写成计数。现在 `S36` 声明 `needs:["num"]`，`S2N` 只允许落在 `U05/U54/U58/U67` 这类提供 `num` 的组件上（不看就丢卡点名），`R1` 把 `sel` 绑到组件声明的数字元素；卡本身不再有回落分支。确认：`grep 'preset: S36' index.html` 里的选择器必须带 `.v` / `b` 这类数字选择器；落在 `[data-anim="tags"]` 上就是旧行为。

三条都能在 `诊断/检查结果.txt` 之外的 `s2_warnings_json` / `data-motion-skipped` 里看到点名，但**都不阻塞渲染**：结构对不对由生成端保证。

## 页面只剩 0.1 秒、后面的动效全错拍怎么查

什么时候读：成片第一屏一闪而过、某一屏完全不动、动效比语音晚好几秒。

- 症状与原因：`sync_video.py` 给每屏定位起点时，会用「词级时间码」拼一条全片字符轴，按字符位置取真实起点。这条轴用的是 ASR 文本，字幕用的是口播文案；两次识别不是同一次时（繁体、同音错字、重跑过 ASR），字符位置会对不上，页面起点被甩到别的句子上，个别屏被夹到 `0.12` 秒。
- 更糟的是连锁反应：`data-start` 错了，`window.__cueWindows` 跟着错，`cue('s02','关键词')` 算出来的相对秒就落到这屏的尾部，动作全部堆在片尾或被夹掉——看起来就是「这一屏根本没动」。
- 2026-11-10 已修：① 只有字幕文本和识别文本覆盖率 ≥85% 且字符数一致时才用字符轴，否则在句内插值；② 页面从某句开头讲（命中位置 0）时，起点直接取那句的真实起点，不走字符轴；③ 页面被压到 0.5 秒以下会打印 `scene_too_short=...`。
- 排查：先看 `sync_video.py` 输出里有没有 `char_axis=disabled`、`scene_too_short=`；再核对 `index.html` 里每屏 `data-start` 是否等于它 `data-sentence-ids` 那句在 `字幕/口播时间码.json` 里的 `start`。对不上就重跑 `sync_video.py`，不要手改 `data-start`。

## 没有真实时间码时（ASR 失败 / 首次模型下载）

什么时候读：同步阶段报「本地 ASR 不可用」，或者新项目第一次渲染卡在字幕/时间码。

- `sync_video.py` 会先试两次本地 ASR；两次都失败时，如果项目有 `口播文案.txt`，会按完整句子和字数比例把音频时长分配给字幕和页面，并写 `字幕/估算说明.txt`。
- 这只是应急：页面切点和动效 cue 只能近似。修好 ASR 或提供 `字幕/口播时间码.json` 后重跑 `sync_video.py`，就会按真实词级时间码精确对齐。
- ASR 偶发失败最常见的原因是第一次跑要下载 whisper 模型、网络中断或缓存锁；重跑一次通常就好。手动验证：
  ```bash
  node "$HYPERFRAMES_CLI" transcribe 媒体/口播.mp3 --model small --language zh --json --to srt --output 字幕/口播.srt
  ```
- 不要在没有时间码时直接删 `字幕/` 硬渲；先看 `字幕/估算说明.txt` 是否存在。

## 进件候选片渲染：全黑、静止、零时长

从外部包渲候选片（`admit.py render`）时，四种成因会互相伪装，按下面顺序排。

**先看两件事**：成片体积、`待筛/<批次>/诊断/<slug>.log` 里的关键词。

| 症状 | 成因 | 怎么确认 | 修法 |
|---|---|---|---|
| 多条片体积完全一样、都只有十几 KB | 页面里 GSAP 根本没加载（CDN 在离线渲染里 404） | `grep -c "cdn.jsdelivr\|unpkg\|cdnjs" 源/<slug>/index.html` 应为 0 | 适配器把 gsap 与插件换成本地副本（`assets/vendor/gsap.min.js`、`gsap-plugins/`） |
| 画面停在第 0 帧不动 | 包里的时间轴是 `gsap.timeline({paused:true})`，宿主不给时间 | 日志里没有报错，帧数正常但每帧一样 | 注入驱动：`window.addEventListener('hf-seek', e => 逐个 tl.pause(t).time(t))` |

**成片质量的无截图判断**：

## canvas 画面（B 卡背景）

什么时候读：一屏要用 canvas 绘制的光效与粒子（B23–B39 那批背景卡），或要写 canvas 时画布是空的、不动。

- 背景卡一律走 `bgkit.bind(timeline, canvas, name, params)`（`assets/vendor/bg-kit.js`）：内部用一条覆盖全场的哑 tween 读 `timeline.time()` 重绘，并同时挂 `hf-seek` 兜底。不要自己起驱动。
- 手写 canvas 时按同一协议：只依赖 `t` 计算，`window.addEventListener('hf-seek', e => renderAt(e.detail.time))` + 首帧 `renderAt(0)`。
- **绘制优先用哑 tween + `timeline.time()`，不要依赖 `onUpdate`**：2026-11-06 踩过 seek 抑制回调、画布 alpha 全 0。这条**已被运行时补掉**——`sync_video.py` 把 `tl.seek` 改成 `suppress=false`、并接管 `__seekTo`，2026-11-19 实测 `tl.seek(t)` 和 `tl.time(t)` 都会触发 `onUpdate`，所以现在 33 张 onUpdate 绘制卡是活的。仍然推荐哑 tween 的写法：它是唯一不依赖这层补丁的写法，换渲染器或补丁失效时不会整层空白。
- 不要用 `requestAnimationFrame` / `setInterval` 当驱动；随机数用 `kit.seeded(seed)`，不用 `Math.random`。
- canvas 固定 `width=1080 height=1920`，不得按 `getBoundingClientRect` 改尺寸（`check_html_contract.py` 拦这条）。
- `.scene` 外壳必须保留，字幕和时长同步靠它；canvas 只是 section 内部的图层。
- `check_html_contract.py` 对含 `hf-seek` 的页面跳过"动效选择器全部落空"门禁（canvas 本来没有 DOM 选择器）。

## 页面节奏与画面排期（口播片段锚定）

什么时候读：页面切换和语音对不上、一页太快/太慢、想改每屏停留时间。

- 2026-11-09 起，分镜不再按“一页几句”配额：模型自己决定页数和切点，但每屏必须写 `data-voiceover`，逐字等于这一页实际说到的那段原文。`R3` 从分镜的 `voiceover_text` 自动注入，模型不用手写。
- `align_scenes_to_caption_cues()` 用这段原文在真实词级时间码里找页面起点；页长 = 下一屏起点 − 本屏起点。不再按作者期时长在句子内部按比例切。
- 旧项目没有 `data-voiceover` 时仍走旧的句子组锚定 + 组内比例；新项目一律走新逻辑。
- 页面切换落在词首，句末停顿自然归到上一页；最后一页补到口播结束。
- 一页只有 2 秒却塞 4 个信息点，先修分镜，不要靠拉长/压缩动画。
- 实测：1501-rebuild 7 句 → 7 页，页长 5.4–8.4 秒，和每句真实时长一致；旧版 12 页是作者期 4.2–4.6 秒被等比缩放，页长和内容无关。

## 动效按真实词触发（window.__cue）与屏内出场序（window.__slot）

什么时候读：动效"和语音对不上"、动作总是挤在开头或屏尾、标题最后一个才出、最后一个元素只留零点几秒、或者要改 `S2` / `R1` 的时间写法。

- Dify 里跑的时候还没有 TTS，模型只能猜秒。同步阶段已经有真实时间码，`sync_video.py` 会在 `<head>` 注入 `<script id="cue-runtime">`：
  - `window.__cueLines`：全片字幕行（文字、绝对起点、时长、句子 id）；`__cue` **只在属于这一屏的句子里找**，不会再命中前一句同一个词后被压到 0.02 秒；
  - `window.__cueWords[scene]`：ASR 词级时间（只作兜底）；
  - `window.__cue(scene, 关键词, 默认秒)`：返回**作者期相对秒**（已除以 `data-timeline-scale`），交给 `at()` 后会还原成真实相对秒；
  - `window.__slot(scene, 序号, 总数, 关键词, 卡片时长)`：返回**本屏相对秒**，是屏内动作的唯一入口。它按真实屏长铺开一屏（顺序由 `R1` 给的序号决定）：**有余量时按等间隔排、末位收在切点前 2.0s**（`window.__slotTail` 改了就行，默认 2.0），挤不下时才退回按收尾时刻等距；`beat` 只在槽内微调。单位同 `__cue`，除以 `data-timeline-scale` 再交给 `at()`。
    一屏的卡片总时长超过可用窗口时（一屏塞三四个长卡），末位仍会压到切点——那是内容过载，先减屏内元素，不要去调 `__slotTail`；
  - `window.__sceneCardDur[scene]`：`R1` 写进去的本屏每张卡时长，`__slot` 靠它算尾界；
  - `window.__cueAbs(scene, 关键词, fallbackAbs)`：返回**绝对秒**，只给转场脚本用；
  - `window.__sceneStart(scene)`：这一屏的绝对起点。
- `R1` 的写法：`at(slot('s04', 1, 5, '关键词', __cardDur[1]))`，并在 builder 前导定义 `var slot = ...`、写 `window.__sceneCardDur[scene]`。
- 注入是幂等的：重复 sync 不会叠加脚本。没有 transcript 时整段跳过，`__slot` 退回按卡片时长独立算。

## 动作时刻错位、转场吃掉入场、整屏没动效（2026-11-19）

什么时候读：某屏动效「出现的时刻不对」「出现后跑到画面外」「转场一结束东西已经在画上了」「这屏明明写了动效却一点不动」。

### 症状一：长屏后半段的动作提前一个屏起点

`sync_video` 的 `patchTimeline` 以前用 `if (args[position] < start) args[position] += start` 猜「相对秒还是绝对秒」。短屏（3–4 秒）里相对秒永远小于屏起点，猜得对；11.7 秒的长屏只要把动作放到后半段，相对秒就比屏起点大，于是不补，被当成绝对秒用——整条动作提前整整一个屏起点。20261119-1549 的 s02：`cue('s02','既怕开始')` 算出 8.33s，实际应该是 3.193+8.33=11.52s，成片里 8.33s 就冲出去了，屏尾 4.7 秒全静止。

修法：按 builder 形参判定。`function(timeline, at)` 是屏内 builder，位置一律相对秒、无条件补屏起点；`function(timeline)` 是骨架/转场 builder，写的是绝对秒，一处都不补。不要再猜。

### 症状二：转场一结束，元素已经到位（「直接出现」）

转场窗口（`data-pt-dur`）里整屏被快照/遮罩盖着，屏内入场在这段跑完，观众根本看不见。20261119-1549 的 s07：flip3d 0.92s，T26 入场 1.0s 从 0.02s 就起跑，转场结束那一刻 title 已 99.9%、media 已 93%——看着就是「图片和文字转场完直接出现」。

修法：`sync_video` 的 `stamp_pt_durations` 解析 `__pt(...)` 调用，把每屏转场时长写进 `data-pt-dur`；`patchTimeline` 在相对模式下把落在 `start + ptDur + 0.02` 之前的动作抬到后面。

### 症状三：屏首 set 被当成越界动作

骨架的 `timeline.set(section, {autoAlpha:0}, end)` 本来就写在屏尾，被 clamp 夹到 `end-0.06` 后，时间线检查每天报 6 条 `position-clamped` 假 error。现在 clamp 跳过带 `autoAlpha` 的 set。

### 症状四：写了动效，整屏一动不动

先查这一屏的 `<script>` 能不能解析：把每个内联块抽出来跑 `node --check`，再数这一屏有没有 canvas
（`document.querySelectorAll('[data-scene="sXX"] canvas').length`）。两种表现都指向同一件事——
**整块 script 语法错误，浏览器把它丢了**：`20261119-1549` 的 s06 是从头就 `SyntaxError`；
`20261119-2223` 的 s01 是**没有背景、所有元素从第 0 帧就是最终态**，5 秒里逐帧像素完全一致。

成因有两个，都在外壳上：

1. 上游把脚本写成 IIFE 结尾 `})();`，外层是 `push(function(){...})`，那个空的 `()` 把 push 的 `}` 吞掉；
2. 外壳是"补在最后一块身上"的：`R2` 先按括号差补 `});`，**之后**才丢块（同一元素第二张进入卡、
   target 不在本屏），最后一块一丢，`});` 跟着没了，`{` 12 对 `}` 11 → `Unexpected end of input`。
   这一屏的背景卡和入场卡**一条都没注册**，检查器还按文本数着「3 条 preset」，`data-motion-skipped`
   也只记了被丢的那一条。

修法（2026-11-20，已进 `R2`）：外壳**只由 `R2` 生成一次**。先把 `<script>`、`push(function(timeline, at){`、
结尾的 `})();` / `});`、上游那行 `var cue = ...` 全部剥掉，只留 body；丢块、补首帧隐藏、补默认入场都在
body 层做；最后统一拼 `"<script>\n" + PUSH_HEAD + "\n" + CUE_LINE + "\n" + body + "\n});\n</script>"`。
不再有括号计数、不再有第二次装壳，块怎么丢都碰不到外壳。

### 症状五：第四到第五页看不见转场，最后一个元素只留零点几秒（2026-11-20，已治本）

`20261120-1424` 六屏只有 2 刀转场，第 4→5 页是硬切；同时 6 屏里 5 屏的标题最后一个出场，最后一屏的
标题「人生成立」只留 0.47s。两条症状同一批改掉，因为都是「结构交给模型了」：

- **转场**：`S2` 的 `transition` 是按屏可选字段，`R3` 见到没给 / kind 不在白名单就 `continue`。
  白名单还只写了 8 个 kind，而目录有 15 张 PT（PT09–PT15 选了也静默变硬切）。
  现在 `R3` 按切点表逐刀生成 **N-1 条**，kind 从 `catalog.page_transition` 派生；模型漏给的刀按
  「本片转场族（模型选中的 + 目录顺序补到 3 种）」顺延，并 warning 点名重跑 `S2`。
- **屏内时刻**：位置原来是「该元素的 `beat` 在口播里的时刻」，被 `__cue` 的 `0.72×屏长` 上限压一刀。
  标题是概括句，模型把 `beat` 挑在句子落点上 → 标题永远最后出；上限只看「什么时候开始露」，
  不知道卡自己要演多久 → T05 的 2.0s 揭示从切点前 1.66s 起跑，被盖掉时还剩 0.34s。
  现在 `R1` 按 `role` 定槽位（title → 辅助 → body → media → 组件 → state），`__slot` 按真实屏长
  铺开一屏：有余量按等间隔、末位收在切点前 2.0s，挤不下才退回按收尾等距；`beat` 只在槽内微调。

自查口径：每屏 `data-pt-dur` 的个数 = 屏数 − 1；屏内最后一个动作的「起点 + 卡片时长」必须 ≤ 真实切点 − 0.3s。

## 转场不生效、字看不见、文字压照片怎么查

什么时候读：转场脚本明明写了滑入/擦除，成片每一刀都是硬切；成片里出现"有一行看不清""文字压在照片上""标题特别小""每页都是硬切""组件样式几乎看不到"。

这五条症状同一批出现时，根因都在**版面与运行时的所有权**上，不在模型写得对不对。修法一律落在生成端（composer / sync_video / kit），不靠门禁拦。

### 先按症状定方向

从症状往下走，一步对到一类原因：

- **每一刀都是硬切**：先看渲染日志里有没有这两行，它们比看画面快得多：
  - `[Browser:WARN] scene builder failed TypeError: window.__pt is not a function` → 见下面「页间转场在渲染器里退化成硬切（2026-11-16 已修）」，转场整条丢了。
  - 没有这一行、但成片仍是硬切 → 再往下看显隐时序，见下面「症状四：每页都是硬切」。
- **某一行字和背景色糊在一起** → 组件调色板挂在根节点、背景 tone 挂在每屏，两边对不上，见「症状一」。
- **文字压在 inset 照片上**，一半在图上、一半在底色上 → 照片矩形没被解析到，版面没做避让，见「症状二」。
- **标题只有 43px**，比 45px 的字幕还小 → 缩字没有下限，见「症状三」。
- **组件几乎看不到**、挤成几块砖 → 组件被收进窄文字栏，见「症状五」。

### 症状一：某一行字和背景色糊在一起

组件（`.ui-*`）的调色板 `components.css` 挂在**根节点** `#stage[data-bg-tone]` 上，
文字色由 `layout_composer` 挂在**每屏**的 `data-bg-tone` 上。模型把根写成 `light`、
九屏全写 `dark` 时，组件拿到浅底配色（`#182528`）而背景卡是近黑 `#0B0F18` —— 深墨压黑底。

修法（两处，都是生成端）：`sync_video.inject_layout_composer` 把根节点 tone 归一成各屏的多数派；
`layout_composer` 再给每屏发一套 `--ui-*`（`UI_VARS`），组件永远跟着自己那一屏走，根节点写错也不影响。

**要"量"而不是"看"的时候，口径写死这三条**（2026-11-17 实测，四点五秒的片子就量出过 1.01）：

1. 取片盒内**线性化相对亮度**的 p97（文字笔画）与 p50（底色），对比度 `(Y97+0.05)/(Y50+0.05)`。
   用 p97 不用 p90：中文细笔画只占盒内像素 3–6%，p90 会落在底色上。
2. **只量"字已经在屏幕上"的帧**：`opacity` 要取**自身 + 全部后代的最小值**——拆词动画父元素 `opacity:1` 时子 `span` 可能还是 0；
   门槛也不能卡 0.98，本地 `[data-role="body"]` 常态就是 `0.92`（次级层级是设计），卡 0.98 会把整类正文判成"没出来"。
3. **盒大半在画布外的片不算对比度**：量到的是画布边缘的一条，先按几何问题（越界）修，修完再量。

低于 3.0 就是"字在但认不出"，落在这个区间的屏先查背景卡族与垫层，不要先改字号。

### 症状二：文字压在 inset 照片上，一半在图上、一半在底色上

`_media_rect()` 是**倒着从 HTML 里正则抠照片坐标**的。模型写 `left: 0` / `right: 0`（无单位）时
旧正则要求"数字+px"，解析失败 → 版面以为没有照片 → 不做避让。重跑还会自食：抠到的是上一轮
自己注入的 `section[...]{left:608px;width:397px}`。

修法：`_media_rect` 只认带 `width` 的规则、跳过 `section[` 开头的补丁、单位可省。
`build_scene_css` 改成"文字区与照片矩形真的相交才动手"，缩照片时**保比例、保间距**，
横向挤不出 240px 时改为上下分带——版面自己保证不重叠。

**2026-11-20 补一个同症状、不同根源的**：照片 role 是 `texture` 时，`R2` 原来把它当满屏底纹写成
`1080×1920`（`slot="full"`），而 `layout_composer` 的分带判定是 `slot != "full"`——于是认为这屏
"整屏底纹、不用让位"，文字照旧走 `top:150; height:1383` 居中；随后 media_fix 把满屏图压成
913–1533 的横带时，`anchor` 又被 `else: anchor="center"` 重置，文字就压在照片上
（20261119-2223 的 s06：标题下沿压进图 47px、正文 96px 整块在图里）。
修法：`texture` 不再冒充 `full`，和别的 role 一样落 840 通栏横带（高度 620），只有 `full` 才满屏
（而 `full` 在 `S2N` 早已归一成 `band`）。分带成立后这一屏自动走 flex 排版，整组居中、间距恒 24。

### 症状三：标题只有 43px，比 45px 的字幕还小

> **2026-11-17 起机制已换**：`_downgrade` 和四档字阶都删了，字号改由 `solve_scale()` 按
> 栏宽 ÷ 每行字数几何求解。下面这段是历史成因，留着是为了看懂老项目。

`_downgrade` 按"每行字数 = 宽 / 字号"反推缩字，没有下限；照片占掉 86% 画幅时文字栏只剩 420，
一路乘 0.94 就收到 43。字阶四档的下沿是 60/36/34/30。

修法：`ROLE_FLOOR` 硬地板（title 60、body 34、note/label 34）；文字栏最窄 480（420 时 8 字标题会折成 7+1）；
`kit.split` 的 words 用 `pre-wrap` 而不是 `pre`（中文没空格，整行被拆成一个不可断的 span），
再配 `text-wrap:balance`，杜绝单字成行。

### 症状四：每页都是硬切

`__pt` 的排期写在 `sceneStart - 0.45`，而进入屏在切点之前是 `visibility:hidden`，
整条转场演在看不见的元素上。实测 s02 切点 5.817：5.574 时 clip 已 36%、5.79 到 99%，
屏一直 hidden，5.82 才可见、此时 clip 99.9%。

修法：`__pt` 自己把起点夹到 `__sceneStart(id)`（模型传 -0.45 也不认），配合 `apply_scene_overlap`
的 tail=0.9（上一屏多留 0.9 秒），交接窗口就是切点后 0.3–0.6 秒。`zoom-cover` / `flip3d` 额外补了
透明度交叉，否则不透明的进入屏一上来就把上一屏盖死，看起来还是硬切。

- 根因在显隐时序，不在转场代码：渲染器按 `data-start` 切场景显隐，**进入屏在切点之前是 hidden**；
  所以动作写 `__sceneStart - 0.5` 的那一套（2026-11-14 的设计）全部发生在这屏不可见的时候，等于没做。
- 本地注入的 `scene-window-runtime`（`sync_video.install_scene_window`）本来想给 0.5s 提前量，
  但它以前只挂 `__seekTo`：① 页面自己的 `onUpdate` 驱动在 DOMContentLoaded 里注册，比注入脚本晚，
  会把它覆盖；② 渲染器实际是 `window.dispatchEvent(new CustomEvent('hf-seek',{detail:{time}}))`，
  只挂 `document` 的监听收不到（2026-11-15 实测：DOM 里能看见，成片里看不见）。
- 现行模型（`sync_video.apply_scene_overlap`）：**`data-start` 不动**，进入屏仍在切点才可见；把上一屏的
  `data-duration` 往后延长 `tail=0.9` 秒，真实切点另存 `data-cue-start`（与 `data-start` 相同）。
  屏内动效、`__sceneStart`、cue 时间码全锚在 `data-cue-start` 上，所以节奏不变；两屏在这 0.9 秒里同时在，
  转场才有对象可动。
  曾经试过"进入屏 `data-start` 提前 0.45 秒整屏滑进来"，渲染器按自己的场景窗口切显隐，提前可见不成立，已废弃。
- 不要只动 `media` / `bg` 某一层：整屏滑进来时其它层会在切点跳一下，还是硬切（2026-11-15 实测两次）。
- 页间转场只有 8 种可用的实现（`window.__pt`，见 `sync_video.PAGE_TRANSITIONS_JS`）：
  `iris` / `wipe-diag` / `curtain` / `blinds` / `zoom-cover` / `push-both` / `flip3d` / `flash-cut`。
  **双图 shader 转场用不到页间**（那批已整族删除）：它们要 from/to 两帧纹理，而"上一页"是 DOM 不是图像，
  逐帧 seek 里截不出上一页的纹理。这类实现只能用于屏内照片层切换。
- 自检别用肉眼抽样：按 `ffmpeg -ss 切点+0.1/+0.25` 抽两帧比对均差不小于 5 才算真的动了。

### 症状五：组件几乎看不到

除了症状一的配色，还有两层：`normalize_scene_layers` 会把 `.ui-*` 收进 420px 的文字栏
（2 列各 202px、36px 字撑成 142px 的砖）；模型也会在 `.scene-copy` 里写绝对定位
（`top:1120px;left:90px` 双倍位移、右边界顶到 1080）。

修法：窄栏（<560）的 `.ui-grid` 退成单列、`.ui-steps` 退成纵向；组件字号地板 1.55
（24px 基准 → 37px，竖屏小字下限 34）；`.scene-copy` 的直接子元素一律 `position:relative`（流式），
版面只归 composer 管。

### 症状六：字小、旁边一条空白、组件列表看着是空的（2026-11-17 已修）

三个症状三个真因，都在生成端，别再去调模型：

1. **标题一路缩到地板 60px。** `sync_video` 取"标题最长一行"给 `_downgrade` 当 `line_chars`，
   没有 `<br>` 时它等于整句长度（17 个字的标题 → 17），`line_chars` 那道"硬换行不许折行"
   的保护就把字号按"17 字一行"缩，缩到 `ROLE_FLOOR` 60 停。
   修法：`len(_raw) > 1`（真有 `<br>`）才给 `line_chars`，否则交给 `text-wrap: balance`。
2. **无图屏也按 zone 收窄。** `.scene-copy` 的宽度以前一律 `max(zone.width, 760)`，
   `left-middle` 是 780，1080 的画布右边空 210px，字还在 780 里自己折行。
   修法：没有照片就不再避让，`width = avail_w`（900）。
   顺带：窄栏（<620）标题放宽到 3 行——482 的竖栏 18 个字压 2 行要 ≤53px，撞地板反而更小。
3. **组件列表"空的"。** 组件在、行数据也在，是 `components.css` 里 `.ui-table th` 有 `color`、
   `td` 没有，`td` 继承到文档默认黑，压在同色深底上（实测表头最亮 171、标题 247、行 39）。
   修法两层：`.ui-table td{color:var(--ui-ink)}`，根治是 `layout_composer` 给
   `.scene-copy` 补 `color:var(--ui-ink)`——所有"只给子元素上色"的组件（`.ui-toast` 这类）一起修好。

附带修的两条：`.scene-copy` 从 top/bottom 撑满改成 `height:auto` + 锚一端，柔光底衬
不再是一块占屏 80% 的大暗块；`media_fix`（宁可缩照片也不压字）以前判 `rect.get("cls")`，
新版行内样式的照片没有 cls，整条分支是死代码，现在 `cls` 和 `data-media-slot` 都能落选择器。

### 症状七：整屏字小、正文比字幕还小

2026-11-17 实测 20261117-1740：s02 最大 40px、s03 最大 36px（字幕是 45px）、五屏卡在 76px。
三个成因按顺序查：

1. **措辞猜档**（已删除）：旧 `normalise_scale` 用 `超大|巨大|三行|块|段` 去匹配分镜的自由文本，
   分镜写"大字结论""三条大字""三张大卡"全部落进最保守一档。现在字号 = 栏宽 ÷ 每行字数，
   读 `data-composition-scale` 只认 `vertical`。
2. **漏写 title**：`S2` 要求 `copy` 必有 `title`，漏了之后整屏最大的字只能落在 lead/body 上。
   提示词已把"漏写 title 视为不合格"写死；诊断看 `[data-role="title"]` 有没有出现。
3. **组件为 0**：全片没有 `ui-*`，就没有大数字／大卡片当视觉锚，只剩文字块。看
   `visual_budget.components` 是否为空（上游没给槽位），`S2` 现在要求槽位非空时至少用 1 个。

### 症状八：字压在照片上（横向压进去一条）

`layout_composer` 会把照片等比缩到文字栏外侧，写的是
`section[data-scene=...] [data-media-slot=...]{left/top/width/height}`。
但 `R2` 把照片矩形写成**行内 style**，行内优先级高于普通选择器，让位规则整段失效
（2026-11-17 s05 实测压进去 110px）。现在 `media_fix` 四个属性都带 `!important`。
改这里必须一起看 `sync_video._media_rect`：它读的是行内 style，改成 CSS 规则要同步改解析。

### 症状九：诊断说「少给动效」，其实是检查器口径错（2026-11-17 已修）

`check_html_contract.py` 原来这样数：

```python
_markers = re.findall(r'preset:\s*(T\d+|X\d+|P\d+|W\d+|U\d+)', doc)     # 不数 S 卡
_state_markers = re.findall(r'preset:\s*(T06|X01|X02|U01|U02|U04|U05)', doc)  # 状态类写死 6 个
```

S02/S07/S23 这些**就是状态卡**，却一条都不算，于是：报"7 个场景只有 4 条 preset"（实际 10 条）、
报"0 条状态变化"（实际 6 条），每次都把人往"`S2` 没产出"上带。
现在条数 = 所有非背景卡（`B*` 排除），状态类 = `presets.json` 里 `role` 为 `state_text`/`state_block`
的编号，从能力库派生，找不到能力库就跳过（不误报）。另外新增"这些屏只有 1 条内容动效"的点名，
直接列出屏号，按屏回 `S2` 补一条状态卡。

### 页间转场在渲染器里退化成硬切（2026-11-16 已修）

症状：浏览器里 seek 到切点后 `getComputedStyle(scene).clipPath` 明明在变（5.12s 时 s02 只擦了 0.55%，5.35s 到 64%），成片同一时刻已经是整屏新页，每一刀都是硬切。

真因不在 `__pt` 的实现，也不在显隐时序，而是**转场 builder 根本没执行**：

- HyperFrames 编译期会把 body 里的内联 `<script>` 改成 `type="text/hyperframes-deferred"` 之类的特殊类型，再在 `DOMContentLoaded` 回调里按原顺序重新 append 一遍（`deferScriptsUntilFonts` + `afterFontsFallback`）。
- 重放发生在 `DOMContentLoaded` 回调内部，此刻 `document.readyState` 是 `interactive`，不是 `loading`。页面自己的 boot 写的是 `readyState === 'loading' ? 监听 DOMContentLoaded : 立即执行`，于是走了「立即执行」。
- 而 `page-transition-runtime`（定义 `window.__pt`）原来注入在 `</body>` 前，排在 boot 之后，还没被重放到。转场 builder 一调用就抛 `window.__pt is not a function`，被页面的 `try { build(...) } catch` 吞成一条 `console.warn` —— 于是五个切点的转场全部没有建立。
- 所以「在浏览器里打开页面看是对的」不能当证据：直接用 file:// 打开时 boot 走的是 DOMContentLoaded 分支，那时 `__pt` 已经定义好了。**只有走渲染器重放脚本的路径才会失败**。

修法（三处，都在生成端）：

- `sync_video.install_page_transitions` 把 `page-transition-runtime` 注入到 `</head>` 前，和 `__gtCut` 的 `GT_HEAD_SCRIPTS` 一致。head 里的内联脚本按原顺序解析、不打延迟类型，一定早于所有 builder。
- 同一个函数在 `<head>` 最前再注入一个 `page-transition-shim`：`window.__pt` 只把参数塞进 `__ptQueue`，真正的运行时执行时调 `window.__ptFlush()` 一次性补建。就算以后渲染器再改脚本时序，转场也只会晚一点建，不会丢。
- `motion-runtime` 里 `watchIncomingWrite` 的短路判据从 `window.__pt` 改成 `window.__ptFlush`。判 `__pt` 会因为 shim 永远为真，让「转场在进入屏起点写透明度/缩放」这条检查重新变成永久失效。

验证（不要再靠肉眼抽样）：同一份生成物，修前 5.06–6.0 秒逐帧差是 0.3（等于静止），修后 5.08 起 1.3 → 3.8 → 7.7 → 回落，抽 5.30 那帧能看到上一屏被斜向擦开、右边露出新页的点阵背景。

### 顺带两条不是版面的

- **`timeline.call` 不归 patchTimeline 管**：T05 打字机的位置被当成绝对秒，整段动画在别的屏跑完。
  现在 `call` 会按"这个 builder 最近解析到的场景起点"补偏移。
- **句级时间码被当词级用**：`use_char_axis` 只看字符数是否相等，句级 6 条也能凑齐，
  字符轴变成平的（一句话里每个字都映射到句首），屏内切点全塌到"上一屏 +0.12s"。
  现在要求 `len(word_entries) >= 2 × 句数` 才启用字符轴。

## 排版门禁：现在只诊断

2026-11-16 起，排版问题**不再停止渲染**。`check_html_layout.mjs` 报的两类重问题照样会被点名：

- 多数场景开场即空白（≥ 一半场景在开场 0.4 秒没有可见元素）；
- 多数场景内容出画布（≥ 一半场景的 `top < 0` 或 `bottom > 1920`）。

它们和单屏出画布、组件轻微重叠、垂直中心偏离一起写进 `诊断/检查结果.txt`，然后**照常渲染**。
文字位置本身由 `layout_composer.py` 按 `text_zone` / `align` / `scale` 生成，模型手写的绝对定位是主要来源；
要改就从构图枚举或场景 CSS 改，不要回头加"检测到就停"。

想要旧的拦截行为：`STRICT_RENDER=1 bash render.sh`。

## 成片复核工具（联系表、响度、音画对齐）

什么时候读：想整体看一遍镜头、怀疑响度不对、怀疑音效和画面不同步。

**渲染流程已内置这一步**：`render.sh` 在契约检查之后会生成 `成片/复核/联系表.jpg` 和 `成片/复核/音频报告.txt`，只报告不拦截。下面的命令用于单独重跑或换参数。

三个工具在 `runtime/scripts/`；每个项目目录里的 `脚本/` 是它们的副本（新项目自动带上，老项目用 runtime 路径）。

```bash
cd "runtime/scripts"

# 1) 联系表：每 2 秒取一帧，6 列，缩略宽 384，一次看完所有镜头
bash contact_sheet.sh "成品/纪念逝者/成片/最终视频.mp4" /tmp/sheet.jpg 2 6 384

# 2) 响度/真峰/削波/长静音/音视频时长是否一致
bash audio_check.sh "成品/纪念逝者/成片/最终视频.mp4" -14.5

# 3) 音效与事件时间是否对齐（需要一份事件 JSON）
python3 audio_sync_check.py 成片/最终视频.mp4 events.json --fps 30
```

- `contact_sheet.sh` 在没有 `drawtext` 滤镜的 ffmpeg 上会自动去掉时间戳，仍然出图。
- `audio_check.sh` 的目标值按本仓库标准传 `-14.5`；不传默认 `-14`。
- `normalize_final_audio.py` 走两遍 loudnorm（`linear=true`，实测 -14.08 LUFS / -1.46 dBTP）。单遍动态模式会过冲真峰（实测目标 -1.5 却跑出 +0.2 dBTP），`render.sh` 的响度关卡会直接判失败。
- `audio_sync_check.py` 要求事件 JSON：`[{"t": 1.20, "name": "click"}, ...]`，偏差超过 1 帧即判失败。
- `sound_kit.py` 是程序化音效素材库（纯 numpy），需要补音效时直接在脚本里 import。
- 另有 `capture_seek.mjs`：给暴露了 `window.seek(t)` 的页面用的逐帧抓取路径，主线渲染不走它。

画面与声音的工艺参考不进仓库；要查工艺直接看成品项目里的项目说明。

## 字幕整片不显示 / 文字半截 / 硬切 / 下划线错位（2026-11-16）

什么时候读：成片里**一个字幕都没出现**、某屏文字只剩后半句或下半行、页间全是硬切、下划线跑到文字块底下。

这几条都是"代码实现"问题，不是模型写坏，根因与修法都在生成端：

| 症状 | 根因 | 修法 |
|---|---|---|
| 字幕一条都不显示 | 字幕 CSS 是 `.caption{display:none}` + `.show` 切换；切换控制器被塞进"最后一个 `<script>`"，GT/转场运行时安装时整段重写那个 script，控制器被删 | 控制器独立成 `<script id="media-clock-state">`，插在 `</body>` 前，并在转场之后安装 |
| 文字只剩后半句 / 半行 | 打字类卡用 `timeline.call` 改 `textContent`，渲染 seek 会跳过 call，停在某一刻的文本 | 改成 `clip-path` 裁剪揭示（`T05`）；Cards 里禁止 textContent 改字 |
| 文字被水平硬切一半 | 强调卡对文字做 `scale`，分块截图只重绘瓦片 | 强调只用 `opacity`（`S07`），不对文字做 scale |
| 页间全是硬切 | 切点表缺刀，`R3` 就少生成几条 `__pt` | `R3` 按切点表逐刀生成 `__pt`，条数 = 屏数 − 1；缺的刀按本片转场族补齐并点名重跑 `S2` |
| 下划线位置错 | 绝对定位的条贴在多行目标底部 | K07 改背景片段逐行铺；K07/K08 只指 `accent`/`num`/`label` |
| 文字压在照片上 | 照片框由模型随手写坐标，版面反查不到矩形 | `R2` 按槽位（top/bottom/left/right/full）放照片，文字自动落另一半 |

排查顺序：先确认是不是**旧项目**（旧 HTML 里的卡代码是烘焙进去的，重跑同步不会变），再看是不是**运行时注入被覆盖**（搜 `media-clock-state`），最后才怀疑模型。

## 跑外部检查器：两条硬前提 + 一条落点

什么时候读：要跑仓库外的检查/取证脚本（CDP 那一类），报 `WebSocket is not defined`，或者只打一句 `unsettled top-level await` 什么都没出。

| 症状 | 成因 | 修法 |
|---|---|---|
| `ReferenceError: WebSocket is not defined` | 脚本用全局 `WebSocket` 连 CDP；Node < 22 没有这个全局（本机默认 v20.20.2） | 换 `~/.nvm/versions/node/v22.23.3/bin/node` 跑 |
| 只有 `Warning: Detected unsettled top-level await`，无输出 | Chrome 子进程 `sandbox initialization failed` → GPU 进程 unusable → `FATAL ... Goodbye`，`launch()` 永远等不到调试端口 | 参数补 `--no-sandbox --disable-dev-shm-usage`（本地 puppeteer 检查器一直带着，外部脚本多半没带） |
| 中文路径 `file://` 打开报错或白页 | `fileUrl()` 只按 Windows 盘符拼 | POSIX 分支：`'file://' + 绝对路径逐段 encodeURIComponent` |

**判断脚本是不是真跑起来了**：能读到页面暴露的量测钩子（`window.__canvas()` / `window.__screens()` 之类）才算跑起来；读不到一律先怀疑浏览器没起来，不要当成"页面没写钩子"去改页面。

**落点**：一次性的对照脚本放 `成品/` 下的临时目录，结论并进文档后整个删掉；不要把外部脚本散在工作区根。
