# 生图与图片链路（GPT Image / 即梦 / 已下载图片对号）

- 什么时候读：画面要出真实照片、图片没生成、想先看一张效果、改生图模型或尺寸、用即梦出了图要丢进项目
- 不用读：只跑流程看 `经验文档/使用说明.md`；图已经齐了只想渲染

图片**不在 Dify 里生成**：Dify 的 HTTP 节点超时短、返回体积大（b64 单张 2–4MB）、失败重试没有状态，
一条片 9–12 张必然撞限制。Dify 只出计划，执行放本地，能并发、能缓存、能只补一张。

## 分工

```text
Dify H01P 图像计划（逐屏决定 role；有图的写英文 prompt + 尺寸 + 文字留白侧 + 镜头运动，无图的写 html_brief）
→ Dify H01PV 归一化（校验字段、补漏屏的 HTML 背景、拆出 image_brief_json）
→ 场景组按 role 落版：照片屏写 <img src="{{IMG:图片id}}">，无图屏写 data-visual="html" + data-anim="bg"
→ 本地 generate_images.py 只对有图屏调 GPT Image API → 媒体/图片/<id>.png
→ 构建时把 {{IMG:图片id}} 替换成 媒体/图片/<id>.png
→ 渲染
```

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `IMAGE_API_KEY` / `OPENAI_API_KEY` / `ARK_API_KEY` | 无 | 必填；Key 不进项目文件、不进日志 |
| `IMAGE_API_BASE` | `https://api.openai.com/v1` | 兼容 OpenAI Images 协议的网关也可以；填火山方舟会自动切模式 |
| `IMAGE_MODEL` | 按 Base 自动选 | OpenAI 下是 `gpt-image-1`，火山下是 `doubao-seedream-4-0-250828` |
| `IMAGE_SIZE` | `1024x1536` | 竖屏满图；局部横图在计划里写 `1536x1024` |
| `IMAGE_QUALITY` | `medium` | `low` / `medium` / `high`，只对 OpenAI 生效 |

### 用即梦 / 火山方舟

即梦（Dreamina，`jimeng.jianying.com`）是字节的 C 端产品，**没有公开 API**，只能网页/App 手动出图。它背后的图像模型是 Seedream，对外通过**火山方舟**提供，接口是 OpenAI Images 兼容的：

```text
Base URL   https://ark.cn-beijing.volces.com/api/v3
接口        POST /images/generations
鉴权        Authorization: Bearer <ARK_API_KEY>
模型        doubao-seedream-4-0-250828（或 doubao-seedream-3-0-t2i-250415）
```

拿 Key 的路径：

1. 打开 <https://www.volcengine.com/product/ark>，注册并完成实名。
2. 进控制台 <https://console.volcengine.com/ark>，左侧「开通管理」里开通 Seedream 图片生成模型。
3. 左侧「API Key 管理」→ 创建 API Key，复制出来。
4. 配到终端：

```bash
export ARK_API_KEY=你的key
export IMAGE_API_BASE=https://ark.cn-beijing.volces.com/api/v3
```

脚本检测到 Base 里含 `volces.com` 就自动切火山模式：

- 不发 `quality` / `output_format`，改发 `response_format: "url"`，然后下载；
- **`watermark: false`**（火山默认加水印，不关的话每张图右下角有"AI生成"）；
- 尺寸自动映射：`1024x1536 → 832x1248`、`1536x1024 → 1248x832`、`1080x1920 → 720x1280`（Seedream 3.0 只认固定尺寸；4.0 也接受这些值）。
- 模型要在控制台**先开通**，没开通会返回 `InvalidEndpointOrModel` 或 404。

### 只有即梦网页版，没有 API

也能用：手动出图，按图片 id 命名丢进 `媒体/图片/`，然后跳过生图。

```text
成品/项目名/媒体/图片/s01.png
成品/项目名/媒体/图片/s02.png
...
```

- 文件名必须是 `图片计划.json` 里的 `id`（默认等于 `scene_id`），扩展名 `.png` / `.jpg` / `.jpeg` / `.webp` 都认。
- 尺寸建议 1080×1920 或 832×1248（2:3），`object-fit: cover` 会按 9:16 裁左右。
- 出图提示词直接用 `媒体/图片计划.json` 里对应那条的 `prompt`，粘进即梦即可。
- **两种放法都行**：叫 `s02.png` 的直接按名字对上；叫即梦默认名（`jimeng-…`）的按修改时间从早到晚对号，
  构建会打印「哪张配哪屏」，看一眼就知道配得对不对。不想让它按时间猜，加 `--strict-ids`。
  `role=html` 的屏不占图片位，会跳过（见下节）。
- 放好后：`--skip-images` 走构建，缺哪张会直接点名。

#### 环境变量不用手动 source

`MIMO_API_KEY` 写在 `~/.zshrc` 里时，统一入口（非登录 shell）拿不到，会报「缺少 MIMO_API_KEY」。
`build_black_frame_project.py` 现在会自动翻 `~/.zshrc`、`~/.zprofile`、`~/.bash_profile`、`~/.profile`
找这个名字，只用不打印（日志只写"已从某文件读取"）。

#### 对号规则（id 优先，其余按修改时间）

`媒体/图片/s02.png` 这类按 id 命名的优先；剩下的（即梦下载名）按修改时间从早到晚，
依次配给第一个、第二个有图屏。`role=html` 的屏不生成图、也不占位。
构建会打印完整对号表，先看一眼再出片；要它只认 id 命名就加 `--strict-ids`。

想先看它打算怎么配：

```bash
cd "成品/项目名"
python3 脚本/ingest_images.py                      # 预览：哪张配哪屏、缺哪张
python3 脚本/ingest_images.py --from ~/Downloads   # 先把下载目录里的图搬进来（保持原名）
python3 脚本/ingest_images.py --strict-ids         # 只认 id 命名，别的一概不用
```

- 默认按**修改时间**排；一次性拖入导致时间被改，就用 `--order name`。
- 即梦下载名带时间戳（`jimeng-2026-11-08-1234.png`），`--order name` 通常最稳。
- 数量对不上会直接说「还缺 s07、s08」或列出多出来的文件，不会瞎配。
- 这个脚本只预览和搬文件，**不改名**；构建用的是同一套规则，所以预览看到什么就是出片用的什么。
- **先导出提示词包**，别一张张翻 JSON：

```bash
cd "成品/项目名"
python3 脚本/generate_images.py --plan 媒体/图片计划.json --sheet
open 媒体/出图清单.html   # 双击也行：只有两个按钮，点完自动进"放图"
```

生成两样东西：

```text
媒体/出图/全部提示词.txt      所有提示词合集，分隔线切开，整份复制也不混
媒体/出图/s01.txt … s10.txt   每张一份：中文提示词（主）+ 英文提示词（备）+ 保存文件名
媒体/出图/README.txt          怎么出、放哪、文件对照表
媒体/出图清单.html            出图页：只有「复制全部中文」「打开文件夹」两个动作，
                              复制内容按【第 N 张 · id】分段、分隔线隔开；点完自动跳到"放图"（文件名 + 构建命令）
```

每份 txt 长这样：

```text
【s01】full · 文字留白 bottom · 镜头 push-in

这张画什么：空房间里的光

—— 中文提示词（复制这一段）——
<模型写的中文提示词>
画面里不要出现文字、字母、数字、logo、水印…构图给下侧留出干净的空白。

—— 英文提示词（可选，模型更吃英文）——
<英文 prompt，含全片风格前缀>

出图后保存为：s01.png
放进：媒体/图片/
```

`H01P` 现在每张同时给 `prompt`（英文）和 `prompt_zh`（中文），两条描述同一张画面。中文那条是给手动出图用的，复制就能用；英文那条留给 API 自动出图。缺 `prompt_zh` 时脚本会直接给英文全文，不会拿一句 subject 糊弄。

`build_black_frame_project.py ... --images-only` 会自动生成这一整套。

### 单独跑

```bash
cd "成品/项目名"
python3 脚本/generate_images.py --plan 媒体/图片计划.json --out 媒体/图片 --list   # 先看要生成哪些
python3 脚本/generate_images.py --plan 媒体/图片计划.json --only s01               # 先出一张看风格
python3 脚本/generate_images.py --plan 媒体/图片计划.json                          # 全量
python3 脚本/generate_images.py --plan 媒体/图片计划.json --force --only s03       # 重生成某张
python3 脚本/generate_images.py --plan 媒体/图片计划.json --dry-run                # 出占位图，跑通链路
```

- `媒体/图片/_生成记录.json` 记 prompt 哈希，prompt / 模型 / 尺寸 / 质量都没变就复用，不重复花钱。
- 失败会打印 `image sXX FAIL ...` 并以退出码 1 结束；按提示 `--only` 补那一张即可。
- 内容策略拒绝（HTTP 400）不会自动改写 prompt，换措辞后重跑。
- `--dry-run` 生成带 id 的占位图，用于验证版面与渲染链路，不产生费用。

### 构建时

`build_black_frame_project.py` 在写 `index.html` 之前：

1. 把 `image_plan_json` 落到 `媒体/图片计划.json`；
2. HTML 里有 `{{IMG:...}}` 就自动生图（`--skip-images` 可跳过）；
3. 把占位替换成 `媒体/图片/<id>.png`，文件不存在直接报错（`--allow-missing-images` 才放行）；
4. 打印哪些场景既没有图、也没有声明 `data-visual=html`。

只生成图片、不配音不渲染：

```bash
bash .../run_dify_output.sh 项目名 /path/to/output.json   # 正常入口
# 或
python3 tools/build_black_frame_project.py 项目名 --input-file ... --images-only
```

### 版面上的事实

- 计划里竖图是 `1024x1536`（2:3），画布是 `1080x1920`（9:16），`object-fit: cover` 会裁掉左右约 16%。所以 prompt 必须要求主体留在中间安全宽度，文字留白侧写进 `text_safe_zone`。
- 图片里的文字一律不许出现：prompt 统一追加 no text / no logos / no UI。
- 人物按主题决定：生活、职场、消费、家庭类可以自然露脸；纪念、医疗、未成年人、隐私题材避免可识别正脸。不要摆拍看镜头，不要塑料 AI 脸。
- 一致性只靠 `prompt_prefix`：同一支片子的介质、光学、光、色彩、质感全部写在这一段里，逐字拼到每张前面。换风格就改这一段，不要逐张改。

### 旧项目重渲染会被拦

`check_html_contract.py` 要求每个 scene 要么有 `媒体/图片/` 引用，要么带 `data-visual="html"` 和 `data-anim="bg"`。2026-11-08 之前那种全 HTML 图形、没有照片也没有声明 HTML 背景的项目会 FAIL（`这些场景没有图片，也没有 data-visual="html"`）。无图屏是合法形态，但必须是设计过的背景，不能是纯色空白。
