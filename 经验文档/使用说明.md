# 通用 HTML 视频项目使用说明

- 适用：视频工作流
- 最后核对：2026-10-25
- 什么时候读：跑完整流程、导 Dify、重渲染、改配置、加新项目之前

## 当前方案

本项目支持三种互相隔离的输出模式：

```text
仅 HTML：Dify 生成内容和 HTML → 浏览器预览
黑帧口播：Dify 生成 HTML + 口播文案 → MiMo TTS 口播 → 字幕、BGM、MP4
全合一：Dify 生成 HTML + HeyGen 数字人/口播 → 字幕、BGM、MP4
```

完整版中 HeyGen 只负责数字人表现和口播音轨，并始终保留数字人小窗；无数字人版本不调用 HeyGen，默认使用 MiMo TTS 生成口播。产品 UI、字幕、图表、流程、CTA 和元素级动效均由 HTML/CSS/GSAP 制作。字幕固定为中下方 `bottom:13%`、宽度随文字自适应（上限 80%）、45px 字号、1.35 行高、700 字重、白色无底板文字（只用柔和投影保证亮背景可读）；图片状正文可用满整屏，字幕会盖在画面底部，不强制底部留白。无数字人模式删除小窗后必须回收原占位区域，顶部标签和标题回到正常左上栅格，不得继续向右避让。

## 输入怎么进去

`A00` 只有一个必填框 `主题、原始文本或随口一句话`。可以直接粘贴聊天记录、会议纪要、文章、语音转写、清单或零散笔记，不需要先自己总结：

```text
任意素材 → A01 提炼（主张 + 论点 + 证据）→ A04 论点排序 → A06 按论点写口播 → A07 检查 → A08 按论点分镜
```

- 提炼结果在 `brief.distill`，下游只能用它的主张和论点，不许按素材顺序复述。
- 不设配额：几个论点、每段几句、总共多少字、分几屏，全部由内容和模型自己判断。
- `A07` 只拦三件事：JSON 结构坏掉、没有完整句子、时间连接词成串（在按过程复述）。其余判断（照搬、漏讲、转述对话、字数句数）只写进 `copy_warnings_json` 和 `content_diagnostics`，供你回看，不阻塞、不强制改写。
- 素材长度不等于视频长度：写得长就成片长，没有目标时长。

## 推荐入口

两个 Dify Workflow 都使用同一条命令：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/HTML视频项目/workflow_runtime/tools/run_dify_output.sh' 你的项目名
```

命令会打开 TextEdit。把 Dify 完整输出粘贴到 TextEdit，不要粘贴到终端；内容完整后自动继续。

- 只有 `html_document`：生成 `HTML视频项目/HTML预览/项目名.html`。
- 包含 `html_document` 和 `voiceover_script`：按已批准原文生成口播、同步字幕并生成 `HTML视频项目/项目名/成片/最终视频.mp4`。
- 包含 `html_document` 和 `heygen_response_json`：下载媒体、同步字幕并生成 `HTML视频项目/项目名/成片/最终视频.mp4`。

TextEdit 的原始输入会保存到：

```text
HTML视频项目/Dify输出/项目名-年月日-时分秒-dify-output.txt
```

黑帧口播输出还会保存：

```text
HTML视频项目/Dify输出/项目名-blackframe-input.json
HTML视频项目/Dify输出/项目名/html_document.html
HTML视频项目/Dify输出/项目名/voiceover_script.txt
```

全合一输出还会保存：

```text
HTML视频项目/Dify输出/项目名-unified-input.json
HTML视频项目/Dify输出/项目名/html_document.html
HTML视频项目/Dify输出/项目名/heygen_response.json
```

### 黑帧 TTS 可视化配置

不需要在命令里写 TTS 参数。导入 `04_黑帧口播_分组生成.yml` 后，在 Dify 的开始节点直接选择或填写：

| 配置项 | 可选项/默认值 |
|---|---|
| TTS 供应商 | `mimo`（默认）、`macos`、`openai-compatible` |
| TTS 模型名 | 填 `mimo-v2.5-tts`；留空也使用 `mimo-v2.5-tts` |
| TTS Base 地址 | `默认（按量付费）`、`Token Plan - 中国`、`Token Plan - 新加坡`、`Token Plan - 欧洲` |
| TTS 声音 | `mimo_default`（默认）、`冰糖`、`茉莉`、`苏打`、`白桦`、`Mia`、`Chloe`、`Milo`、`Dean` |

默认声音是 **`mimo_default`**，不是 `冰糖`。在 Dify 下拉框里直接点选音色即可；本地运行时不需要再写 `--tts-provider`、`--tts-model`、`--tts-voice` 或 Base 地址参数。

## 字幕（本地写）

### 样式

- 无底板：字幕只有文字本身，背景透明、无描边、无圆角、无内边距
- 文字：45px / 行高 1.35 / 字重 700 / 白色 / 水平居中 / 双层柔和黑色投影（`0 3px 12px` + `0 1px 4px`）
- 位置：中下方 `bottom:13%`，整体水平居中
- **尺寸自适应**：文字宽度跟着内容走（`width:auto`），最多占画布 80%（864px）；多行时自动换行。

模型不负责字幕：HTML 里不出现字幕容器和字幕样式。渲染前 `sync_video.py` 会注入字幕层，按口播完整句子切分并锚到真实时间码。

要自己写字幕，把 SRT 放到项目下即可，优先级高于自动切句：

```text
HTML视频项目/项目名/字幕/手写字幕.srt     # 首选
HTML视频项目/项目名/字幕/最终字幕.srt     # 次选
```

SRT 里的文案和时间码会被原样使用，必要时按口播时长做等比校正；不再跑自动切句和 ASR。

## 检查策略（成片优先）

本地渲染链只在"渲染器跑不起来"时停下：缺 `#stage`、缺 `CAPTIONS_START/END`、没有 `window.__timelines`、没有 GSAP 动作、用了 `requestAnimationFrame`/`performance.now`。

其余检查（`check_html_contract.py`、`check_html_layout.mjs`、`check_motion_profile.py`、黑帧检测、Dify 里的 H02）全部只报告不拦截：版面重叠、垂直中心、动效密度、字幕规格偏差都会打印出来，但渲染照常进行。`render.sh` 在缺少 `data-render-mode` 时会按 `媒体/口播.mp3` 和有无 HeyGen 响应自动判断渲染模式。

## 动效不动、黑屏、音画不同步怎么查

什么时候读：成片出现前段全黑（只有字幕和声音）、后半段没有动效、页面切换和语音对不上。

### 先看渲染日志里的四个数

`sync_video.py` 每次同步会打印：

```text
scene_tags=8 caption_cues=8 scene_span=46.080 timeline_scale=0.9804
```

- `scene_tags`：识别到的真实页面数（已排除 `gA-scene` 这类包裹层）
- `caption_cues`：字幕句数，应与 `scene_tags` 相等
- `scene_span`：作者期时间轴跨度，应接近口播时长
- `timeline_scale`：作者期到真实时长的缩放，通常在 0.8–1.25；出现 5 倍这种数字说明跨度算错了

### 四种已知症状

| 症状 | 原因 | 修法 |
|---|---|---|
| 前段黑屏、页面跳得比语音慢 | scene 判定把 `class="gA-scene"` 包裹层当成页面，页面数虚高，时间被平均分掉 | 用 class token 精确匹配（`"scene"` 必须独立成词） |
| 时间轴被压缩或拉长 | 模型把每个 scene 的 `data-start` 都写成 0，跨度取 `max(start+duration)` 只有 9 秒 | 所有 start 相同时按 duration 求和 |
| 后段完全没动效 | 模型的 `at()` 是场景内相对时间，但 GSAP 只有一条全局时间线 | `scene-offset-runtime` 在 builder 执行时加上所属场景的 `data-start` |
| 动效写了但从不执行 | 选择器命中 0 个元素，常见是 `.gB [data-scene="s03"] …`——`data-scene` 就在 section 自己身上，加了前缀变成"找后代" | 运行时兜底改写成 `[data-scene="s03"] …` 再重试 |

### 怎么自助确认

- `check_html_layout.mjs` 的报告里有 `motion` 段：`total`（时间线动作数）、`byScene`（每个场景的动作数与起止时间）、`missingSelectors`（命中 0 个元素的选择器）。
- 04 的 Dify 输出里带 `motion_report_json`：每组的 `actions`、`unmatched`、`coverage`、`uncovered`。`unmatched` 非空就先修选择器，不要先调提示词。
- 浏览器里验证：console 执行 `Object.values(window.__timelines)[0].getChildren(true,true,false).length`，数量为 0 说明时间线没建起来。

## Dify 导入与文件名

```text
Dify工作流/04_黑帧口播_分组生成.yml     # 黑帧口播，当前默认
Dify工作流/01_有数字人完整视频工作流.yml  # 数字人版
Dify工作流/归档/                        # 02、03 已停用，只作历史备份
```

`04_黑帧口播_分组生成.yml` 是黑帧口播的默认版本：`H00` 把分镜切成四组，`H01S` 只出骨架，`H02A–D` 各组只写自己的场景和动效，`H03` 合并并输出 `motion_report_json`（每组动作数、未命中选择器、组件动效覆盖率）与 `merge_warnings_json`。动效验收先看这两个输出。

它不调用 HeyGen，也不生成任何数字人窗口、黑帧小窗或空白保留区。Dify 只生成 HTML 和最终口播文案，不生成音频；统一入口在本地默认使用 MiMo TTS 的 `mimo-v2.5-tts`，把口播文案生成 `媒体/口播.mp3`，再对齐字幕并渲染 MP4。也可以在统一入口后加 `--voice-file /path/to/voice.mp3`，使用已有音频替代 TTS。

无数字人视频（历史模式名 `black-frame`）的执行边界是：

```text
Dify（mimo-v2.6-pro）生成 HTML + voiceover_script
→ 本地 run_dify_output.sh
→ 本地 MiMo TTS（mimo-v2.5-tts）生成 媒体/口播.mp3
→ 本地按完整句子和真实转写时间码生成 字幕/
→ 以 `媒体/口播.mp3` 的真实时长为唯一主时钟，按 `data-sentence-ids`/`data-sentence-id` 把场景切换和字幕逐句锚到真实时间码，并校准 GSAP 相对动效
→ 本地 HyperFrames/FFmpeg 渲染 成片/最终视频.mp4
→ 标准化成片响度到约 -14.5 LUFS
→ 校验视频/音轨/口播/HTML 时长一致，且没有数字人窗口或黑帧占位
```

全合一 Workflow 需要配置：

```text
HEYGEN_API_KEY
HEYGEN_API_BASE=https://api.heygen.com
HEYGEN_AVATAR_ID
HEYGEN_VOICE_ID
```

两个 Workflow 的所有 LLM 节点默认使用 Xiaomi MiMo 官方插件的 `mimo-v2.6-pro`，在 Dify 的模型供应商中配置 Xiaomi MiMo API Key。

## 通用性与模板边界

- 输入层是通用的：可以填写不同品牌、产品、受众、场景、行业和创作要求。
- 事实与内容层完全按本次输入工作：可以输入另一个产品，也可以输入跑步、赚钱、成长、知识、经历或任意主题。每次运行只使用本次输入和 `用户输入事实与合规规则.md`，不加载任何固定品牌或产品故事。
- HTML 的画布和技术同步契约固定，但视觉主题、排版、栅格、字体、组件形态、颜色、动效和过场由模型根据每次内容自由设计，不使用固定 HTML 模板。
- 内容角度支持 `rotate`、`manual`、`random` 三种模式；`random` 只能从已审核主题池随机并记录 seed，不是任意随机。

## 以后修改 Workflow 或提示词

后续 AI 对话会自动读取根目录 `AGENTS.md`。修改 Dify Workflow、提示词、Code 节点、输出字段或渲染规则时，必须按该文件的同步表更新：

- Workflow YAML：实际运行版本。
- `保留资料/工作流提示词/`：提示词镜像。
- `保留资料/工作流代码节点/`：Code 节点镜像。
- `Dify工作流/使用说明.md`：输入、输出、容错和故障说明。
- `经验文档/使用说明.md`：本地命令、目录和人工操作。
- `保留资料/项目文档/视频需求与质量标准.md`：媒体、布局、字幕和质检规则。

不要只改 YAML 或只改文档。每次修改后按 `AGENTS.md` 的最低验证清单检查。
