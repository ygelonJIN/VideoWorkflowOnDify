# 通用 HTML 视频项目使用说明

- 适用：视频工作流
- 最后核对：2026-11-17
- 什么时候读：跑完整流程、导 Dify、重渲染、改配置、加新项目之前

## 当前方案

三种互相隔离的输出模式：

```text
仅 HTML：Dify 生成内容和 HTML → 浏览器预览
黑帧口播：Dify 生成 HTML + 口播文案 → MiMo TTS → 字幕、BGM、MP4
全合一：Dify 生成 HTML + HeyGen 数字人/口播 → 字幕、BGM、MP4
```

完整版里 HeyGen 只负责数字人表现和口播音轨，始终保留数字人小窗；无数字人版不调 HeyGen，默认 MiMo TTS。

- **画面由真实照片或纯文字排版承担**：`H01P` 逐屏决定 `role`（`band` / `inset` / `portrait` / `thumb` / `texture` / `html`，真值见根目录 `AGENTS.md`「口径」），本地 `generate_images.py` 只给有图的屏生成照片；`role=html` 是纯文字屏，靠字号、断行、留白撑住。整片至少一张真实照片。
- **HTML 只做文字和动效**，界面元素只能取编号组件，具象视觉归照片。组件与版面的完整规则见 `能力库/项目文档/视频需求与质量标准.md` §6。
- **字幕不归模型**：HTML 里不出现字幕容器和样式，渲染前由 `sync_video.py` 注入，规格与切句规则见 `能力库/项目文档/视频需求与质量标准.md` §8 和本文「字幕」节。
- 数字人小窗几何只在 `H01Z` 的 `--pip-*` 里写一次（尺寸、位置见 `视频需求与质量标准.md` §4），版面按它自动避让。
- 无数字人模式删掉小窗后必须回收原占位区域，顶部标签和标题回到正常左上栅格，不得继续向右避让。

## 输入怎么进去

`A00` 只有一个必填框 `主题、原始文本或随口一句话`。可以直接粘贴聊天记录、会议纪要、文章、语音转写、清单或零散笔记，不需要先自己总结：

```text
任意素材 → A01 提炼（主张 + 论点 + 证据）→ A04 论点排序 → A06 按论点写口播 → A07 检查 → A08 按论点分镜
```

- 提炼结果在 `brief.distill`，下游只能用它的主张和论点，不许按素材顺序复述。
- 不设配额：几个论点、每段几句、总共多少字、分几屏，全部由内容和模型自己判断。
- `A07` 只拦三件事：JSON 结构坏掉、没有完整句子、时间连接词成串（在按过程复述）。其余判断（照搬、漏讲、转述对话、字数句数）只写进 `copy_warnings_json` 和 `content_diagnostics`，供你回看，不阻塞、不强制改写。
- 素材长度不等于视频长度：写得长就成片长，没有目标时长。

## 目录结构

目录职责只有一份，在根目录 `AGENTS.md`，这里不复制。

只记一条运行时的落点：`workflow_runtime/` 是可复用运行资产，不是项目目录；每次生成的内容写入 `成品/项目名/`，不要写回运行时。能力层（卡、目录、样片、台账）在 `能力库/动效库/`，怎么生成见 `经验文档/能力层架构.md`。

## 推荐入口

两个 Dify Workflow 都使用同一条命令：

```bash
bash '/Volumes/TUF ESD-T1A Media/视频工作流/成品/workflow_runtime/tools/run_dify_output.sh' 你的项目名
```

命令会打开 TextEdit。把 Dify 完整输出粘贴到 TextEdit，不要粘贴到终端；内容完整后自动继续。

- 只有 `html_document`：生成 `成品/HTML预览/项目名.html`。
- 包含 `html_document` 和 `voiceover_script`：按已批准原文生成口播、同步字幕并生成 `成品/项目名/成片/最终视频.mp4`。
- 包含 `html_document` 和 `heygen_response_json`：下载媒体、同步字幕并生成 `成品/项目名/成片/最终视频.mp4`。

运行时产物都落在 `成品/Dify输出/`：

| 输入类型 | 保存的文件 |
|---|---|
| 任何 | `项目名-年月日-时分秒-dify-output.txt`（TextEdit 原文） |
| 黑帧口播 | `项目名-blackframe-input.json`、`项目名/html_document.html`、`项目名/voiceover_script.txt` |
| 全合一 | `项目名-unified-input.json`、`项目名/html_document.html`、`项目名/heygen_response.json` |

### 黑帧 TTS 可视化配置

不需要在命令里写 TTS 参数。导入 `04_黑帧口播_分组生成.yml` 后，在 Dify 的开始节点直接选择或填写：

| 配置项 | 可选项/默认值 |
|---|---|
| TTS 供应商 | `mimo`（默认）、`macos`、`openai-compatible` |
| TTS 模型名 | 填 `mimo-v2.5-tts`；留空也使用 `mimo-v2.5-tts` |
| TTS Base 地址 | `默认（按量付费）`、`Token Plan - 中国`、`Token Plan - 新加坡`、`Token Plan - 欧洲` |
| TTS 声音 | `mimo_default`（默认）、`冰糖`、`茉莉`、`苏打`、`白桦`、`Mia`、`Chloe`、`Milo`、`Dean` |

默认声音是 **`mimo_default`**，不是 `冰糖`。在 Dify 下拉框里直接点选音色即可；本地运行时不需要再写 `--tts-provider`、`--tts-model`、`--tts-voice` 或 Base 地址参数。

## 渲染器 CLI（HyperFrames）

什么时候读：报错“缺少 HyperFrames CLI”、换电脑、清理过 npm 缓存之后。

- CLI 钉在 `成品/workflow_runtime/vendor/node_modules/hyperframes`（当前 0.9.15），随硬盘走，不受 `/tmp` 重启和 `~/.npm` 被清影响。
- 查找顺序：`HYPERFRAMES_CLI` 环境变量 → 从当前目录向上最多 4 层的 `vendor/`（覆盖项目、`失败项目/子项目` 和 `workflow_runtime` 三种位置）→ `~/.npm/_npx` 缓存 → `command -v hyperframes`。
- Node 必须 22+；`render.sh` 先找 `/tmp/node22-runtime`，再取 `~/.nvm/versions/node` 里最高的版本，低于 22 直接报错。`sync_video.py` 用同一套规则。
- 不要在流水线里用 `npx hyperframes`：它装进 `~/.npm/_npx`，清一次缓存就整条链断掉，而报错文案又会把人往“装 Node”上带。
- 重装或升级：

```bash
cd "/Volumes/TUF ESD-T1A Media/视频工作流/成品/workflow_runtime/vendor"
PATH="$HOME/.nvm/versions/node/v22.23.3/bin:$PATH" npm i --no-audit --no-fund
```

`vendor/node_modules` 已被 `.gitignore` 的 `node_modules/` 挡住，不进仓库；`package.json` / `package-lock.json` 随仓库走，换机后 `npm i` 即可还原同一版本。

## 字幕（本地写）

### 样式

- 无底板：字幕只有文字本身，背景透明、无描边、无圆角、无内边距
- 文字：45px / 行高 1.35 / 字重 700 / 白色 / 水平居中 / 双层柔和黑色投影（`0 3px 12px` + `0 1px 4px`）
- 位置：中下方 `bottom:13%`，整体水平居中
- **尺寸自适应**：文字宽度跟着内容走（`width:auto`），最多占画布 80%（864px）；多行时自动换行。

模型不负责字幕：HTML 里不出现字幕容器和字幕样式。渲染前 `sync_video.py` 会注入字幕层，按口播完整句子切分并锚到真实时间码。

要自己写字幕，把 SRT 放到项目下即可，优先级高于自动切句：

```text
成品/项目名/字幕/手写字幕.srt     # 首选
成品/项目名/字幕/最终字幕.srt     # 次选
```

SRT 里的文案和时间码会被原样使用，必要时按口播时长做等比校正；不再跑自动切句和 ASR。

## 检查策略（结构由生成端保证，检查只诊断）

每一屏的 HTML 不再由模型自由书写：`H02S` 输出**规格 JSON**，`H02SK` 按固定模板渲染成唯一合法的 `<section>`。
标签闭合、属性齐全、背景/文字槽、作用域 CSS 都由代码保证，所以"截断/未闭合/丢属"这类问题在生成端就不会出现。

本地检查器（`check_html_contract.py`、`check_html_layout.mjs`、`check_html_timing.mjs`、`check_composition_variation.mjs`）只把结果写进项目的 `诊断/检查结果.txt`，**默认不拦渲染**；要旧行为跑 `STRICT_RENDER=1 bash render.sh`。真正会停止的只有环境问题：缺 Chrome、缺 Node 22、缺 HyperFrames CLI。

动效编号白名单在 2026-11-11 引入，2026-11-16 起由 `presets.json` 的 `role` 生成（见 `经验文档/能力层架构.md`）：`H02S` 的动效段只能从 `motion_budget` 的编号里选，`check_presets.py --html` 只报告。

## Dify 导入与文件名

导入哪份、装什么插件、输入输出字段、出错怎么对，统一写在 `Dify工作流/使用说明.md`，这里只记节点链（改提示词时用来对位置）：

```text
H00 分组与目录 → H01D 视觉定调 → H01P 图像计划 → H01PV 整理图像计划
→ H01C 组件语法 → H01X 全片编号分配 → H01XJ 注入编号
→ H01T 转场设计 → H01V 整理转场 → H01S 骨架
→ H02I 迭代（H02S 单屏规格 + 本屏动效 → H02SX 按编号展开 → H02SK 渲染 HTML 并合并）
→ H03 合并（拼回整片 + 按 `H01V` 切点表生成 `__pt` 调用）
```

`04_黑帧口播_分组生成.yml` 是默认版本（2026-11-10 起**逐屏生成**）：`H00` 出构图账本与逐屏载荷，`H01S` 出骨架，`H02I` 每轮把一屏喂给 `H02S`，它一次输出这一屏的规格和 `motions`（元素名、触发词、编号），`H02SX` 按编号在本机展开成 `<script>`，`H02SK` 把规格渲染成该屏 HTML 并与脚本合并，`H03` 拼回整片、去重、校正 `sentence_ids`，并按 `H01V` 的权威切点表直接生成 `__pt(...)`（转场脚本不再经过 LLM）——输出 `motion_report_json` / `merge_warnings_json`。动效验收先看这两个输出。`H02SX` 遇到不能落在常驻文字上的编号（`text_safe: false`）会换成同槽位替身卡并记 `skipped`；`H02SK` 发现脚本里的目标不是这一屏的元素时，会把它拉到本屏主文字上，并在 section 上写 `data-motion-skipped`，检查器把它报成"动效目标不在本屏"——这两条都在点名 `H02S` 该重跑。

旧的四组版（`H02A–D`）在 `Dify工作流/归档/04_黑帧口播_分组生成_分组版备份.yml`，导入报错时可退回。`01_有数字人` 现在是 04 + 右上角数字人小窗：链路、编号、逐屏生成全同 04，多一个 `H01Z` 写小窗、出口换 HeyGen；两边的差异清单见 `经验文档/能力层架构.md` §七。

它不调用 HeyGen，也不生成任何数字人窗口、黑帧小窗或空白保留区。Dify 只生成 HTML 和最终口播文案，不生成音频；统一入口在本地默认使用 MiMo TTS 的 `mimo-v2.5-tts`，把口播文案生成 `媒体/口播.mp3`，再对齐字幕并渲染 MP4。也可以在统一入口后加 `--voice-file /path/to/voice.mp3`，使用已有音频替代 TTS。

无数字人视频（历史模式名 `black-frame`）的执行边界是：

```text
Dify（任意 chat 模型）生成 HTML + voiceover_script
→ 本地 run_dify_output.sh
→ 本地 MiMo TTS（mimo-v2.5-tts）生成 媒体/口播.mp3
→ 本地按完整句子和真实转写时间码生成 字幕/
→ 以 `媒体/口播.mp3` 的真实时长为唯一主时钟，按 `data-sentence-ids`/`data-sentence-id` 把场景切换和字幕逐句锚到真实时间码，并校准 GSAP 相对动效
→ 本地 HyperFrames/FFmpeg 渲染 成片/最终视频.mp4
→ 标准化成片响度到约 -14.5 LUFS
→ 校验视频/音轨/口播/HTML 时长一致，且没有数字人窗口或黑帧占位
```

全合一 Workflow 需要配置：

```text
HEYGEN_API_KEY
HEYGEN_API_BASE=https://api.heygen.com
HEYGEN_AVATAR_ID
HEYGEN_VOICE_ID
```

两个 Workflow 的 LLM 节点只保留 `provider`/`name`/`mode` 和 `completion_params.max_tokens`；`temperature`、`top_p` 一律不写，采样交给模型插件默认值——写死采样参数会在换到推理类模型时直接 400。当前默认是 `opencode_go` 插件的 `gpt-6-luna`（最大输出 128000），`dependencies` 里声明了 `langgenius/opencode_go:0.5.2`；换模型时把各 LLM 节点的 `provider`/`name` 和 `dependencies` 一起换，任何 `llm: true` 的 chat 模型都能接。

## 通用性与模板边界

- 输入层是通用的：可以填写不同品牌、产品、受众、场景、行业和创作要求。
- 事实与内容层完全按本次输入工作：可以输入另一个产品，也可以输入跑步、赚钱、成长、知识、经历或任意主题。每次运行只使用本次输入和 `用户输入事实与合规规则.md`，不加载任何固定品牌或产品故事。
- HTML 的画布和技术同步契约固定，但视觉主题、排版、栅格、字体、组件形态、颜色、动效和过场由模型根据每次内容自由设计，不使用固定 HTML 模板。
- **2026-11-08 起，视觉的各环节拆成独立节点，一个都不许写死**（只改了 04）：节点链见本文上节「Dify 导入与文件名」，这里不重复。
  - 所有能力编号（背景卡、U 组件、入场/状态/组件动效）都由 `H01X` 看全片内容选，`H01XJ` 注入逐屏载荷并做兜底归一；`H00` 只发目录与白名单，不再按屏号轮转。页间转场是 15 张编号卡 `PT01–PT15`（`kind` 见 `sync_video.py` 的 `__ptList`）：`H01T` 逐切点选编号与时长，`H03` 按切点表生成 `window.__pt` 调用；动效只写屏内，页间交接归 `H03`。
  - 骨架不做视觉决策，只照抄 `art_direction_json.tokens`（2026-11-10 起只含颜色/字体栈/圆角/描边/缓动/时长，**不含字号和间距**），并把 `background_css` / `background_js` 原样拼进去。
  - 契约边界（这几条仍固定）：画布 1080×1920、`gsap.timeline({paused:true})` + `window.__sceneBuilders`、`[data-scene="sXX"]` 锚点、字幕由本地注入不归模型、禁止 `Math.random`/`rAF`/`setTimeout` 做时钟。
  - 本地不再给视觉兜模板：`scene-overlap`、背景层、场景底色这类写死的样式已从项目 HTML 撤掉，模型不产出就是没有。
  - 场景显隐页面自己管：主时间线里按 `data-start` / `data-duration` 切可见性；`sync_video.py` 另外注入 `scene-window-runtime`（`OVERLAP=0`）把显隐驱动挂到时间线本身，并在每次 seek 时驱动 `__gtTick` / `__ptTick`。两条驱动算出来的可见窗口一致，不要只留一条。
  - `H03` 合并对 `#s01` 这类锚点**无条件**改写成 `[data-scene="s01"]`（本地同步阶段会把 section id 改成 `scene-<id>`，留着 `#id` 必然失效）。
- 内容角度用 `rotate`（按已审核主题池轮换）或 `random`（从主题池随机并记 seed）；规则见 `能力库/项目文档/用户输入事实与合规规则.md`。
