# 通用 HTML 视频项目使用说明

- 适用：视频工作流
- 最后核对：2026-11-06
- 什么时候读：跑完整流程、导 Dify、重渲染、改配置、加新项目之前

## 当前方案

本项目支持三种互相隔离的输出模式：

```text
仅 HTML：Dify 生成内容和 HTML → 浏览器预览
黑帧口播：Dify 生成 HTML + 口播文案 → MiMo TTS 口播 → 字幕、BGM、MP4
全合一：Dify 生成 HTML + HeyGen 数字人/口播 → 字幕、BGM、MP4
```

完整版中 HeyGen 只负责数字人表现和口播音轨，并始终保留数字人小窗；无数字人版本不调用 HeyGen，默认使用 MiMo TTS 生成口播。**画面由真实照片或纯文字排版承担**（2026-11-10 起）：Dify 的 `H01P` 逐屏决定 `role`（`full` / `inset` / `portrait` / `texture` / `html`），本地 `generate_images.py` 只生成有图的屏到 `媒体/图片/`；`role=html` 的屏不生成照片，是**纯文字屏**，靠字号、断行、留白承担画面。整片至少保留一张真实照片。**HTML 只做文字和动效，不画任何图形**：不画图标、插画、示意图、数据图表，也不画线条、网格、刻度、进度条、色块、卡片、标签框。字幕、排版元素和元素级动效仍由 HTML/CSS/GSAP 制作。字幕固定为中下方 `bottom:13%`、宽度随文字自适应（上限 80%）、45px 字号、1.35 行高、700 字重、白色无底板文字（只用柔和投影保证亮背景可读）；图片状正文可用满整屏，字幕会盖在画面底部，不强制底部留白。无数字人模式删除小窗后必须回收原占位区域，顶部标签和标题回到正常左上栅格，不得继续向右避让。

## 输入怎么进去

`A00` 只有一个必填框 `主题、原始文本或随口一句话`。可以直接粘贴聊天记录、会议纪要、文章、语音转写、清单或零散笔记，不需要先自己总结：

```text
任意素材 → A01 提炼（主张 + 论点 + 证据）→ A04 论点排序 → A06 按论点写口播 → A07 检查 → A08 按论点分镜
```

- 提炼结果在 `brief.distill`，下游只能用它的主张和论点，不许按素材顺序复述。
- 不设配额：几个论点、每段几句、总共多少字、分几屏，全部由内容和模型自己判断。
- `A07` 只拦三件事：JSON 结构坏掉、没有完整句子、时间连接词成串（在按过程复述）。其余判断（照搬、漏讲、转述对话、字数句数）只写进 `copy_warnings_json` 和 `content_diagnostics`，供你回看，不阻塞、不强制改写。
- 素材长度不等于视频长度：写得长就成片长，没有目标时长。

## 渲染器 CLI（HyperFrames）

什么时候读：报错“缺少 HyperFrames CLI”、换电脑、清理过 npm 缓存之后。

- CLI 钉在 `成品/workflow_runtime/vendor/node_modules/hyperframes`（当前 0.9.15），随硬盘走，不受 `/tmp` 重启和 `~/.npm` 被清影响。
- 查找顺序：`HYPERFRAMES_CLI` 环境变量 → 从当前目录向上最多 4 层的 `vendor/`（覆盖项目、`失败项目/子项目` 和 `workflow_runtime` 三种位置）→ `~/.npm/_npx` 缓存 → `command -v hyperframes`。
- Node 必须 22+；`render.sh` 先找 `/tmp/node22-runtime`，再取 `~/.nvm/versions/node` 里最高的版本，低于 22 直接报错。`sync_video.py` 用同一套规则。
- 不要在流水线里用 `npx hyperframes`：它装进 `~/.npm/_npx`，清一次缓存就整条链断掉，而报错文案又会把人往“装 Node”上带。
- 重装或升级：

```bash
cd "/Volumes/TUF ESD-T1A Media/视频工作流/成品/workflow_runtime/vendor"
PATH="$HOME/.nvm/versions/node/v22.23.3/bin:$PATH" npm i --no-audit --no-fund
```

`vendor/node_modules` 已被 `.gitignore` 的 `node_modules/` 挡住，不进仓库；`package.json` / `package-lock.json` 随仓库走，换机后 `npm i` 即可还原同一版本。

## 字幕（本地写）

### 样式

- 无底板：字幕只有文字本身，背景透明、无描边、无圆角、无内边距
- 文字：45px / 行高 1.35 / 字重 700 / 白色 / 水平居中 / 双层柔和黑色投影（`0 3px 12px` + `0 1px 4px`）
- 位置：中下方 `bottom:13%`，整体水平居中
- **尺寸自适应**：文字宽度跟着内容走（`width:auto`），最多占画布 80%（864px）；多行时自动换行。

模型不负责字幕：HTML 里不出现字幕容器和字幕样式。渲染前 `sync_video.py` 会注入字幕层，按口播完整句子切分并锚到真实时间码。

要自己写字幕，把 SRT 放到项目下即可，优先级高于自动切句：

```text
成品/项目名/字幕/手写字幕.srt     # 首选
成品/项目名/字幕/最终字幕.srt     # 次选
```

SRT 里的文案和时间码会被原样使用，必要时按口播时长做等比校正；不再跑自动切句和 ASR。

## 检查策略（成片优先，结构残缺除外）

本地渲染链只在两类情况下停下：**渲染器跑不起来**（缺 `#stage`、缺 `CAPTIONS_START/END`、没有 `window.__timelines`、没有 GSAP 动作、用了 `requestAnimationFrame`/`performance.now`），以及**产物结构残缺**（缺 `</html>`、`<style>`/`<script>` 开闭不配对、标签里属性引号未闭合、有口播句子找不到对应场景）。

2026-11-11 起动效走编号白名单：`H02SM` 只能从 `能力库/动效库/能力卡.md` 的编号里选实现，`check_presets.py --html` 在渲染前核对 `kit.*` 调用和 `preset` 编号（只报告，不拦渲染）。计划侧的校验用 `check_presets.py --plan motion_plan.json`：编号不在白名单、相邻屏重复、preset 与 action 语义不符都会报。

结构残缺这一组是 2026-11-05 补的：当时一条 Dify 输出在 `data-anim="seat-bottom` 处被截断，8 个场景只剩 4 个、动效归零，旧规则只给 WARN，于是渲出了一条静帧片。现在 `check_html_contract.py` 判 FAIL 后 `render.sh` 直接停止，并提示"修 HTML 或重跑 Dify，不要硬渲"。

其余检查（`check_html_layout.mjs`、`check_composition_variation.mjs`、`check_motion_profile.py`、Dify 里的 H02）仍然只报告不拦截：版面重叠、垂直中心、构图重复、动效密度、字幕规格偏差都会打印出来，但渲染照常进行（渲染前的 `check_html_timing.mjs` 和渲染后的黑帧检测属于拦截项，见「空页、图片闪回与动作越界怎么查」）。构图检查默认只报告；要把它变成硬拦截时加 `STRICT_COMPOSITION=1`，相邻或首尾两屏是同一套骨架就会停下。`render.sh` 在缺少 `data-render-mode` 时会按 `媒体/口播.mp3` 和有无 HeyGen 响应自动判断渲染模式。

### 2026-11-06 新增的硬拦截

这几条会把渲染直接停掉（退出码 1），因为漏过去就是一条废片：

| 拦截项 | 症状 | 位置 |
|---|---|---|
| `scene` 缺 `data-scene` | 动效与场景判定错位 | `check_html_contract.py` |
| `scene` 缺 `data-sentence-ids` | 字幕无法对时 | `check_html_contract.py` |
| `canvas` 未写死 `width="1080" height="1920"` | 渲染时被缩到 338×600，画面糊 | `check_html_contract.py` |
| 用 `getBoundingClientRect()` 改 `canvas.width` | 同上，且元素错位 | `check_html_contract.py` |
| 内容出画布（`top < 0` 或 `bottom > 1920`） | 文字跑到画布外，看不出错位在哪里 | `check_html_layout.mjs` |
| 过半场景开场即空白 | 成片大面积空背景，观众以为视频坏了 | `check_html_layout.mjs` |
| 残留 `{{IMG:...}}` 占位 | 生图没跑或替换没执行，画面缺图 | `check_html_contract.py` |
| 某个 scene 没有 `媒体/图片/` 引用，也没有 `data-visual="html"` | 这一屏只剩未声明的文字和底色 | `check_html_contract.py` |
| 引用的图片文件不存在 | 占位替换成功但文件被删/没生成 | `check_html_contract.py` |
| 相邻或首尾两屏构图骨架相同（仅 `STRICT_COMPOSITION=1`） | 换的只是文案不是构图，整片看起来每页一样 | `check_composition_variation.mjs` |

排查顺序：先跑 `python3 脚本/check_html_contract.py index.html`，再跑 `脚本/check_html_layout.mjs index.html` 和 `脚本/check_composition_variation.mjs index.html`，都 PASS 再渲染。

## 真实图像（GPT Image API）

什么时候读：画面要出真实照片、图片没生成、想先看一张效果、改生图模型或尺寸时。

### 分工

```text
Dify H01P 图像计划（逐屏决定 role；有图的写英文 prompt + 尺寸 + 文字留白侧 + 镜头运动，无图的写 html_brief）
→ Dify H01PV 归一化（校验字段、补漏屏的 HTML 背景、拆出 image_brief_json）
→ 场景组按 role 落版：照片屏写 <img src="{{IMG:图片id}}">，无图屏写 data-visual="html" + data-anim="bg"
→ 本地 generate_images.py 只对有图屏调 GPT Image API → 媒体/图片/<id>.png
→ 构建时把 {{IMG:图片id}} 替换成 媒体/图片/<id>.png
→ 渲染
```

图片**不在 Dify 里生成**：Dify 的 HTTP 节点超时短、返回体积大（b64 单张 2–4MB）、失败重试没有状态，一条片 9–12 张必然撞限制。Dify 只出计划，执行放本地，能并发、能缓存、能只补一张。

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `IMAGE_API_KEY` / `OPENAI_API_KEY` / `ARK_API_KEY` | 无 | 必填；Key 不进项目文件、不进日志 |
| `IMAGE_API_BASE` | `https://api.openai.com/v1` | 兼容 OpenAI Images 协议的网关也可以；填火山方舟会自动切模式 |
| `IMAGE_MODEL` | 按 Base 自动选 | OpenAI 下是 `gpt-image-1`，火山下是 `doubao-seedream-4-0-250828` |
| `IMAGE_SIZE` | `1024x1536` | 竖屏满图；局部横图在计划里写 `1536x1024` |
| `IMAGE_QUALITY` | `medium` | `low` / `medium` / `high`，只对 OpenAI 生效 |

### 用即梦 / 火山方舟

即梦（Dreamina，`jimeng.jianying.com`）是字节的 C 端产品，**没有公开 API**，只能网页/App 手动出图。它背后的图像模型是 Seedream，对外通过**火山方舟**提供，接口是 OpenAI Images 兼容的：

```text
Base URL   https://ark.cn-beijing.volces.com/api/v3
接口        POST /images/generations
鉴权        Authorization: Bearer <ARK_API_KEY>
模型        doubao-seedream-4-0-250828（或 doubao-seedream-3-0-t2i-250415）
```

拿 Key 的路径：

1. 打开 <https://www.volcengine.com/product/ark>，注册并完成实名。
2. 进控制台 <https://console.volcengine.com/ark>，左侧「开通管理」里开通 Seedream 图片生成模型。
3. 左侧「API Key 管理」→ 创建 API Key，复制出来。
4. 配到终端：

```bash
export ARK_API_KEY=你的key
export IMAGE_API_BASE=https://ark.cn-beijing.volces.com/api/v3
```

脚本检测到 Base 里含 `volces.com` 就自动切火山模式：

- 不发 `quality` / `output_format`，改发 `response_format: "url"`，然后下载；
- **`watermark: false`**（火山默认加水印，不关的话每张图右下角有"AI生成"）；
- 尺寸自动映射：`1024x1536 → 832x1248`、`1536x1024 → 1248x832`、`1080x1920 → 720x1280`（Seedream 3.0 只认固定尺寸；4.0 也接受这些值）。
- 模型要在控制台**先开通**，没开通会返回 `InvalidEndpointOrModel` 或 404。

### 只有即梦网页版，没有 API

也能用：手动出图，按图片 id 命名丢进 `媒体/图片/`，然后跳过生图。

#### 对号规则（不改文件名）

图片**保持原名**，构建时只做映射：按修改时间从早到晚，最早那张算第一个有图屏，依次往下；`role=html` 的屏不生成图、也不占位。已经叫 `s01.png` 的文件优先按名字匹配。

想先看它打算怎么配：

```bash
cd "成品/项目名"
python3 脚本/ingest_images.py                      # 预览：哪张算 s01、缺哪张
python3 脚本/ingest_images.py --order name         # 按文件名里的数字排，不看时间
python3 脚本/ingest_images.py --from ~/Downloads   # 先把下载目录里的图搬进来（保持原名）
```

- 默认按**修改时间**排；一次性拖入导致时间被改，就用 `--order name`。
- 即梦下载名带时间戳（`jimeng-2026-11-08-1234.png`），`--order name` 通常最稳。
- 数量对不上会直接说「还缺 s07、s08」或列出多出来的文件，不会瞎配。
- 这个脚本只预览和搬文件，**不改名**；构建用的是同一套规则，所以预览看到什么就是出片用的什么。
- **先导出提示词包**，别一张张翻 JSON：

```bash

python3 脚本/generate_images.py --plan 媒体/图片计划.json --sheet
open 媒体/出图/          # 每张一份 txt + README
open 媒体/出图清单.html   # 同一批内容的网页版，点一下全选
```

生成两样东西：

### 版面上的事实

- 计划里竖图是 `1024x1536`（2:3），画布是 `1080x1920`（9:16），`object-fit: cover` 会裁掉左右约 16%。所以 prompt 必须要求主体留在中间安全宽度，文字留白侧写进 `text_safe_zone`。
- 图片里的文字一律不许出现：prompt 统一追加 no text / no logos / no UI。
- 人物按主题决定：生活、职场、消费、家庭类可以自然露脸；纪念、医疗、未成年人、隐私题材避免可识别正脸。不要摆拍看镜头，不要塑料 AI 脸。
- 一致性只靠 `prompt_prefix`：同一支片子的介质、光学、光、色彩、质感全部写在这一段里，逐字拼到每张前面。换风格就改这一段，不要逐张改。

### 旧项目重渲染会被拦

`check_html_contract.py` 要求每个 scene 要么有 `媒体/图片/` 引用，要么带 `data-visual="html"` 和 `data-anim="bg"`。2026-11-08 之前那种全 HTML 图形、没有照片也没有声明 HTML 背景的项目会 FAIL（`这些场景没有图片，也没有 data-visual="html"`）。无图屏是合法形态，但必须是设计过的背景，不能是纯色空白。

## canvas 与三维画面（Three.js）

什么时候读：要在一屏里放三维物体、WebGL 效果，或 canvas 绘制的光效与粒子时。

- `three.module.js` 放在 `workflow_runtime/assets/vendor/`（r169，单文件 1.3MB），构建时复制到项目的 `assets/`。
- `sync_video.py` 不再把所有脚本改写成 `assets/gsap.min.js`：`data-src="素材/vendor/x.js"` 按文件名映射成 `assets/x.js`。
- 页面画法（官方 seek 协议）：

```html
<canvas id="anim" style="position:absolute;inset:0"></canvas>
<script type="module">
import * as THREE from "./assets/three.module.js";
function renderAt(t){ /* 只依赖 t 计算 */ }
window.addEventListener('hf-seek', function(e){ renderAt(e.detail.time); });
renderAt(0);
</script>
```

- **不要用 GSAP 的 `onUpdate` 画 canvas**：渲染器 seek 时会抑制 GSAP 回调，画布永远是空的（2026-11-06 实测踩过，症状是画布 alpha 全 0）。
- 不要用 `requestAnimationFrame`/`setInterval` 当驱动；随机数用固定种子。
- `.scene` 外壳必须保留，字幕和时长同步靠它；canvas 只是 section 内部的图层。
- `check_html_contract.py` 对含 `hf-seek` 的页面跳过"动效选择器全部落空"门禁（canvas 场景本来没有 DOM 选择器）。
- 已验证：canvas 2D 与 WebGL 都能在本地渲染链路出片。

## Dify 跑完没有任何输出

什么时候读：工作流显示跑完，但结果区是空的、没有内容可复制。

2026-11-07 之前的原因是**代码节点直接抛异常**：Dify 遇到异常会中止整条流程，结束节点根本没执行，所以既没有输出，也不知道停在哪。

现在的行为：

- `A16` 打包失败（JSON 不合法、口播为空、A12 合规判 `rejected`）→ 返回 `approval_status=failed` + `package_error`，走 `A16_批准包门禁` 的 false 分支到「未完成诊断」；`needs_changes` 不拦，留人工改。
- `A07` / `A07R` 口播为空 → 返回 `copy_valid=false`，交给原门禁，不再抛异常。
- `H00` 分镜为空 → 返回空组和 `scene_total=0`，不中止。
- `H03` 合并出的 HTML 不完整 → 返回空 `html_document` 加告警，不中止。
- `A90_生成未完成诊断`（原模板节点，已换成代码节点）会把 A16 / A09 / A11 的具体错误拼成一段可复制的说明。

判断停在哪一步：

1. 先看结束节点输出里的「按下面列出的那一步去修」。
2. 仍为空，就在 Dify 运行记录里看哪个节点标红——那是唯一还没兜住的情况（模型节点报错）。
3. 本地入口会提示 `Dify 输出缺少完整 html_document`，说明上游确实没产出 HTML。

## 场景没被识别导致重复/不消失

什么时候读：片头内容叠在一起、页面之间不消失、整片像好几屏糊在同一时间。

- 原因：模型把场景写成 `class="clip gA gA-scene"`，`scene` 只是后缀。旧逻辑要求 `scene` 独立成词，这些 section 没被当成场景，`data-start` 一直是 0，于是所有这类场景从 0 秒起同时显示。
- 2026-11-07 已修：`sync_video.is_scene_tag()` 改为语义判定——class 有独立 `scene`，**或**是带 `data-sentence-ids` 的 `<section>`，都算场景。
- 症状消失的标志：同步日志 `scene_tags` 等于页面里 section 的实际数量，且相邻场景的 `start` 首尾相接。

## 整屏空白：内容被排到画布外

什么时候读：某一屏只剩背景和字幕，但 HTML 里明明有内容。

- 原因：模型用绝对定位把整块内容放到画布外面（实测 `top 2150`，画布只有 1920），元素存在但看不见。
- 2026-11-07 已加自动回正：只在**整屏内容完全在画布外**（`bottom <= 0` 或 `top >= 1920`）时整体 `translateY` 拉回。不要按安全区（`top < 200`、`bottom > 1620`）平移：满版背景和光晕让包围盒必然从 0 开始，会把每一屏都往下推 200px，表现为整段下移、顶部留空（当天实测 12 屏全部 `translateY(200px)`）。
- 注意：必须在场景可见时测量。启动时一次性测量会失败，因为其他场景还是 `display:none`，量出来是 0。
- 运行时脚本改成"先移除旧块再注入"，否则老项目永远用旧版本（踩过：改了脚本但项目里还是旧的）。

## 页面节奏与画面排期（口播片段锚定）

什么时候读：页面切换和语音对不上、一页太快/太慢、想改每屏停留时间。

- 2026-11-09 起，分镜不再按“一页几句”配额：模型自己决定页数和切点，但每屏必须写 `data-voiceover`，逐字等于这一页实际说到的那段原文。`H03` 从分镜的 `voiceover_text` 自动注入，模型不用手写。
- `align_scenes_to_caption_cues()` 用这段原文在真实词级时间码里找页面起点；页长 = 下一屏起点 − 本屏起点。不再按作者期时长在句子内部按比例切。
- 旧项目没有 `data-voiceover` 时仍走旧的句子组锚定 + 组内比例；新项目一律走新逻辑。
- 页面切换落在词首，句末停顿自然归到上一页；最后一页补到口播结束。
- 一页只有 2 秒却塞 4 个信息点，先修分镜，不要靠拉长/压缩动画。
- 实测：1501-rebuild 7 句 → 7 页，页长 5.4–8.4 秒，和每句真实时长一致；旧版 12 页是作者期 4.2–4.6 秒被等比缩放，页长和内容无关。

## 动效按真实词触发（window.__cue）

什么时候读：动效"和语音对不上"、动作总是挤在开头、或者要改 H02M 的时间写法。

- 动效节点（A10/H02SM）在 Dify 里运行时还没有 TTS，只能猜 `at(秒)`。同步阶段已经有真实时间码，`sync_video.py` 会在 `<head>` 注入 `<script id="cue-runtime">`：
  - `window.__cueLines`：全片字幕行（文字、绝对起点、时长、句子 id）；`__cue` **只在属于这一屏的句子里找**，不会再命中前一句同一个词后被压到 0.02 秒；
  - `window.__cueWords[scene]`：ASR 词级时间（只作兜底）；
  - `window.__cue(scene, 关键词, 默认秒)`：返回**作者期相对秒**（已除以 `data-timeline-scale`），交给 `at()` 后会还原成真实相对秒；
  - `window.__cueAbs(scene, 关键词, fallbackAbs)`：返回**绝对秒**，只给转场脚本用；
  - `window.__sceneStart(scene)`：这一屏的绝对起点。
- H02SM 的写法：`start_trigger` 是 `word:关键词` 的节拍，时间写 `at(cue('s04', '关键词', 1.2))`，并在 builder 里定义 `var cue = function(s, w, f){ return window.__cue ? window.__cue(s, w, f) : f; };`
- 注入是幂等的：重复 sync 不会叠加脚本。没有 transcript 时整段跳过，动效退回显式秒数。

## 排版门禁的致命判定

只有两类问题会停止渲染：

- **多数场景开场即空白**（≥ 一半场景在开场 0.4 秒没有可见元素）；
- **多数场景内容出画布**（≥ 一半场景的 `top < 0` 或 `bottom > 1920`）。

其余一律只告警、继续渲染：单个场景出画布、单屏文字与组件轻微重叠（例如「·」压到卡片 294px²）、垂直中心偏离、越出安全区。

判定逻辑在 `check_html_layout.mjs` 末尾，按错误文案匹配（`开场即空白` / `排到了画布外`）。加新规则时记得同步这里，否则新错误会被当成致命项把渲染拦掉。

## 成片复核工具（联系表、响度、音画对齐）

什么时候读：想整体看一遍镜头、怀疑响度不对、怀疑音效和画面不同步。

**渲染流程已内置这一步**：`render.sh` 在契约检查之后会生成 `成片/复核/联系表.jpg` 和 `成片/复核/音频报告.txt`，只报告不拦截。下面的命令用于单独重跑或换参数。

三个工具在 `成品/workflow_runtime/scripts/`；每个项目目录里的 `脚本/` 是它们的副本（新项目自动带上，老项目用 runtime 路径）。

```bash
cd "成品/workflow_runtime/scripts"

# 1) 联系表：每 2 秒取一帧，6 列，缩略宽 384，一次看完所有镜头
bash contact_sheet.sh "成品/纪念逝者/成片/最终视频.mp4" /tmp/sheet.jpg 2 6 384

# 2) 响度/真峰/削波/长静音/音视频时长是否一致
bash audio_check.sh "成品/纪念逝者/成片/最终视频.mp4" -14.5

# 3) 音效与事件时间是否对齐（需要一份事件 JSON）
python3 audio_sync_check.py 成片/最终视频.mp4 events.json --fps 30
```

- `contact_sheet.sh` 在没有 `drawtext` 滤镜的 ffmpeg 上会自动去掉时间戳，仍然出图。
- `audio_check.sh` 的目标值按本仓库标准传 `-14.5`；不传默认 `-14`。
- `normalize_final_audio.py` 走两遍 loudnorm（`linear=true`，实测 -14.08 LUFS / -1.46 dBTP）。单遍动态模式会过冲真峰（实测目标 -1.5 却跑出 +0.2 dBTP），`render.sh` 的响度关卡会直接判失败。
- `audio_sync_check.py` 要求事件 JSON：`[{"t": 1.20, "name": "click"}, ...]`，偏差超过 1 帧即判失败。
- `sound_kit.py` 是程序化音效素材库（纯 numpy），需要补音效时直接在脚本里 import。
- 另有 `capture_seek.mjs`：给暴露了 `window.seek(t)` 的页面用的逐帧抓取路径，主线渲染不走它。

画面与声音的工艺参考在 `能力库/画面工艺/`，遇到具体创作问题按目录索引查。

## Dify 输出超限：整组画面消失

什么时候读：契约检查报"有 N 句口播没有对应场景"、`<style>` 开闭不配对，或成片里某几屏完全没出现。

### 先认症状

| 症状 | 含义 |
|---|---|
| 合并后 `<section class="scene">` 数量少于分镜场景数 | 有几组只写了 CSS，没写到结构就被切了 |
| `<style>` 开/闭数量不等（如 5 开 2 闭） | 断在样式中间，后面所有标记被当成样式文本吞掉，页面看起来"全没了" |
| CSS 占 HTML 一半以上 | 正常应明显低于一半；过半说明结构没写出来 |
| `motion JSON` 报 `Unterminated string starting at char X`，X 接近总长 | 真截断（不是中文引号 bug，那个报 `Expecting ',' delimiter` 且位置在中间） |

### 原因

`H01S` 和 `H02A–D` 每个节点都要吐一整套设计系统 CSS + 场景结构 + GSAP 脚本，单组 6–8KB。2026-11-06 调大上限之前，模型默认最大输出装不下，组就在写完 CSS 后被切断。断在 CSS 里是最坏形态：样式没有闭合标签，后面的 `<section>` 全变成样式文本，本地只能看到残留的 1–2 个场景。

### 处理

1. **调大最大输出**。2026-11-06 已把每个 LLM 节点的最大输出设成 **128000**，并写进 YAML 的 `completion_params.max_tokens`，导入时一起生效，不用再手工重设；换模型时先确认新模型接受这个字段。
2. 仍建议把 `H02` 的输出顺序改成**先 `<section>` 后 `<style>`**：真被截断时至少画面结构还在，只是难看，不会整页消失。
3. 把公共 CSS 挪进 `H01S` 骨架，`H02` 只写本组特有样式，输出量能砍一半。
4. 判断修没修好只看一条：**合并后 section 数 = 分镜场景数**。CSS 好不好看是后话。

调大上限只是把断点往后推，不改变"每组越写越长"的趋势；真的再撞上，按 2、3 收窄输出。

## 渲染失败后怎么定位和续跑

什么时候读：本地命令报错、契约检查 FAIL、成片没生成。

### 三步定位

1. **确认跑的是新输出**：看 `成品/Dify输出/项目名-年月日-时分秒-dify-output.txt` 的时间戳。拿旧 JSON 重跑只会得到同一个坏结果，白跑一轮。
2. **看契约检查的 reason**：`缺哪些句口播没有场景` 说明丢组；`<style> 开闭不配对` 说明断在 CSS；`没有任何 GSAP 动作` 说明组脚本没写出来。
3. **到原始 TXT 里找断点**：搜 `<style` 和最后一个 `<section`，能看出断在第几组。

### 续跑

失败时项目会被整体移到 `成品/失败项目/项目名-时间戳/`，`媒体/口播.mp3`、`媒体/背景音乐.mp3`、`字幕/` 都还在。**移回 `成品/项目名/` 后直接在项目目录跑 `bash render.sh`**，不用重新 TTS、不用重跑 Dify。

只有一条别做：不要为了出片去改 `check_html_contract.py` 放行残缺产物——那正是它该拦的东西。

## 动效不动、黑屏、音画不同步怎么查

什么时候读：成片出现前段全黑（只有字幕和声音）、后半段没有动效、页面切换和语音对不上。

### 先看渲染日志里的四个数

`sync_video.py` 每次同步会打印：

```text
scene_tags=8 caption_cues=8 scene_span=46.080 timeline_scale=0.9804
```

- `scene_tags`：识别到的真实页面数（已排除 `gA-scene` 这类包裹层）
- `caption_cues`：字幕句数，应与 `scene_tags` 相等
- `scene_span`：作者期时间轴跨度，应接近口播时长
- `timeline_scale`：作者期到真实时长的缩放，通常在 0.8–1.25；出现 5 倍这种数字说明跨度算错了

### 五种已知症状

| 症状 | 原因 | 修法 |
|---|---|---|
| 日志出现"分镜/动效 JSON 被截断"，动作全被归一到 `s01` | Code 节点先把中文引号 “” 替换成 ASCII 引号再 `json.loads`；文案里一带引号，合法 JSON 就被自己的替换弄坏 | 2026-11-05 已修：先按原文解析，失败才退到替换版；`01`/`04` 的 YAML 和镜像都改了，需要在 Dify 里重新导入 |

### 文字动效同质化怎么查

2026-11-09 起，H02M 不提供文字入场样式清单，每屏由模型按内容设计，只约束结果：相邻两屏不能一眼相同，全片不同做法不少于 min(4, 屏数)，且禁止把 `opacity 0.55~0.65 → 1` 或"浅灰变强调色"当入场。

回看时先看 H02M 脚本顶部那张逐屏文字方案表：如果每行写的理由都差不多，或者代码里每屏都是 `fromTo(... {opacity: 0.6, y: 30} ...)`，就是又退回模板了，重跑 H02M。

2026-11-09 起本地有 `check_motion_variation.mjs`：从真实 GSAP 时间线里逐屏抽“文字动作组合 / 图片动作组合”，相邻同签名、全片文字组合少于 4 种、图片运动少于 3 种会告警。`render.sh` 渲染前会跑一次（只报告，不阻塞）：

```bash
node 脚本/check_motion_variation.mjs index.html
```

它按组件 + 属性族统计，能看出“每页都是同一种擦除+位移”，但仍不能判断审美；最终还要人眼过一遍联系表。`check_motion_profile.py --html` 只能看整屏变化量，别拿它当文字动效的验收。

### 怎么自助确认

- `check_html_layout.mjs` 的报告里有 `motion` 段：`total`（时间线动作数）、`byScene`（每个场景的动作数与起止时间）、`missingSelectors`（命中 0 个元素的选择器）。

## 空页、图片闪回与动作越界怎么查

什么时候读：成片有整屏只剩字幕、图片出现后闪一下、动作跑到别的页上。

- `check_html_timing.mjs`（渲染前，`render.sh` 默认执行，失败会拦）：2026-11-12 起改成**逐帧（1/30）** seek，检查每屏在自己窗口内是否可见、每个 `data-anim` 内容层是否**有且只有一次入场**（首帧即最终态 = 没有入场，会拦）、是否出现 `1 → 0 → 1` 闪回、背景层是否第 1 帧就在、动作是否越界被夹到屏尾。原来的 0.2 秒抽样漏掉过 1 帧级的闪回（31.27s 实测），不要再改回抽样。
- 两个运行时违规（`window.__motionViolations`，同一份门禁会读）：动作位置越界被夹到屏尾；转场脚本在进入屏起点写透明度/缩放/遮罩（转场只许动离场屏）。
- `detect_blank_frames.py`（渲染后）只判**真正的孤立单帧**（比紧邻前后两帧都暗、且两帧都亮），多帧暗段和淡入淡出不算。`repair_blank_frames.py` 直接复用它的判据，改判据只改 detect 一处。
- 典型症状与原因：
  - 整屏只有字幕：scene 的 `opacity` 被写成 0，或显隐驱动没在 seek 时更新。`__hfRenderState` 现在会调用页面的 `window.__updateScenes(time)`；页面自己的驱动要把这个函数挂出来。
  - 图片出现后消失 0.3 秒：转场淡入写的是 `cue()` 相对秒，却被运行时加了目标场景起点，落在屏尾；起止位置必须用绝对秒。
  - 图片四周露一圈：给 `.photo` 容器做了 `scale`，同时用同尺寸遮板盖住；容器放大后从遮板四周露边。缩放图片本体（`img`），不要缩放容器。
- 转场脚本必须写绝对秒：builder 第一行 `timeline.__absolutePositions = true`，用 `__sceneStart` / `__cueAbs`。不要把 `__cue()` 直接当位置，也不要用代理对象 + CSS 变量写 scene 的 `opacity`。
- 动效差异用 `check_motion_variation.mjs`（渲染前，只报告）：逐屏列出文字/图片动作组合，相邻同签名、全片种类不足会告警；它只看真实 GSAP 时间线，不替代人眼判断。

## 页面只剩 0.1 秒、后面的动效全错拍怎么查

什么时候读：成片第一屏一闪而过、某一屏完全不动、动效比语音晚好几秒。

- 症状与原因：`sync_video.py` 给每屏定位起点时，会用「词级时间码」拼一条全片字符轴，按字符位置取真实起点。这条轴用的是 ASR 文本，字幕用的是口播文案；两次识别不是同一次时（繁体、同音错字、重跑过 ASR），字符位置会对不上，页面起点被甩到别的句子上，个别屏被夹到 `0.12` 秒。
- 更糟的是连锁反应：`data-start` 错了，`window.__cueWindows` 跟着错，`cue('s02','关键词')` 算出来的相对秒就落到这屏的尾部，动作全部堆在片尾或被夹掉——看起来就是「这一屏根本没动」。
- 2026-11-10 已修：① 只有字幕文本和识别文本覆盖率 ≥85% 且字符数一致时才用字符轴，否则在句内插值；② 页面从某句开头讲（命中位置 0）时，起点直接取那句的真实起点，不走字符轴；③ 页面被压到 0.5 秒以下会打印 `scene_too_short=...`。
- 排查：先看 `sync_video.py` 输出里有没有 `char_axis=disabled`、`scene_too_short=`；再核对 `index.html` 里每屏 `data-start` 是否等于它 `data-sentence-ids` 那句在 `字幕/口播时间码.json` 里的 `start`。对不上就重跑 `sync_video.py`，不要手改 `data-start`。

## 没有真实时间码时（ASR 失败 / 首次模型下载）

什么时候读：同步阶段报「本地 ASR 不可用」，或者新项目第一次渲染卡在字幕/时间码。

- `sync_video.py` 会先试两次本地 ASR；两次都失败时，如果项目有 `口播文案.txt`，会按完整句子和字数比例把音频时长分配给字幕和页面，并写 `字幕/估算说明.txt`。
- 这只是应急：页面切点和动效 cue 只能近似。修好 ASR 或提供 `字幕/口播时间码.json` 后重跑 `sync_video.py`，就会按真实词级时间码精确对齐。
- ASR 偶发失败最常见的原因是第一次跑要下载 whisper 模型、网络中断或缓存锁；重跑一次通常就好。手动验证：
  ```bash
  node "$HYPERFRAMES_CLI" transcribe 媒体/口播.mp3 --model small --language zh --json --to srt --output 字幕/口播.srt
  ```
- 不要在没有时间码时直接删 `字幕/` 硬渲；先看 `字幕/估算说明.txt` 是否存在。

什么时候读：渲染在 `Checking browser...` 后直接失败，提示 `This account cannot write to /Users/.../.cache/hyperframes/locks`。

## Dify 导入与文件名

`04_黑帧口播_分组生成.yml` 是黑帧口播的默认版本（2026-11-10 起改为**逐屏生成**）：`H00` 只做构图账本归一化和逐屏载荷（`scene_payloads`），`H01S` 出设计系统和骨架，`H02I` 迭代节点每轮把一屏喂给 `H02S`（一屏一次调用，只看得到自己这一屏 + 全片构图账本），同一轮里 `H02SM` 只输出这一屏的动效判断 JSON（编号+target+时间，不写代码），`H02SX` 按编号在本机展开成 `<script>`，`H02SK` 把该屏 HTML 与脚本合并，`H02J` 按分镜顺序把逐屏结果拼回一个字符串，`H03` 先按分镜去重、丢弃越界 scene 并校正 `sentence_ids`，再合并并输出 `motion_report_json` 与 `merge_warnings_json`。动效验收先看这两个输出。 旧的四组版（`H02A–D`）留在 `Dify工作流/归档/04_黑帧口播_分组生成_分组版备份.yml`，导入报错时可以退回。01 数字人版仍是旧结构，未迁移。

它不调用 HeyGen，也不生成任何数字人窗口、黑帧小窗或空白保留区。Dify 只生成 HTML 和最终口播文案，不生成音频；统一入口在本地默认使用 MiMo TTS 的 `mimo-v2.5-tts`，把口播文案生成 `媒体/口播.mp3`，再对齐字幕并渲染 MP4。也可以在统一入口后加 `--voice-file /path/to/voice.mp3`，使用已有音频替代 TTS。

无数字人视频（历史模式名 `black-frame`）的执行边界是：

```text

→ 标准化成片响度到约 -14.5 LUFS
→ 校验视频/音轨/口播/HTML 时长一致，且没有数字人窗口或黑帧占位
```

## 通用性与模板边界

- 输入层是通用的：可以填写不同品牌、产品、受众、场景、行业和创作要求。
- 事实与内容层完全按本次输入工作：可以输入另一个产品，也可以输入跑步、赚钱、成长、知识、经历或任意主题。每次运行只使用本次输入和 `用户输入事实与合规规则.md`，不加载任何固定品牌或产品故事。
- HTML 的画布和技术同步契约固定，但视觉主题、排版、栅格、字体、组件形态、颜色、动效和过场由模型根据每次内容自由设计，不使用固定 HTML 模板。
- **2026-11-08 起，视觉的各环节拆成独立节点，一个都不许写死**（只改了 04）：
  `H01D 视觉定调 → H01C 组件语法 → H01T 转场设计 → H01V 整理转场 → H01G 背景系统 → H01W 拆背景 → H01S 骨架 → H02I 迭代（H02S 单屏场景 → H02SM 动效判断 → H02SX 按编号展开 → H02SK 合并）→ H02J 拼接 → H02T 转场脚本 → H03 合并`。
  - 转场没有固定类型菜单，由 H01T 逐切点设计，H02T 实现；背景没有固定层数和技术选型，由 H01G 按隐喻决定；动效只写屏内，页间交接归 H02T。
  - 骨架不做视觉决策，只照抄 `art_direction_json.tokens`（2026-11-10 起只含颜色/字体栈/圆角/描边/缓动/时长，**不含字号和间距**），并把 `background_css` / `background_js` 原样拼进去。
  - 契约边界（这几条仍固定）：画布 1080×1920、`gsap.timeline({paused:true})` + `window.__sceneBuilders`、`[data-scene="sXX"]` 锚点、字幕由本地注入不归模型、禁止 `Math.random`/`rAF`/`setTimeout` 做时钟。
  - 本地不再给视觉兜模板：`scene-overlap`、背景层、场景底色这类写死的样式已从项目 HTML 撤掉，模型不产出就是没有。
  - 场景显隐也交还给页面：`sync_video.py` 不再注入 `scene-window-runtime`（并会清掉历史残留），页面必须在主时间线里按 `data-start` / `data-duration` 自己切可见性；`check_html_contract.py` 与 `H02` 校验把它列为拦截项。
