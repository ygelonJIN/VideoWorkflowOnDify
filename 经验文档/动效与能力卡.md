# 动效与能力卡

## 什么时候读

- 要新增/删除/修改一张动效卡、组件卡或背景卡之前
- 改了 `presets.json`、`motion-kit.js`、`bg-kit.js`、`components.css`、`auto-fit.js` 之后
- 成片动效不对、卡片"没生效"、渲染出来是黑的或静止的时候
- 要把新卡接进 Dify 工作流之前

---

## 一、加一张卡：先出样片，再入表

**2026-11-13 起的前置条件**：任何新卡先做成 8–12 秒样片（1080×1920，真合成，不是格子里的近似），给用户看完点头，才允许写进 `presets.json`。
没样片的卡不入表——编号一旦进提示词，模型就会开始选它。

样片门槛定的原因：08b–11b 那批卡是"照着描述加的"，实际到了成片里，一半的参数范围是拍的。

### 三步（缺一步等于没加）

`能力库/动效库/presets.json` 是唯一源，其他地方都是从它派生的。

1. **改 `presets.json`**
   - 必填：`id` `name` `family` `layer` `status` `cap` `params` `use` `avoid` `code`
   - `status` 只有 `ready` 会进管线；不确定的写 `needs-work`，废弃的写 `skip`
   - `code` 里的选择器占位用 `{{sel}}`，时间用 `{{at}}`，参数用 `{{名字}}`
2. **跑 `sync_expander.py`**
   把 ready 卡写进 Dify 的 H02SX 展开器（`TPL` / `DEFAULTS` 两块是生成的，**不要手改 YAML**）
3. **出一张卡的样片**
   `bash 能力库/动效库/render_card.sh <编号>`：生成工程 + 渲染 3 秒 + 落到 `样片/全卡审阅/<族>/`，约 7 秒。
   **加卡只出这一张**，不重渲其它卡；批量重出才用 `make_review_reels.py` + `渲染清单.tsv`。

校验命令：

```bash
python3 能力库/动效库/sync_expander.py --check   # 不一致就退出 1
```

### 卡的参数必须自洽

- `code` 里出现的每个 `{{x}}`，都要能在该卡的 `params` 里找到同名默认值，否则展开时 `KeyError` 被静默跳过。
- 参数名统一用 `dur`（不要 `duration`）——`sync_expander` 的 `DEFAULTS` 只认 `dur`。
- 需要第二个目标的卡（如 L01 视差）用 `sel2`；展开器会兜底成 `sel`，但那样两层同速，等于没视差。

## 二、运行时契约

| 层 | 挂在哪 | 例子 |
|---|---|---|
| `camera` | 整屏取景 | C01 |
| `media` | 照片/图块 | C03、D01 |
| `layer` | 中间层 | L01 |
| `element` | 单个元素/组件 | K01、UA07 |
| `overlay` | 覆盖层 | M01、G01 |

- 字幕层在相机之外，**永远不跟着镜头动**。
- 全部动效由 GSAP 时间线驱动，浏览器逐帧 seek；禁止 `requestAnimationFrame`、`performance.now`、`Math.random`。
- 需要"随机"的用 `kit.seeded(种子)` 或 `kit.noise2(x,y,seed)`。

## 三、踩过的坑（每一条都烧过时间）

### 1. 空目标 tween 不触发 onUpdate

`timeline.to({}, { duration: 6, onUpdate: fn })` 在 seek 时**不会渲染**，`fn` 不执行。
`bg-kit.bind` 早期就是这么写的，导致 canvas 背景可能只在第 0 帧画过一次。

正确写法：给一个有真实属性的对象。

```js
var drv = { v: 0 };
timeline.to(drv, { v: 1, duration: D, ease: 'none', onUpdate: paint }, 0);
```

### 2. `hf-seek` 派发在 window，不在 document

渲染器用 `window.dispatchEvent(new CustomEvent('hf-seek', {detail:{time}}))`。
监听挂 `document` 收不到。一律 `window.addEventListener('hf-seek', ...)`。

### 3. `mix-blend-mode` 会出黑块

在这个渲染器里，带 `mix-blend-mode` 的元素会把下方区域拍成纯黑（浅底视频最明显）。
文字/边框换色不要用它；需要压色就用固定色或半透明叠加。

### 4. 浅底视频必须 `--workers 1`

多 worker 渲染时，每个 worker 的视口高度可能比画布短约 90px，**画面底部会出现一条黑边**。
深色片子看不出来，浅底（纸面/白底）一眼就穿。渲染命令加 `--workers 1`。

同类问题：这台机器上还要显式指定浏览器，否则 HyperFrames 会去下载 Chrome 并卡在锁上：

```bash
export HYPERFRAMES_BROWSER_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

### 5. 选择器必须按场景作用域

卡片的 `sel` 如果是 `.h`、`.uiwrap` 这种全局类名，只会命中**第一个**场景的同名元素；
后面的 `fromTo` 带 `immediateRender`，会在 t=0 就把那个元素钉成 from 状态，导致前面的场景永远不出现。

正确做法：调用方把选择器补成 `#s03 .h`，或在展开器里统一加 `[data-scene="s03"]` 前缀。

### 6. 组件"整块淡入"而不是逐条

组件根下面如果只有一层包裹，`> *` 只命中一个元素，stagger 没东西可错开。
组件有 2 个以上同级子项时，用 `UA07` 并给 `child`（`.b` / `.p` / `tr` / `.t`），不要用 `UA01`。

### 7. 手动渲染少一个开关，DOM 合成必挂

`render.sh` 里那串参数不是可选的：

```bash
hyperframes render . --quality delivery --no-browser-gpu --experimental-fast-capture=false
```

手动跑（比如渲样张）时漏了 `--experimental-fast-capture=false`，没有 WebGL canvas 的合成会被切到 `drawelement` 捕获，直接报
`DrawElementImage requires the canvas to have the content=drawable attribute`，一帧都出不来。带 WebGL 的合成因为走 GPU 反而会绕开这条路，所以三维片能渲、纯 DOM 片不能渲，很容易误判成"HTML 写坏了"。

### 8. 两个同步工具会互相覆盖 H02SX

- `workflow_runtime/tools/sync_prompts_to_yaml.py` 用 `能力库/工作流代码节点/expand_motion_plan.py` **整段覆盖** YAML 里的 H02SX 代码；
- `能力库/动效库/sync_expander.py` 只把 `TPL` / `DEFAULTS` 两块拼进去。

所以改完提示词跑完前者，`TPL` 会被打回镜像里的旧版本（实测从 99 张掉到 19 张，新增的卡全丢）。
**顺序固定**：`sync_prompts_to_yaml.py` → `sync_expander.py` → `sync_expander.py --check`。交付前用 `--check` 把关。

### 9. 指针类不能写死坐标

I02 第一版把落点写成 `(700,596)`、`(300,880)`、`(250,1090)`，面板布局一挪，三处全点空——
而且**静止帧上看不出来**，只有跟着时间轴看才发现。

正确做法：建表时量一次目标元素的中心，指针用 `x/y` 位移过去。

```js
const r = el.getBoundingClientRect();
const dx = (r.left + r.width / 2) - (ptrRect.left + 6);   // 6 = 箭头尖的偏移
```

场景是 `display:none` 时量到的是 0：临时 `display:block; visibility:hidden` 量完再还原。
I01 卡已经按这个实现，`data-pointer-to` 只在确实要指空白处时才写。

## 四、样张怎么验证

每张卡都要有自己的一支 3 秒片子，放在 `能力库/动效库/样片/全卡审阅/<族>/<编号>-<名字>.mp4`。
验证三件事：

1. **画面有内容**：抽帧后用像素统计看非黑占比，别只看缩略图（缩略图会骗人）。
2. **动效在跑**：相邻帧的差分均值（`tblend` + `signalstats`）不为 0；成片对比参考片，中位数不能是 0。
3. **首帧是空的**：t=0 抽帧应该是纯背景，任何元素都不该"本来就在"。

渲染完删掉 `.hf`、`.hyperframes` 缓存和中间的 `out.mp4`，只留 `示范NN-*.mp4`。

### 10. 项目里的 `脚本/` 是快照，改 runtime 不生效

每个项目目录下有自己的一份 `脚本/`（render.sh 里调的是 `脚本/check_html_contract.py` 等）。
改了 `成品/workflow_runtime/scripts/` 里的检查器，**老项目不会跟着变**，重跑还是旧规则。

修法：改完 runtime 后同步到项目，或重跑时手工覆盖：

```bash
for f in check_html_contract.py check_html_timing.mjs check_composition_variation.mjs check_motion_variation.mjs sync_video.py; do
  cp "成品/workflow_runtime/scripts/$f" "成品/<项目>/脚本/$f"
done
```

2026-11-13 踩到：放宽了契约，重跑仍 FAIL，因为项目里那份还是 17:23 的快照。

### 11. `kit.split` 会把容器里的空白节点拆成 span，撑爆版面

症状：一屏三行 `ui-row` 之间出现 400px 级的大空白，字号看起来变小，整屏像散了。

实测（2026-11-13，s04）：

```
goals 高度 1461px，三行 at 868 / 1289 / 1710（每行只有 86px）
goals 的直接子节点：SPAN.kit-char ×7 … DIV.ui-row … SPAN.kit-char ×7 …
```

原因：逐字卡（T09 等）被指到了**容器**上，`split` 遍历 childNodes 时把行与行之间的**缩进空白文本节点**也拆成了 `kit-char`（`display:inline-block`，每个约 44px 宽），于是行被空白 span 顶开。

修法（`motion-kit.js` 两处）：

```js
// 1) 纯空白文本节点跳过
if (!text || !text.replace(/\s/g, '')) return;
// 2) 目标是复合容器时，单子元素下探，多子元素跳过并记 __splitWarnings
```

**同时注意每个项目有两份 motion-kit**：`assets/motion-kit.js` 和 `素材/vendor/motion-kit.js`，页面实际加载的是前者（`<script src="assets/...">`）。只改一份不会生效。
