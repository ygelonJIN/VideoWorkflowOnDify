# 动效与能力卡

## 什么时候读

- 要新增/删除/修改一张动效卡、组件卡或背景卡之前
- 改了 `presets.json`、`motion-kit.js`、`bg-kit.js`、`components.css`、`auto-fit.js` 之后
- 成片动效不对、卡片"没生效"、渲染出来是黑的或静止的时候
- 要把新卡接进 Dify 工作流之前

---

## 一、加一张卡：三步，缺一步等于没加

`保留资料/动效库/presets.json` 是唯一源，其他地方都是从它派生的。

1. **改 `presets.json`**
   - 必填：`id` `name` `family` `layer` `status` `cap` `params` `use` `avoid` `code`
   - `status` 只有 `ready` 会进管线；不确定的写 `needs-work`，废弃的写 `skip`
   - `code` 里的选择器占位用 `{{sel}}`，时间用 `{{at}}`，参数用 `{{名字}}`
2. **跑 `sync_expander.py`**
   把 ready 卡写进 Dify 的 H02SX 展开器（`TPL` / `DEFAULTS` 两块是生成的，**不要手改 YAML**）
3. **跑 `build_presets.py --demo <目录>` 出样张**
   样张页用同一份 `code` 展开，能渲出来才算做完

校验命令：

```bash
python3 保留资料/动效库/sync_expander.py --check   # 不一致就退出 1
```

### 卡的参数必须自洽

- `code` 里出现的每个 `{{x}}`，都要能在该卡的 `params` 里找到同名默认值，否则展开时 `KeyError` 被静默跳过。
- 参数名统一用 `dur`（不要 `duration`）——`sync_expander` 的 `DEFAULTS` 只认 `dur`。
- 需要第二个目标的卡（如 L01 视差）用 `sel2`；展开器会兜底成 `sel`，但那样两层同速，等于没视差。

## 二、运行时契约

| 层 | 挂在哪 | 例子 |
|---|---|---|
| `camera` | 整屏取景 | C01 |
| `media` | 照片/图块 | C03、D01 |
| `layer` | 中间层 | L01 |
| `element` | 单个元素/组件 | K01、UA07 |
| `overlay` | 覆盖层 | M01、G01 |

- 字幕层在相机之外，**永远不跟着镜头动**。
- 全部动效由 GSAP 时间线驱动，浏览器逐帧 seek；禁止 `requestAnimationFrame`、`performance.now`、`Math.random`。
- 需要"随机"的用 `kit.seeded(种子)` 或 `kit.noise2(x,y,seed)`。

## 三、踩过的坑（每一条都烧过时间）

### 1. 空目标 tween 不触发 onUpdate

`timeline.to({}, { duration: 6, onUpdate: fn })` 在 seek 时**不会渲染**，`fn` 不执行。
`bg-kit.bind` 早期就是这么写的，导致 canvas 背景可能只在第 0 帧画过一次。

正确写法：给一个有真实属性的对象。

```js
var drv = { v: 0 };
timeline.to(drv, { v: 1, duration: D, ease: 'none', onUpdate: paint }, 0);
```

### 2. `hf-seek` 派发在 window，不在 document

渲染器用 `window.dispatchEvent(new CustomEvent('hf-seek', {detail:{time}}))`。
监听挂 `document` 收不到。一律 `window.addEventListener('hf-seek', ...)`。

### 3. `mix-blend-mode` 会出黑块

在这个渲染器里，带 `mix-blend-mode` 的元素会把下方区域拍成纯黑（浅底视频最明显）。
文字/边框换色不要用它；需要压色就用固定色或半透明叠加。

### 4. 浅底视频必须 `--workers 1`

多 worker 渲染时，每个 worker 的视口高度可能比画布短约 90px，**画面底部会出现一条黑边**。
深色片子看不出来，浅底（纸面/白底）一眼就穿。渲染命令加 `--workers 1`。

同类问题：这台机器上还要显式指定浏览器，否则 HyperFrames 会去下载 Chrome 并卡在锁上：

```bash
export HYPERFRAMES_BROWSER_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

### 5. 选择器必须按场景作用域

卡片的 `sel` 如果是 `.h`、`.uiwrap` 这种全局类名，只会命中**第一个**场景的同名元素；
后面的 `fromTo` 带 `immediateRender`，会在 t=0 就把那个元素钉成 from 状态，导致前面的场景永远不出现。

正确做法：调用方把选择器补成 `#s03 .h`，或在展开器里统一加 `[data-scene="s03"]` 前缀。

### 6. 组件"整块淡入"而不是逐条

组件根下面如果只有一层包裹，`> *` 只命中一个元素，stagger 没东西可错开。
组件有 2 个以上同级子项时，用 `UA07` 并给 `child`（`.b` / `.p` / `tr` / `.t`），不要用 `UA01`。

## 四、样张怎么验证

每个能力批次都要出一支 1.5–2 秒/项的样张，放在 `HTML视频项目/示范-镜头与排版/`。
验证三件事：

1. **画面有内容**：抽帧后用像素统计看非黑占比，别只看缩略图（缩略图会骗人）。
2. **动效在跑**：相邻帧的差分均值（`tblend` + `signalstats`）不为 0；成片对比参考片，中位数不能是 0。
3. **首帧是空的**：t=0 抽帧应该是纯背景，任何元素都不该"本来就在"。

渲染完删掉 `.hf`、`.hyperframes` 缓存和中间的 `out.mp4`，只留 `示范NN-*.mp4`。
