# 动效与能力卡

## 什么时候读

- 要新增/删除/修改一张动效卡、组件卡或背景卡之前
- 改了 `presets.json`、`motion-kit.js`、`bg-kit.js`、`components.css`、`auto-fit.js` 之后
- 成片动效不对、卡片"没生效"、渲染出来是黑的或静止的时候
- 要把新卡接进 Dify 工作流之前
- **搬一批外部动效进来（筛完样片、准备入表）之前——直接跳到「一批卡入表：全链改动清单」，那节是默认全做**
- 新增 WebGL / shader 类卡（照片、遮罩、转场）之前——见同节「WebGL / shader 卡」

---

## 一、加一张卡：先出样片，再入表

**2026-11-13 起的前置条件**：任何新卡先做成 8–12 秒样片（1080×1920，真合成，不是格子里的近似），给用户看完点头，才允许写进 `presets.json`。
没样片的卡不入表——编号一旦进提示词，模型就会开始选它。

样片门槛定的原因：08b–11b 那批卡是"照着描述加的"，实际到了成片里，一半的参数范围是拍的。

### 三步（缺一步等于没加）

`能力库/动效库/presets.json` 是唯一源，其他地方都是从它派生的。

1. **改 `presets.json`**
   - 必填：`id` `name` `family` `layer` `status` `cap` `params` `use` `avoid` `code`
   - `status` 只有 `ready` 会进管线；不确定的写 `needs-work`，废弃的写 `skip`
   - `code` 里的选择器占位用 `{{sel}}`，时间用 `{{at}}`，参数用 `{{名字}}`
2. **跑同步链，顺序不能反**
   ```bash
   cd 成品/workflow_runtime/tools && python3 sync_prompts_to_yaml.py   # 提示词镜像 → YAML
   cd - && python3 能力库/动效库/sync_expander.py                       # TPL/DEFAULTS → YAML
   python3 能力库/动效库/sync_expander.py --check                       # 不一致就退出 1
   ```
   `sync_expander.py` 把 ready 卡写进 Dify 的 H02SX 展开器（`TPL` / `DEFAULTS` 两块是生成的，**不要手改 YAML**）。
3. **出一张卡的样片**
   `bash 能力库/动效库/render_card.sh <编号>`：生成工程 + 渲染 3 秒 + 落到 `样片/全卡审阅/<族>/`，约 7 秒。
   **加卡只出这一张**，不重渲其它卡；批量重出才用 `make_review_reels.py` + `渲染清单.tsv`。

删一张卡：`python3 能力库/动效库/remove_card.py <编号> [--dry-run]`——一条命令走完 presets、能力卡、同步链，
并删掉该卡的样片与 `源/<族>/<编号>/`。**编号删后永久留空，不复用**（进过提示词的编号复用会让旧记录对不上），
删完把那几个编号追加到 `已有能力一览.md` 的"做过又删了"清单。

### 卡的参数必须自洽

- `code` 里出现的每个 `{{x}}`，都要能在该卡的 `params` 里找到同名默认值，否则展开时 `KeyError` 被静默跳过。
- 参数名统一用 `dur`（不要 `duration`）——`sync_expander` 的 `DEFAULTS` 只认 `dur`。
- 需要第二个目标的卡（如 L01 视差）用 `sel2`；展开器会兜底成 `sel`，但那样两层同速，等于没视差。

### WebGL / shader 卡（2026-11-14 起）

照片、遮罩、转场这类画面元素允许用 WebGL——`W11–W20`（`kit.deform`）从 2026-11-13 起就是这条路，
`--no-browser-gpu` 下走软件 WebGL，1080×1920/30fps 与 DOM 卡同量级。加这类卡多三件事：

1. **vendor 两份文件**：`assets/vendor/gltrans-kit.js`（运行时）+ `gl-transitions.glsl.js`（生成的数据）。
   数据文件由 `能力库/动效库/build_gltrans.py` 从上游仓库生成，**不手改**；改渲染逻辑只改运行时。
   `sync_video.py` 两份都要注入，且顺序是运行时在前。
2. **卡的写法统一**：`glt.mount(照片元素, 'ShaderName', {from:'#0a0b0b', params})`，进度只由时间线给。
   `from` 是底色 → 读起来是"照片从暗场里长出来"，不用第二张照片。
3. **`p0`/`p1` 有效区间**：直接线性扫 0→1 时，多数 shader 的画面变化只落在中段（量出来常在 0.2–0.8）。
   卡上给 `p0`/`p1` 两个参数（默认 0/1 直通），样片用"前 10% 快进到 p0、中间 80% 走完、最后 10% 收到 1"
   的三段映射把变化铺满整段，否则成片是"前 1.5 秒动完、后面静帧"。

样板工程与全库审阅批：

```bash
# 确认片（每张卡 3 秒）在 样片/全卡审阅/<族>/
bash 能力库/动效库/render_card.sh GT24
# 外部素材进件走一次渲：build → render → keep/drop
python3 能力库/动效库/intake.py build --src ~/Downloads/gl-transitions-master
```

## 二、运行时契约

| 层 | 挂在哪 | 例子 |
|---|---|---|
| `camera` | 整屏取景 | C01 |
| `media` | 照片/图块 | C03、D01 |
| `layer` | 中间层 | L01 |
| `element` | 单个元素/组件 | K01、UA07 |
| `overlay` | 覆盖层 | M01、G01 |

- 字幕层在相机之外，**永远不跟着镜头动**。
- 全部动效由 GSAP 时间线驱动，浏览器逐帧 seek；禁止 `requestAnimationFrame`、`performance.now`、`Math.random`。
- 需要"随机"的用 `kit.seeded(种子)` 或 `kit.noise2(x,y,seed)`。

## 三、踩过的坑（每一条都烧过时间）

### 1. 空目标 tween 不触发 onUpdate

`timeline.to({}, { duration: 6, onUpdate: fn })` 在 seek 时**不会渲染**，`fn` 不执行。
`bg-kit.bind` 早期就是这么写的，导致 canvas 背景可能只在第 0 帧画过一次。

正确写法：给一个有真实属性的对象。

```js
var drv = { v: 0 };
timeline.to(drv, { v: 1, duration: D, ease: 'none', onUpdate: paint }, 0);
```

### 2. `hf-seek` 派发在 window，不在 document

渲染器用 `window.dispatchEvent(new CustomEvent('hf-seek', {detail:{time}}))`。
监听挂 `document` 收不到。一律 `window.addEventListener('hf-seek', ...)`。

### 3. `mix-blend-mode` 会出黑块

在这个渲染器里，带 `mix-blend-mode` 的元素会把下方区域拍成纯黑（浅底视频最明显）。
文字/边框换色不要用它；需要压色就用固定色或半透明叠加。

### 4. 浅底视频必须 `--workers 1`

多 worker 渲染时，每个 worker 的视口高度可能比画布短约 90px，**画面底部会出现一条黑边**。
深色片子看不出来，浅底（纸面/白底）一眼就穿。渲染命令加 `--workers 1`。

同类问题：这台机器上还要显式指定浏览器，否则 HyperFrames 会去下载 Chrome 并卡在锁上：

```bash
export HYPERFRAMES_BROWSER_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

### 5. 选择器必须按场景作用域

卡片的 `sel` 如果是 `.h`、`.uiwrap` 这种全局类名，只会命中**第一个**场景的同名元素；
后面的 `fromTo` 带 `immediateRender`，会在 t=0 就把那个元素钉成 from 状态，导致前面的场景永远不出现。

正确做法：调用方把选择器补成 `#s03 .h`，或在展开器里统一加 `[data-scene="s03"]` 前缀。

### 6. 组件"整块淡入"而不是逐条

组件根下面如果只有一层包裹，`> *` 只命中一个元素，stagger 没东西可错开。
组件有 2 个以上同级子项时，用 `UA07` 并给 `child`（`.b` / `.p` / `tr` / `.t`），不要用 `UA01`。

### 7. 手动渲染少一个开关，DOM 合成必挂

`render.sh` 里那串参数不是可选的：

```bash
hyperframes render . --quality delivery --no-browser-gpu --experimental-fast-capture=false
```

手动跑（比如渲样张）时漏了 `--experimental-fast-capture=false`，没有 WebGL canvas 的合成会被切到 `drawelement` 捕获，直接报
`DrawElementImage requires the canvas to have the content=drawable attribute`，一帧都出不来。带 WebGL 的合成因为走 GPU 反而会绕开这条路，所以三维片能渲、纯 DOM 片不能渲，很容易误判成"HTML 写坏了"。

### 8. 两个同步工具会互相覆盖 H02SX

- `workflow_runtime/tools/sync_prompts_to_yaml.py` 用 `能力库/工作流代码节点/expand_motion_plan.py` **整段覆盖** YAML 里的 H02SX 代码；
- `能力库/动效库/sync_expander.py` 只把 `TPL` / `DEFAULTS` 两块拼进去。

所以改完提示词跑完前者，`TPL` 会被打回镜像里的旧版本（实测从 99 张掉到 19 张，新增的卡全丢）。
**顺序固定**：`sync_prompts_to_yaml.py` → `sync_expander.py` → `sync_expander.py --check`。交付前用 `--check` 把关。

### 9. 指针类不能写死坐标

I02 第一版把落点写成 `(700,596)`、`(300,880)`、`(250,1090)`，面板布局一挪，三处全点空——
而且**静止帧上看不出来**，只有跟着时间轴看才发现。

正确做法：建表时量一次目标元素的中心，指针用 `x/y` 位移过去。

```js
const r = el.getBoundingClientRect();
const dx = (r.left + r.width / 2) - (ptrRect.left + 6);   // 6 = 箭头尖的偏移
```

场景是 `display:none` 时量到的是 0：临时 `display:block; visibility:hidden` 量完再还原。
I01 卡已经按这个实现，`data-pointer-to` 只在确实要指空白处时才写。

## 四、样张怎么验证

每张卡都要有自己的一支 3 秒片子，放在 `能力库/动效库/样片/全卡审阅/<族>/<编号>-<名字>.mp4`。
验证三件事：

1. **画面有内容**：抽帧后用像素统计看非黑占比，别只看缩略图（缩略图会骗人）。
2. **动效在跑**：相邻帧的差分均值（`tblend` + `signalstats`）不为 0；成片对比参考片，中位数不能是 0。
3. **首帧是空的**：t=0 抽帧应该是纯背景，任何元素都不该"本来就在"。

渲染完删掉 `.hf`、`.hyperframes` 缓存和中间的 `out.mp4`，只留 `示范NN-*.mp4`。

卡的数量、族分布一律以 `presets.json` 现算，**不要抄文档里的数字**——抄下来三天就错。

`--experimental-fast-capture=false` **不能省**：省掉会走 `drawElement` 捕获，纯 DOM 合成直接失败。

- `-w 1` 同下文「浅底视频」那条坑。
- 超过 ~20 秒的合成另有性能问题，长片拆段再 `ffmpeg concat`。

### 11. `kit.split` 会把容器里的空白节点拆成 span，撑爆版面

症状：一屏三行 `ui-row` 之间出现 400px 级的大空白，字号看起来变小，整屏像散了。

实测（2026-11-13，s04）：

```
goals 高度 1461px，三行 at 868 / 1289 / 1710（每行只有 86px）
goals 的直接子节点：SPAN.kit-char ×7 … DIV.ui-row … SPAN.kit-char ×7 …
```

原因：逐字卡（T09 等）被指到了**容器**上，`split` 遍历 childNodes 时把行与行之间的**缩进空白文本节点**也拆成了 `kit-char`（`display:inline-block`，每个约 44px 宽），于是行被空白 span 顶开。

修法（`motion-kit.js` 两处）：

```js
// 1) 纯空白文本节点跳过
if (!text || !text.replace(/\s/g, '')) return;
// 2) 目标是复合容器时，单子元素下探，多子元素跳过并记 __splitWarnings
```

**同时注意每个项目有两份 motion-kit**：`assets/motion-kit.js` 和 `素材/vendor/motion-kit.js`，页面实际加载的是前者（`<script src="assets/...">`）。只改一份不会生效。

### 12. `<img>` 不能有子节点：照片类卡把 canvas 挂到父级

W11–W18 第一版 `_el.appendChild(canvas)`，目标又是 `<img>`——子节点被忽略，画面等于没变，静止帧上看不出任何异常。
正确写法：`var _host = _el.tagName === 'IMG' ? _el.parentNode : _el;`，canvas 按 `getBoundingClientRect` 的差值定位到 `_host` 里。

### 13. `z-index:-1` 会被压到场景背景后面

U21 圆角底板第一版把底板 `z-index:-1` 挂在文字下面，结果底板画到了场景背景之后，整屏只剩深色文字——看起来像"卡没生效"。
负 z-index 只在最近的**层叠上下文**里有效；场景没有 `z-index`/`transform`，所以直接沉到最底。
正确写法：底板挂到父级、`z-index:0`，被垫的文字 `position:relative; z-index:1`。

### 14. `sync_prompts_to_yaml.py` 会把 TPL/DEFAULTS 整段剥掉

它只写人手维护的部分（`strip_generated`），写完 YAML 里就没有 `    TPL = {` 了，
紧接着跑 `sync_expander.py` 会 `ValueError: substring not found`。
`sync_expander.py` 现在会退回镜像文件 `能力库/工作流代码节点/expand_motion_plan.py` 当底稿，并在写回 YAML 时同步回写镜像。
顺序仍然固定：`sync_prompts_to_yaml.py` → `sync_expander.py` → `sync_expander.py --check`。

### 15. 背景编号判定要跟着加卡放宽

`expand_motion_plan.py` 里 `visual_budget.background` 的正则原本只认 `B08–B21`，
B23 以后（含新增 B37–B39）只有当模型把它写进 `motions` 才会建 canvas。
已改成 `B(0[8-9]|[1-9][0-9])`，B08–B99 都认。

## GSAP 插件（2026-11-13 起随运行时注入）

vendor 升级到 **GSAP 3.15.1**，插件放在 `assets/vendor/gsap-plugins/`（24 个 `.min.js`，含以前要付费的那些）。
`sync_video.py` 的 `ensure_runtime_scripts()` 会把**12 个视频可用的**自动注入到 `<head>`，
项目组装时 `cp -R assets 素材` 会连子目录一起带过去，所以 HTML 里不用手写这些 `<script>`。

注入的 12 个：SplitText、DrawSVGPlugin、MorphSVGPlugin、MotionPathPlugin、EasePack、
CustomEase、CustomBounce、CustomWiggle、Physics2DPlugin、ScrambleTextPlugin、TextPlugin、Flip。

**没注入**（视频里没意义）：ScrollTrigger、ScrollSmoother、ScrollTo、Observer、Draggable、Inertia、
PixiPlugin、EaselPlugin、CSSRulePlugin、GSDevTools、MotionPathHelper、`all.js`。
`all.js` 不要引——它把 ScrollTrigger 那一坨全打进来。

### 各插件的正确写法（都能 seek）

| 插件 | 写法 | 注意 |
|---|---|---|
| SplitText | `new SplitText('#t', {type:'lines', mask:'lines'})` → `tl.from(sp.lines, {...})` | 拆一次就够，不要每帧拆 |
| DrawSVG | `tl.fromTo(p, {drawSVG:'0% 18%'}, {drawSVG:'82% 100%'})` | 支持只画中段 |
| MorphSVG | `tl.to(shape, {morphSVG:'#target'})` | 两条 path 顶点数差太多会自动加锚点 |
| MotionPath | `tl.to(el, {motionPath:{path:'#p', autoRotate:true, start:.35, end:.75}})` | `align` 要用同一条 path |
| RoughEase | `RoughEase({strength:2.2, points:22, taper:'both', randomize:false})` | `randomize:true` 会破坏可复现，别开 |
| CustomEase | `CustomEase.create('name', 'M0,0 C0.6,0 0.2,1.4 1,1')` | 路径是 0–1 的归一化坐标 |
| CustomBounce | `CustomBounce.create('drop', {strength:.65, squash:2})` → `ease:'drop'` + `ease:'drop-squash'` | **必须先加载 CustomEase** |
| CustomWiggle | `CustomWiggle.create('shake', {wiggles:6, type:'easeOut'})` | 同上，依赖 CustomEase |
| Physics2D | `tl.to(el, {duration:2, physics2D:{velocity:420, angle:-62, gravity:900}})` | **不要加 friction**，见下 |
| ScrambleText | `tl.to(el, {scrambleText:{text:'…', chars:'01AB', revealDelay:.2}})` | 乱码内容是随机的，同帧不可复现 |
| TextPlugin | `tl.to(el, {text:{value:'多行\n字符串'}})` | 换行写在 value 里 |
| Flip | `var st=Flip.getState(sel); /* 改布局 */ var f=Flip.from(st,{duration:1.4}); f.pause(0); tl.to(drv,{p:1,onUpdate:function(){f.progress(drv.p)}})` | 不能 `paused:true`，要 `pause(0)` + progress 驱动 |

### 坑

1. **CustomBounce / CustomWiggle 必须先加载 CustomEase**：缺了它 `_bonusValidated` 为 false，
   页面报 `j is not a function` 之类，整段脚本中断，画面完全静止（静止帧看不出错）。
2. **Physics2D 带 `friction` 会破坏 seek**：无摩擦走闭式公式 `x = s + v·t + a·t²/2`，可复现；
   有摩擦走的是按 `data.step` 递增的离散积分，seek 每次从头来，位置永远停在第 0 步。
   样片实测：带 friction 画面 0% 变化，去掉立刻动。
3. **Flip 的 `paused:true` 不生效**：它自己按真实时钟跑，要在 `Flip.from()` 之后立刻 `pause(0)`，
   再由主时间线的 `progress()` 推进。
4. **ScrambleText 的乱码字符是随机的**：单次渲染没问题（帧是顺序渲的），但同一帧两次 seek 结果不同，
   要求逐帧可复现的镜头别用，或改用手搓的 T07/T08。

### 17. WebGL 方法抽出来单独调用 → `Illegal invocation`（2026-11-14）

```js
var fn = gl['uniform3fv'];  // ✗ 拿到的是无主函数
fn(loc, arr);               // → TypeError: Illegal invocation，整段脚本中断，画面静帧

gl['uniform3fv'](loc, arr); // ✓ 必须带着上下文调
```

表现极具欺骗性：页面不报红、DOM 文字也正常，只有 canvas 不画——第一次遇到会误判成"WebGL 不可用"。
写通用 uniform 派发（`uniformNf`/`uniformNi`/`uniformMatrixNfv`）时最容易踩。

#### 68 张 GT 怎么不把管线撑爆（2026-11-14）

一次性入表 68 张 shader 转场，体量上有三个必须做的取舍，别省：

1. **提示词按组写，不按张写**。三份提示词里每条 GT 都要有编号+名字（否则模型选不到），但按
   形状/块格/三维/光效/材质/图形/照片 七组分段，一段一行，别铺成 68 行表格再加一份。
2. **vendor 按需注入**。`gl-transitions.glsl.js` 743KB，`sync_video.py` 只在 HTML 里出现
   `glt.mount(` 时才注入运行时与数据；没用 shader 的片子一点不背。
3. **一屏一张 + 不与 C01 同屏**。204 张表里最容易被滥用的就是转场，规则写进质量标准和三份提示词，
   不要只写在能力卡里。

展开器侧：`TPL` 从 68KB 涨到 144KB（188 张卡），YAML 从 333KB 涨到 394KB，Dify 导入仍正常；
再加同类批量卡之前先量一次这两个数。

#### 外部效果进件：一次渲，筛完就地转正（2026-11-14）

以前是两遍：先用"试播规格"渲全量给用户筛，选中后再用卡规格渲一遍确认（225 + 68 = 293 张）。
