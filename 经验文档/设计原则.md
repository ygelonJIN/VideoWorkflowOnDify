# 设计原则（改工作流之前先读这一页）

## 什么时候读

- 要改任何一层（提示词、Code 节点、卡、检查器、渲染脚本）之前；
- 想"加个校验、不过就停"的时候；
- 想出"缺了就补一个默认值/换一张卡/编一段文案"的时候；
- 有人报"这条片子某处不对"，你要决定是改片子还是改流程的时候。

---

## 一、目标是"稳定产出正确的片子"，不是"发现错误"

三条不能混：

| 做法 | 性质 | 结论 |
|---|---|---|
| 生成端一次就把结果做对 | **正确** | 要这个 |
| 发现问题 → 拦住、报失败、不出片 | 转移责任 | 不要 |
| 发现问题 → 渲完再改 HTML / 补默认值 | 掩盖问题 | 不要 |

怎么判定"改完了"见 §3.1。

## 二、不兜底：缺什么就暴露什么，让上游重做

兜底看起来"保证出片"，实际是把错误变成静默的默认值，片子看着完整、内容是错的。

| 不要做 | 要做 |
|---|---|
| 口播不合格 → 拿论点拼一段 | 退回重写（`S1R`），提示词要求严格 JSON |
| 合规 rejected → 软化措辞继续打包 | 退回 `S1R`，把 `s1_errors_json` 当重写原因灌回去 |
| 分镜为空 → 按口播切屏 | 报"`S1` 必须先产出 scenes"，退回 `S1` 重做 |
| 缺屏 → 合成一屏 | 回 `S2` 重出；屏数与分镜对不上就是不合格，骨架不替它补屏 |
| 编号选错 → 换同角色卡 | `S2N` 丢弃并点名"编号不在目录，重跑 `S2`" |
| 转场漏刀 → 每屏的可选字段，漏了就静默硬切 | `R3` 按权威切点表（相邻两屏）逐刀生成，**N 屏必出 N-1 条 `__pt`**；模型只给 kind 偏好，缺的那刀按本片转场族补齐并点名重跑 `S2` |
| 屏内先后 → 靠模型逐条挑节拍 | `R1` 按 `role` 定槽位顺序、`__slot` 按真实屏长铺开：有余量按等间隔、末位收在切点前 1.5s；挤不下才退回按收尾等距 |
| 规格缺字段 → 编标题/正文 | 只渲染模型给的内容；缺就是缺，回 `S2` 重出 |

**唯一例外是结构**：标签闭合、属性齐全、槽位不缺由固定模板保证——那是**生成器**，不是兜底；生成器不替模型做内容判断，只保证"模型交什么都能装进一个合法页面"。边界见 §3.3。

## 三、治本口径：不校验、不拦截、不兜底

> 本仓库最硬的一条。任何一次"某处不对"的修改，先按这一节判定是不是治本，再动手。

### 3.1 一句话判断

**改完之后，同样的输入再跑一遍，还会不会出同样的错？**

会 → 你改的是这一条片子，不算改完；不会 → 改的是流程，这才算。

### 3.2 三步：先归层，再改生成器，最后才谈诊断

1. **归层**：症状落在哪一层——定义（`presets.json`）／选择（`S2`+`S2N`）／展开（`R1`）／落版（`R2`）／
   合并（`R3`）／同步（`sync_video`）／渲染（HyperFrames）／内容（`S1`）。归错层，后面的修法一定错。
2. **改生成器**：让那一层**从一开始就产不出这个坏结果**——补结构保证、改输入契约、改卡的判据、
   改按真实时长算的公式。宁可让上游重做，也不在下游补。
3. **诊断只做记录**：修不掉的才写进 `诊断/检查结果.txt`，并且必须点名"该重跑哪个节点"。

### 3.3 六类"看起来修好了"的替代品（一律禁止）

| 想做的 | 为什么不算治本 |
|---|---|
| 新增一条校验，不达标 `exit 1` | 片子直接消失，问题原样留在上游；换一条内容又出 |
| 加 `STRICT_*` 开关、"渲染前拦一道" | 同上，只是把失败藏进开关；日常跑的还是坏产物 |
| 渲完再改 HTML / 临时补一段脚本 | 掩盖问题，且改动不进生成端，下次生成照样坏 |
| 缺字段就用默认值或模板顶替 | 把错误变成静默的"看着完整、内容是错的" |
| 编号选错就换一张同角色的卡 | 替模型做了内容判断，错误从此不可见 |
| 靠人肉复查放行 | 不可重复，也不留下一次 |

**允许的写法只有四种**：判据写进定义层（`presets.json` 的 `role`/`text_safe`/`cap`）、
写进提示词的输入与契约、写进固定模板（生成器）、写进按真实时长/真实数据算的运行时。
**凡是"发现 → 拦住／补齐／换掉／放行"的，都在这六类里。**

### 3.4 唯一的例外：环境

缺 Chrome／缺 Node／缺 HyperFrames／缺输入音频——这些不是内容问题，允许硬失败，也允许 `exit 1`。
判断法：**换一条内容，这个失败还在不在。** 还在 → 环境；不在 → 内容，回去走 3.2。

内容检查（契约/排版/时间线/构图）默认只写 `诊断/检查结果.txt`，不阻塞渲染；
`STRICT_RENDER=1` 只是排查开关，不是日常行为。

### 3.5 诊断的合法出口

诊断可以新加，但只能做两件事：**记录**和**点名**。

- 允许：`R1` 的 `skipped` 记原编号；`R3` 的 warning 写"S2 有 N 刀没给有效 pt，要换风格请重跑 S2"。
- 禁止：诊断里"自动补齐""自动换卡""自动放行""自动改结果"。
- 一条 warning 写完要能回答：**谁该重跑，重跑之后这一条会不会消失。** 答不上就是噪声。

### 3.6 什么时候可以加门槛

只有两种：环境前置（缺 Chrome 直接说清楚），和**已经改完生成端之后**保留的回归探针。
后者也必须默认只报告；要拦，只在专门排查时临时开 `STRICT_*`，不得进日常链路。

## 四、结构问题在生成端消灭，不在渲染前修

- 模型不写整屏 HTML：`S2` 出规格 JSON，`R2` 用模板渲染；
- 文案是纯文本，渲染时转义；
- 组件片段先过标签平衡检查，不平衡就丢弃并记 warning；
- `css` 只接受本屏作用域选择器；
- 媒体位置按槽位算，文字自动落另一半——"字压图"在语法上写不出来。

## 五、卡必须 seek 安全

渲染是"给时间线一个 t，取一帧"，任何依赖执行顺序或真实时钟的实现都会在成片里露馅。

- 禁止用 `timeline.call` 改 `textContent` / `innerHTML`（seek 会跳过 call，文字停在半句）——打字机改用裁剪揭示；
- 禁止对文字做 `scale` 表达强调（分块截图会出现瓦片状裁切）——改用 `opacity`；
- 下划线/圈重点用背景片段或按行绘制，不要拿绝对定位条贴在多行块底部；
- 随机必须固定种子；时间只能来自时间线。

## 六、诊断要能回答"哪一层错了"

每个节点的输出都要能定位责任：

- 选择错了 → `S2N` 的 `s2_warnings_json` 点名到屏与编号；
- 分镜空了 → `S1N` 直接说缺 scenes，让 `S1` 重做；
- 结构缺了 → `R3` 说骨架占位没替换，重跑 `R3`（外壳由 `R2` 一次性生成）；
- 转场缺风格偏好 → `R3` 的 warning 点名"S2 有 N 刀没给有效 pt"，条数不再对不上（逐刀生成，必是 N-1）；
- 动效没生效 → `R1` 的 `skipped` 记录原编号。

warning 里必须写"谁该重跑"，而不是"已补齐"（写法见 §3.5）。

## 七、判断新逻辑放哪一层

§3.2 讲"一个坏结果该去哪一层消灭"，这一节讲"新逻辑该往哪一层加"。

1. 模型能一次做对的 → 写进提示词，加自检清单；
2. 机器能确定性做对的（结构、坐标、校验）→ 写进 Code 节点/渲染器；
3. 只能事后知道的 → 写诊断，不改结果；
4. 想"不通过就停" → 回到第 1 或第 2 步。

## 八、自检（每次改完问自己）

1. 这次改的是**生成端**还是**成片**？
2. 有没有引入默认值顶替模型判断？
3. 有没有新增"不达标就失败"的检查？
4. 同样的错再跑一次还会不会出现？
5. 出问题时，warning 能不能指出该重跑哪个节点？
