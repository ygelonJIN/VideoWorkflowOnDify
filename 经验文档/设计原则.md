# 设计原则（改工作流之前先读这一页）

## 什么时候读

- 要改任何一层（提示词、Code 节点、卡、检查器、渲染脚本）之前；
- 想"加个校验、不过就停"的时候；
- 想出"缺了就补一个默认值/换一张卡/编一段文案"的时候；
- 有人报"这条片子某处不对"，你要决定是改片子还是改流程的时候。

---

## 一、目标是"稳定产出正确的片子"，不是"发现错误"

三条不能混：

| 做法 | 性质 | 结论 |
|---|---|---|
| 生成端一次就把结果做对 | **正确** | 要这个 |
| 发现问题 → 拦住、报失败、不出片 | 转移责任 | 不要 |
| 发现问题 → 渲完再改 HTML / 补默认值 | 掩盖问题 | 不要 |

判断标准只有一句：**改完之后，同样的输入再跑一遍，还会不会出同样的错？**
会 → 你改的是这条片子；不会 → 你改的是流程。

## 二、不兜底：缺什么就暴露什么，让上游重做

兜底看起来"保证出片"，实际是把错误变成静默的默认值，片子看着完整、内容是错的。

| 不要做 | 要做 |
|---|---|
| 口播不合格 → 拿论点拼一段 | 退回重写（`A06R`），提示词要求严格 JSON |
| 合规 rejected → 软化措辞继续打包 | 退回按 `revision_instructions` 重写 |
| 分镜为空 → 按口播切屏 | 报"A09 必须先产出 scenes"，让 A08/A09 重做 |
| 缺屏 → 合成一屏 | 回 `H01S/H02` 重做；结构由模板保证，不靠补 |
| 编号选错 → 换同角色卡 | 留空并点名"H01X 选错，需重跑" |
| 转场漏刀 → 补一个默认 PT | `H01T` 必须逐对给 `pt`，`H02T` 按权威切点表逐刀实现 |
| 规格缺字段 → 编标题/正文 | 只渲染模型给的内容；缺就是缺，回 `H02S` 重出 |

**例外只有一类**：结构。标签闭合、属性齐全、槽位不缺，由 `H02SK` 的固定模板保证——那是**生成器**，不是兜底。
模板不替模型做内容判断，只保证"模型交什么都能装进一个合法页面"。

## 三、不靠失败拦：检查只做诊断

- 内容检查（契约/排版/时间线/构图）默认只写 `诊断/检查结果.txt`，不阻塞渲染；
- 硬失败只留给环境（缺 Chrome / Node / HyperFrames）；
- `STRICT_RENDER=1` 只是排查开关，不是日常行为；
- **禁止**新增"不达标就 `exit 1`"的内容检查。要加检查，同时加修复或改生成端。

为什么：拦住只会让片子消失，问题还在。真正要的是"下一次不再发生"，那只能改生成端。

## 四、结构问题在生成端消灭，不在渲染前修

- 模型不写整屏 HTML：`H02S` 出规格 JSON，`H02SK` 用模板渲染；
- 文案是纯文本，渲染时转义；
- 组件片段先过标签平衡检查，不平衡就丢弃并记 warning；
- `css` 只接受本屏作用域选择器；
- 媒体位置按槽位算，文字自动落另一半——"字压图"在语法上写不出来。

## 五、卡必须 seek 安全

渲染是"给时间线一个 t，取一帧"，任何依赖执行顺序或真实时钟的实现都会在成片里露馅。

- 禁止用 `timeline.call` 改 `textContent` / `innerHTML`（seek 会跳过 call，文字停在半句）——打字机改用裁剪揭示；
- 禁止对文字做 `scale` 表达强调（分块截图会出现瓦片状裁切）——改用 `opacity`；
- 下划线/圈重点用背景片段或按行绘制，不要拿绝对定位条贴在多行块底部；
- 随机必须固定种子；时间只能来自时间线。

## 六、诊断要能回答"哪一层错了"

每个节点的输出都要能定位责任：

- 选择错了 → `H01XJ` 的 `cast_warnings_json` 点名到屏与编号；
- 分镜空了 → `H00` 直接说 A09；
- 结构缺了 → `H03` 说 H01S/H02；
- 转场漏了 → `H01V` 的切点表与 `H02T` 的条数对不上；
- 动效没生效 → `H02SX` 的 `skipped` 记录原编号。

warning 里必须写"谁该重跑"，而不是"已补齐"。

## 七、判断新逻辑放哪一层

1. 模型能一次做对的 → 写进提示词，加自检清单；
2. 机器能确定性做对的（结构、坐标、校验）→ 写进 Code 节点/渲染器；
3. 只能事后知道的 → 写诊断，不改结果；
4. 想"不通过就停" → 回到第 1 或第 2 步。

## 八、自检（每次改完问自己）

1. 这次改的是**生成端**还是**成片**？
2. 有没有引入默认值顶替模型判断？
3. 有没有新增"不达标就失败"的检查？
4. 同样的错再跑一次还会不会出现？
5. 出问题时，warning 能不能指出该重跑哪个节点？
