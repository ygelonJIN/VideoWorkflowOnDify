# 单屏场景（逐屏生成）

你只负责**一屏**的画面。这支片子的每一屏由**真实照片或设计过的 HTML 背景**承担主视觉。一次调用只写一屏：一个 `<section>`、一段 `<style>`。动效由动效节点统一写，转场由转场脚本节点写。

## 输入

- `scene_json`：{{#h02i.item#}}（本屏的分镜，含 `scene_id`、`sentence_ids`、`voiceover_text`、`on_screen_text`、`visual_brief`、`composition`、`index`、`total`、`prev_scene`、`next_scene`）
- `skeleton_html`：{{#h01s.text#}}（结构骨架与图片基础样式，只读）
- `art_direction_json`：{{#h01d.text#}}（色彩、字体、材质、光、纵深；**字号和间距不在里面**）
- `component_grammar_json`：{{#h01c.text#}}（文字块、字法、状态语言、`data-anim` 命名规则；这套语法里没有图形）
- `image_brief_json`：{{#h01pv.image_brief_json#}}（全片索引：查本屏的 `role` / `why` / `html_brief` / 图占多大 / 文字压哪侧 / 镜头怎么动）
- `composition_ledger_json`：{{#h00.composition_ledger_json#}}（全片构图账本：每屏的 `family` / `text_zone` / `align` / `scale`）
- `design_brief`：{{#h00.design_brief#}}（含 `composition_warnings`）

## 只写 `scene_json.scene_id` 这一屏（硬性）

- 输出**恰好一个** `<section>`，`data-scene` 等于本屏 `scene_id`。多写或少写都算错。
- `data-sentence-ids` 逐字抄本屏的 `sentence_ids`；`data-start="0"`；`data-duration` 写本屏口播的估算秒数（按 4.0–4.5 字/秒）；`data-visual` 写 `photo` 或 `html`。
- 不要写别的屏、不要写字幕、不要写 GSAP、不要写 `<script>`。

## 样式不能打架（逐屏生成最容易踩的坑）

每一屏是**独立一次调用**写出来的，最后会拼进同一个文档。所以：

- 所有类名必须带本屏前缀：`.s01-title`、`.s01-body`、`.s01-media`（`s01` = 本屏 `scene_id`）。
- 所有选择器必须以 `[data-scene="s01"]` 开头：`[data-scene="s01"] .s01-title{…}`。不要写裸 `.title`、`p`、`h2` 这类全局选择器，会污染其它屏。
- 各屏的字号、位置、对齐互不相干——这正是要的：**不要为了"统一"去猜别的屏用了什么**。

## 这一屏的构图按分镜执行

`scene_json.composition` 是分镜给这一屏的构图决定（`family` / `text_zone` / `align` / `scale` / `why`）。

- 文字压在 `text_zone` 指定的区域、按 `align` 对齐、主标题按 `scale` 决定力度。
- 对着 `composition_ledger_json` 检查：本屏不能和你紧邻的前后两屏（`prev_scene` / `next_scene`）同构；如果账本里它们和你 `family` 相同，换一个文字区或换一个力度。
- 首屏和末屏要能看出对照。
- 字阶由这一屏自己定：按 `composition.scale` 决定主标题力度（超大单行 / 三行块 / 小标题 + 大字数字 / 竖排……），正文跟着这一屏的标题走。骨架和 tokens 里没有全局字阶，别去找。

## 先读 role：这一屏由谁承担画面

`image_brief_json.images` 里本屏那条有 `role` 和 `why`。先读它，再落版：

| role | 这一屏怎么做 |
|---|---|
| `full` | 照片满屏，是底图；文字压在 `text_safe_zone` 那一侧。 |
| `inset` | 照片是内容块，占屏 40%–70%，**不是底图**；另一半给文字或背景。 |
| `portrait` | 照片是一个视觉锚（人物/物件/局部），文字绕开它。 |
| `texture` | 照片降对比做底纹，文字是主体。 |
| `html` | **不放 `<img>`，也不画图形**。纯文字屏：靠字号、断行、留白承担画面；`html_brief` 写这一屏的字怎么排。 |

## 照片怎么放

- 图片引用一律写成占位符：`{{IMG:图片id}}`。本地渲染前会替换成真实文件路径，**不要写 `媒体/图片/...`、不要写绝对路径、不要写 data URI**。
- `full`：`<div class="s01-media media" data-anim="media"><img src="{{IMG:s01}}" alt="" /></div>`。
- `inset`：`<div class="s01-media media media--inset" data-anim="media">…</div>`，`top/left/width/height` 写在本屏自己的 `.s01-media` 上。
- `portrait`：图片是视觉锚，可以局部裁切、框、圆或异形；文字绕开主体。
- `texture`：图片降对比、降饱和或加遮罩做底纹，文字是唯一主体。

标准结构（`full` 示例，只换内容）：

```html
<section class="scene clip" id="s01" data-scene="s01" data-sentence-ids="s01" data-start="0" data-duration="4.200" data-visual="photo">
  <div class="s01-media media" data-anim="media">
    <img src="{{IMG:s01}}" alt="" />
  </div>
  <div class="s01-scrim media-scrim" data-anim="scrim"></div>
  <div class="s01-copy">
    <p class="s01-kicker" data-anim="kicker">一句引子</p>
    <h1 class="s01-title" data-anim="title">这一屏的主张</h1>
    <p class="s01-body" data-anim="body">支撑主张的一句话</p>
  </div>
</section>
```

## html 屏：只用文字，不画任何图形

`role=html` 的屏不放照片。**这一屏的画面由文字本身的排版本体承担**：字号、字重、断行、字距、对齐、留白节奏，就是它的"画面"。底色、渐变、颗粒来自骨架的 `#background-layer`，不在这一屏里画。

- 保留一个空的 `<div class="s01-bg" data-anim="bg"></div>` 作为背景槽位（契约需要），但**不要往里画东西**：不写线条、网格、色块、刻度、进度、行/链/卡片/标签框、圆圈、图案。
- 唯一允许的 CSS 视觉：文字样式本身，以及为保证可读性加的整屏压暗/压亮渐变（不加结构）。
- 想"讲对比/流程/因果"，用**文字结构**表达：大小字对比、编号、分行、对齐、留白，不要画示意图。
- 这一屏更要靠字级拉开：主标题可以大到 140–180px 单行，或者一整段竖排；不要做成"小标题 + 几行小字"的默认样子。

## 允许什么、禁止什么

**允许**：文字（标题、正文、编号、引句）、字重/字号/字距/行距/断行/对齐、纯色或渐变遮罩（只为可读性）、照片。

**禁止**：图标、插画、示意图、流程图、结构图、数据图表（柱状/折线/饼图）；线条、分隔线、网格、刻度、进度条、色块、圆点、卡片、标签框、行/链结构；`<canvas>`、Three.js、SVG、emoji 当图形。**这一版 HTML 只做文字和动效，不做任何图形。**

要表达具象的东西：用照片。要表达抽象判断：用文字层级。没有第三条路。

## 内容密度与版面

- 每屏至少三层信息，而且只能靠文字拉开：主张（大字）+ 支撑（1–3 行）+ 一个可引用的短句或数字（很小或很大）。不靠画图补画面。
- 内容块在安全区内**整体垂直居中**，占屏高 **45%–70%**；不要顶在顶部 200px、下面空一片。
- 标题字号不小于 72px，正文 36–44px，字号直接写 px，不要用 rem。
- 标题、支撑、视觉锚之间至少 32px；图文各半时文字块与图片之间至少 48px。
- 安全区：左右 90px、顶部 200px、底部 300px（字幕区）。照片可以满屏出血，但文字必须在安全区内。
- 长标题显式断行，避免单字成行；不要贴边。

## 「场景演示」标注只在必要时出现

只有这一屏**确实展示了虚构的数值、虚构的界面或示例数据**时，才在紧挨着那组数字的地方标一次「场景演示」或「示例数据」，一行小字。

- 照片屏、观点屏、纯文字判断屏**一律不标**。
- 不要做成常驻角标、页眉、页脚或水印，不要出现在画面边缘。
- 标了但画面里没有虚构数据，等于给自己加脏点，成片每一帧都带着。

## 技术契约（硬性）

1. `section` 必须是 `<section class="scene clip" …>`，属性一个不少：`id` 与 `data-scene` 都等于本屏 `scene_id`、`data-sentence-ids`、`data-start="0"`、`data-duration`、`data-visual`。
2. 本屏样式放一个 `<style>`，选择器全部以 `[data-scene="本屏 id"]` 开头，类名带 `s<本屏 id>-` 前缀。
3. 照片屏必须有且只有一个 `data-anim="media"` 容器；`html` 屏必须留一个**空的** `data-anim="bg"` 容器当槽位，但不画图形。其余元素用 `kicker / title / body / stat / rule / note / scrim` 这套 `data-anim` 名字，同屏不重名。
4. 需要状态变化的元素加 `data-state="a|b"` 和对应 class；数字加 `data-count="初值|终值"`；列表行加 `data-row`。
5. **不写任何 GSAP 时间线**（`timeline.from/to/fromTo/set` 都不写），动效由动效节点统一写。
6. 字幕由本地注入，不要写字幕块、不要写 `.caption`。
7. 先输出 `<section>`，再输出一个 `<style>`。不要 `<script>`、不要 `<html>`、`<head>`、`<body>`、媒体占位。
8. 只输出以上内容：不要解释、不要代码围栏、不要调试注释、不要场景编号或坐标注释。

## 内容要求

- 这一屏只服务本屏 `voiceover_text` 正在讲的这一句，不跑到别的屏。
- 文字之间、文字与图片主体之间不得叠压；不要常驻页眉页脚水印。
- 一屏讲一件事。讲不完说明分镜该拆，不要靠缩小字号硬塞。
