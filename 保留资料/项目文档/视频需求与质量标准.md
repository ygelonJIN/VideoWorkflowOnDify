# 视频生产与质量标准

## 1. 当前生产架构

```text
html-only：Dify 生成内容和 HTML → 浏览器预览
black-frame：Dify 生成 HTML + 口播文案 → MiMo TTS/提供音频 → BGM、字幕、MP4
full：Dify 生成 HTML → HeyGen 数字人和口播 → BGM、字幕、MP4
```

`full` 中 HeyGen 负责数字人形象、中文口播和口型同步；`black-frame` 不调用 HeyGen。产品 UI、字幕、数据卡片、流程、CTA 和元素级动效均由 HTML/CSS/GSAP 制作。

## 2. 交付规格

- 平台：抖音、视频号、快手、小红书。
- 画幅：9:16。
- 分辨率：1080×1920。
- 帧率：25 或 30 fps。
- 时长：默认 25–35 秒；以最终口播真实时长为准，不通过加速掩盖超长内容。
- 语言：简体中文。
- 封装：H.264 MP4。
- 响度：约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。
- 音画时长差：小于 100ms。

## 3. 输出模式

- `full`：显示 HeyGen 数字人小窗，并使用 HeyGen 口播音轨；小窗位置和尺寸由本次构图决定。
- `black-frame`（历史模式名，实际为无数字人模式）：必须零占位；不得出现数字人窗口、头像、黑帧小窗、纯黑保留区或等价空白窗口。删除窗口后必须回收左上/右上占位区域，顶部内容不得继续避让或留下空槽。使用 MiMo TTS 或用户提供的口播音频。
- `html-only`：只输出浏览器预览，不生成音频和 MP4。
- `black-frame` 仍必须保持真实口播驱动场景、字幕和元素级动画，不得退化成无音频的静态 HTML。

## 4. HeyGen 数字人小窗（仅 full）

- 数字人小窗在整片中保持可识别、不遮挡关键信息；位置和尺寸由本次构图决定。
- 1080px 画布中保持视觉注意力克制，不遮挡标题、数字、图表、字幕或关键操作区域。
- 不固定 top/right、宽高、圆角或阴影，由模型根据构图设计。
- 可以使用圆角矩形、圆形、描边、阴影或其他与本次视觉风格一致的头像框。
- 不遮挡标题、按钮、数字、图表、字幕或关键产品区域。
- 复杂全屏 UI 段可以淡出小窗，但口播音轨继续。

## 5. 单条视频内容结构

每条视频只讲一个核心主张，不按素材的时间顺序讲：

1. 第一句：直接给出 `distill.thesis`（判断句）。
2. 第二句：把结论推到代价、反常识或后果上。
3. 中段：按 `strategy.argument_order` 逐条展开，每个论点 1–2 句，先论点后证据。
4. 结尾一句：回收主张，可以被单独截出来当金句。

信息密度固定为：

- 1 个主张（`thesis`）。
- 支撑主张的论点（`arguments[]`），条数由素材决定；每条要么有证据，要么明确标记 `support=none`。
- 1 组最强证据。
- 1 个收束句（不强制 CTA）。

内容规则（提示词层，靠模型自觉）：

- 禁止时间线流水账：不按素材的时间顺序叙述，过程、行程、寒暄不写。
- 禁止照搬素材：用自己的话讲论点，原话只在关键句上短引用。
- 禁止漏讲主张：讲的每屏都要服务 `thesis`，`argument_coverage` 报清哪个论点落在哪句。
- 不设配额：论点数、句数、字数、屏数全部由内容和模型判断。
- 没有时长目标：文案写多长，成片就多长；`target_duration_seconds` 只作 HTML 编排参考，最终以真实 TTS 时长为准。

唯一的拦截项是"时间连接词成串"（≥5 处即判在按过程复述，触发一次自动改写）；其余（素材重合率、转述处数、自报覆盖、字数句数）只写进 `content_diagnostics`，提示但不阻塞。

中文口播按约 4.0–4.5 字/秒估算；估算值只用于编排，不用来裁剪内容。

## 6. UI 与组件

- 组件用可复用的高保真表现手法（同一套颜色、间距、形状语法），通过文案、数字、行业、流程变量适配内容；不预先提供组件目录或固定模板。
- 不要求每次提供真实产品截图，但不得把生成示意图冒充真实产品截图。
- 示例数据必须标记“场景演示”或“示例数据”，但只在画面确实展示虚构数值或虚构界面时，于该处标 1 处；纯观点、情绪、叙事画面不标注，禁止每屏盖标注水印。
- UI 演示应表现完整动作：输入、筛选、点击、展开、状态变化、流程推进和 CTA。
- 字体、颜色、间距、圆角、阴影和组件层级由模型根据本次主题统一设计，不使用固定模板。
- 组件应有清晰的信息层级和可读性；组件数量、类型、大小和排布由内容与模型能力决定。
- 不提供组件目录，也不接受默认卡片。组件形态必须由本屏要给出的证据推导：数字、对比、先后、状态变化、判词或画面；判定标准是“遮住文字后，画面结构本身仍在表达这一屏的意思”。
- 同一支视频内组件语法必须统一（圆角、描边、标签、间距同一套）；不同视频之间不得复用同一套组件骨架和配色。
- 生成端先做设计定调：一句话视觉隐喻、一个主色相 + 一个强调色 + 一组中性阶；字阶、间距基准和形状语法由这个隐喻统一决定，不设固定档数或固定数值。
- 排版：同屏文字层级、每行字数、标题行数和主对齐方式由构图决定，判断标准是层级清楚、断行自然、可读；四周留安全边，不贴边。
- 不提供组件清单、视觉风格清单或禁用清单：组件、风格和动效由模型按本片隐喻自行决定，避免示例被当成模板。
- 每个场景的主内容垂直中心以 700–1100px 为舒适区、640–1160px 为硬边界；标题、正文、数据组件和当前字幕不得重叠。长标题显式断行，避免单字成行。装饰层（低透明度、渐变文字）不计入重叠。
- 在视觉隐喻统一、组件语法统一的前提下，允许模型自由决定栅格、字阶、外边距、组件数量、动效形态和过场方式；不得使用运行时随机或与内容无关的漂浮、无限粒子。
- 不设常驻页眉、页脚、品牌角标、章节编号或水印层；画面只服务于当前这一屏的内容。
- 字幕不交给模型：HTML 里不出现字幕容器、条目和样式，统一由本地 `sync_video.py` 在渲染前注入；支持用 `字幕/手写字幕.srt` 完全接管文案和时间码。
- 同一场景内的状态切换必须重叠（先入后出）；成片不允许出现只有背景的空屏，哪怕一帧。渲染后由 `detect_blank_frames.py` 检测，`repair_blank_frames.py` 用前一帧修复孤立空帧。
- 图像生成只用于抽象 B-roll、背景和氛围，不用于伪造产品界面。

## 7. 动效要求

每个中段镜头必须包含语义相关元素级动画。每约 1.5–2.5 秒应有一次可见变化，优先使用：

- 信息逐项入场。
- 数字递增。
- 搜索结果逐条出现。
- 路径逐步点亮。
- 鼠标点击和页面状态变化。
- 局部放大或焦点标注。
- 语音关键词高亮。

动作工艺基线：

- 入场位移不超过 32px，单次时长 0.28–0.5s，逐项 stagger 60–100ms；同一屏缓动不超过 2 种。
- 每个场景至少 2 个可寻址的组件级动作，其中至少 1 个必须是状态变化（数值、进度、选中、展开、路径点亮、状态标签切换）；只有位移加淡入不算。
- 动作在场景内要分布开，不得全部挤在开头 0.5 秒；口播说到之前或同时，画面给出对应变化。
- 过场 0.2–0.4s，整片不超过 2 种；硬切也算过场，不必每屏都加动画。

禁止：

- 静态 PNG 直接当作完整动效镜头。
- 只做整图缩放、循环呼吸、随机漂浮或无限粒子。
- 所有元素同时出现后长时间静止。
- 无语义的幻灯片硬切。
- 随机时间和无限循环。

动画必须由语音内容或明确时间线驱动。转场发生在语义停顿处，不在动作或关键词中间切断。

确定性质量门禁：

- 画面里出现的每个组件都要有自己的动作（进入 + 至少一次状态变化），整屏只有一个淡入等于没做动效；HTML 必须使用可寻址 GSAP 时间线的 `from/fromTo/to/set` 动作 API，循环批量生成的动作也要有明确目标和结束时间。
- `H03` 的 `motion_report_json` 会给出每组 `animated_elements / anim_elements` 与 `coverage`，未被任何动作命中的组件会列在 `uncovered` 里，作为人工复核信号（只提示，不阻塞）。
- 动效必须有目标、状态变化、开始/结束和语义理由；不能只有空泛的“出现”。
- 随机性只能发生在作者期变体选择（布局、组件、动效、过场各选一个变体），运行时禁止 `Math.random`、随机时间和随机颜色。
- 最终渲染前执行 `check_html_contract.py`，渲染后执行 `check_final_video.py`；技术时间轴、媒体时长、同步标记、动效时间线或无数字人零占位任一不达标就停止交付。

## 8. 口播、音乐和字幕

- `full` 使用 HeyGen 口播；`black-frame` 使用 MiMo TTS/提供音频。口播始终是主时间线。
- Dify 只生成 `voiceover_script` 和 HTML；MiMo TTS 在本地统一入口运行，音频落为项目的 `媒体/口播.mp3`。
- 字幕文案：默认按口播完整句子切分；把自写 SRT 放到 `字幕/手写字幕.srt`（或 `字幕/最终字幕.srt`）时，完全以该文件为准，跳过自动切句。
- 先确定最终语音，再由句子或词级时间码驱动场景、字幕和元素动画。
- `媒体/口播.mp3` 的实际时长是唯一主时钟。场景从作者期时间等比映射到真实口播时长；每个场景再通过 `data-sentence-ids` 与字幕 `data-sentence-id` 锚到对应完整句子的真实起始时间；元素动效的相对偏移和相对时长使用同一比例。禁止对已校准场景、字幕或媒体时间二次缩放。
- 同步后场景总时长、根 `data-duration`、口播、BGM、成片视频和成片音轨必须一致；字幕不得越过成片结束时间。渲染后执行 `normalize_final_audio.py`，再执行 `check_final_video.py`。
- 说到搜索、数字、流程或 CTA 时，对应视觉元素同步出现。
- 全片字幕按完整句子呈现：每个 `。！？!?` 结束的完整句子单独一条，不按字数截断或拼接半句。
- 默认字幕规格（本地注入，可改）：中下方 `bottom:13%`，水平居中，**文字宽度随内容自适应**（`width:auto`，上限 80% 画布宽度，多行时自动换行），字号 45px、行高 1.35、字重 700、白色文字；无底板、无描边、无圆角、无内边距，只用双层柔和黑色投影保证亮背景可读。字幕不得用整条背景板或全屏遮罩。
- `full` 不遮挡数字人和产品 UI，`black-frame` 不遮挡产品 UI。
- 背景音乐不能压过口播，自动补齐到实际成片时长。
- ASR/HeyGen transcript 只提供时间码；字幕文字必须使用已批准 `voiceover_script` 自动校正同音字和错别字。若没有 transcript，本地 ASR 只作时间码回退，最终仍需人工检查断句。

## 9. Storyboard 与动效计划

分镜至少表达：

- `voiceover_text`
- `visual_source`
- `visual_brief`
- `on_screen_text`
- `motion`
- `transition`
- `sound`
- `sync_rule`

动效计划必须与口播 cue 对应，不能先列后续信息，也不能只给通用“淡入/缩放”。

## 10. 最终质量门禁

检查分两级：**只有"渲染器跑不起来"才拦流程**（缺 `#stage`、缺字幕占位、没有 `window.__timelines`、没有 GSAP 动作、用了 `requestAnimationFrame`/`performance.now`、输出里残留工具调用文本）。版面、动效密度、构图、内容诊断全部只报告，不阻塞渲染——成片优先，问题留给人看。

- [ ] 画布为 1080×1920；场景构图、布局手法（flex/grid/绝对定位/全出血）由模型自由设计。
- [ ] 实际时长符合内容需要，音画时长差小于 100ms。
- [ ] 口播、场景、字幕和元素动画逐句同步。
- [ ] 每个中段镜头建议至少一次可见语义动效，具体动作和密度由模型根据内容决定。
- [ ] 每个时刻只出现一条完整句子字幕，句末标点完整，无截断和半句拼接。
- [ ] 首句就是主张，不是过程描述；全文只讲一个主张。
- [ ] `argument_coverage` 覆盖 `argument_order` 全部论点，没有漏讲。
- [ ] 没有时间线流水账，没有整句照搬素材（回看 `content_diagnostics` 的 `chronology_words` 与 `verbatim_ratio`）。
- [ ] 字幕位置、80% 最大宽度、45px 字号、1.35 行高和无底板文字符合固定规格。
- [ ] 回看 `check_html_layout.mjs` 的报告：文字有没有互相叠压、内容有没有出界（报告不阻塞渲染）。
- [ ] `full` 必须保留 HeyGen 数字人小窗，且不遮挡关键内容；位置和尺寸由本次构图决定。
- [ ] `black-frame`（无数字人模式）零占位，不包含数字人窗口、avatar 角色、数字人媒体、黑帧小窗、纯黑保留区或等价空白窗口。
- [ ] 示例数据明确标注，不冒充真实产品 UI。
- [ ] 数字、案例、英文词和多音字读音正确。
- [ ] 案例、价格、CTA 和产品事实已确认。
- [ ] 响度约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。
- [ ] 若项目提供 `npm run quality:video`，执行并通过。
- [ ] 最终保留 MP4、SRT/字幕时间码、最终口播和 storyboard JSON。

## 11. 运行时边界

- `workflow_runtime/` 只保存通用模板、脚本、资产和工具。
- 每个项目使用独立目录，不把运行结果写入 `workflow_runtime/`。
- `Dify输出/` 保存原始 TXT、统一 JSON 和解析后的 HTML/HeyGen 响应。
- 最终项目字幕保存在项目自己的 `字幕/` 目录。
