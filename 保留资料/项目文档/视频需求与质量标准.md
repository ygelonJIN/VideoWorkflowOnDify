# 视频生产与质量标准

## 1. 当前生产架构

```text
html-only：Dify 生成内容和 HTML → 浏览器预览
black-frame：Dify 生成 HTML + 口播文案 → MiMo TTS/提供音频 → BGM、字幕、MP4
full：Dify 生成 HTML → HeyGen 数字人和口播 → BGM、字幕、MP4
```

`full` 中 HeyGen 负责数字人形象、中文口播和口型同步；`black-frame` 不调用 HeyGen。产品 UI、字幕、数据卡片、流程、CTA 和元素级动效均由 HTML/CSS/GSAP 制作。

## 2. 交付规格

- 平台：抖音、视频号、快手、小红书。
- 画幅：9:16。
- 分辨率：1080×1920。
- 帧率：25 或 30 fps。
- 时长：默认 25–35 秒；以最终口播真实时长为准，不通过加速掩盖超长内容。
- 语言：简体中文。
- 封装：H.264 MP4。
- 响度：约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。
- 音画时长差：小于 100ms。

## 3. 输出模式

- `full`：显示 HeyGen 数字人小窗，并使用 HeyGen 口播音轨；小窗位置和尺寸由本次构图决定。
- `black-frame`（历史模式名，实际为无数字人模式）：必须零占位；不得出现数字人窗口、头像、黑帧小窗、纯黑保留区或等价空白窗口。删除窗口后必须回收左上/右上占位区域，顶部内容不得继续避让或留下空槽。使用 MiMo TTS 或用户提供的口播音频。
- `html-only`：只输出浏览器预览，不生成音频和 MP4。
- `black-frame` 仍必须保持真实口播驱动场景、字幕和元素级动画，不得退化成无音频的静态 HTML。

## 4. HeyGen 数字人小窗（仅 full）

- 数字人小窗在整片中保持可识别、不遮挡关键信息；位置和尺寸由本次构图决定。
- 1080px 画布中保持视觉注意力克制，不遮挡标题、数字、图表、字幕或关键操作区域。
- 不固定 top/right、宽高、圆角或阴影，由模型根据构图设计。
- 可以使用圆角矩形、圆形、描边、阴影或其他与本次视觉风格一致的头像框。
- 不遮挡标题、按钮、数字、图表、字幕或关键产品区域。
- 复杂全屏 UI 段可以淡出小窗，但口播音轨继续。

## 5. 单条视频内容结构

每条视频只讲一个核心主张，不按素材的时间顺序讲：

1. 第一句：直接给出 `distill.thesis`（判断句）。
2. 第二句：把结论推到代价、反常识或后果上。
3. 中段：按 `strategy.argument_order` 逐条展开，每个论点 1–2 句，先论点后证据。
4. 结尾一句：回收主张，可以被单独截出来当金句。

信息密度固定为：

- 1 个主张（`thesis`）。
- 支撑主张的论点（`arguments[]`），条数由素材决定；每条要么有证据，要么明确标记 `support=none`。
- 1 组最强证据。
- 1 个收束句（不强制 CTA）。

内容规则（提示词层，靠模型自觉）：

- 禁止时间线流水账：不按素材的时间顺序叙述，过程、行程、寒暄不写。
- 禁止照搬素材：用自己的话讲论点，原话只在关键句上短引用。
- 禁止漏讲主张：讲的每屏都要服务 `thesis`，`argument_coverage` 报清哪个论点落在哪句。
- 不设配额：论点数、句数、字数、屏数全部由内容和模型判断。
- 没有时长目标：文案写多长，成片就多长；`target_duration_seconds` 只作 HTML 编排参考，最终以真实 TTS 时长为准。

唯一的拦截项是"时间连接词成串"（≥5 处即判在按过程复述，触发一次自动改写）；其余（素材重合率、转述处数、自报覆盖、字数句数）只写进 `content_diagnostics`，提示但不阻塞。

中文口播按约 4.0–4.5 字/秒估算；估算值只用于编排，不用来裁剪内容。

## 6. UI 与组件

- 组件用可复用的高保真表现手法（同一套颜色、间距、形状语法），通过文案、数字、行业、流程变量适配内容；不预先提供组件目录或固定模板。
- 不要求每次提供真实产品截图，但不得把生成示意图冒充真实产品截图。
- 示例数据必须标记“场景演示”或“示例数据”，但只在画面确实展示虚构数值或虚构界面时，于该处标 1 处；纯观点、情绪、叙事画面不标注，禁止每屏盖标注水印。
- UI 演示应表现完整动作：输入、筛选、点击、展开、状态变化、流程推进和 CTA。
- 字体、颜色、间距、圆角、阴影和组件层级由模型根据本次主题统一设计，不使用固定模板。
- 这里的"组件"只能是文字块（标题块、数字、引句、编号组），没有形状：层级、大小和排布由内容决定。
- 不提供组件目录，也不接受默认卡片。组件形态必须由本屏要给出的证据推导：数字、对比、先后、状态变化、判词或画面；判定标准是“遮住文字后，画面结构本身仍在表达这一屏的意思”。
- 同一支视频内组件语法必须统一（圆角、描边、标签、间距同一套）；不同视频之间不得复用同一套组件骨架和配色。
- 生成端先做设计定调：一句话视觉隐喻、一个主色相 + 一个强调色 + 一组中性阶；形状语法（圆角、描边、标签形态）由这个隐喻统一，**字阶、间距和对齐不统一冻结**，由每一屏按自己的构图决定。全片只统一颜色、字体栈、圆角、描边、缓动和时长。
- **构图在分镜阶段分配，逐屏不同**：A08 为每屏写 `composition`（`family` / `text_zone` / `align` / `scale` / `why`），相邻两屏 `family` 不能相同，全片至少 `min(4, 屏数)` 种，首屏与末屏的 `family`、`text_zone`、`scale` 不能三项全同。单屏场景节点照账本执行（逐屏生成时账本随每屏一起下发），不各自即兴；`check_composition_variation.mjs` 量真实 DOM 复核。
- 排版：同屏文字层级、每行字数、标题行数和主对齐方式由构图决定，判断标准是层级清楚、断行自然、可读；四周留安全边，不贴边。
- 不提供组件清单、视觉风格清单或禁用清单：组件、风格和动效由模型按本片隐喻自行决定，避免示例被当成模板。**例外**：动效实现与界面组件的编号库（`保留资料/动效库/`）是受控白名单，模型按编号取用、在参数内调整，见 §7.2。
- 每个场景的主内容垂直中心以 700–1100px 为舒适区、640–1160px 为硬边界；标题、正文、数据组件和当前字幕不得重叠。长标题显式断行，避免单字成行。装饰层（低透明度、渐变文字）不计入重叠。
- 在视觉隐喻统一、组件语法统一的前提下，允许模型自由决定栅格、字阶、外边距、组件数量、动效形态和过场方式；不得使用运行时随机或与内容无关的漂浮、无限粒子。
- 不设常驻页眉、页脚、品牌角标、章节编号或水印层；画面只服务于当前这一屏的内容。
- 字幕不交给模型：HTML 里不出现字幕容器、条目和样式，统一由本地 `sync_video.py` 在渲染前注入；支持用 `字幕/手写字幕.srt` 完全接管文案和时间码。
- 同一场景内的状态切换必须重叠（先入后出）；成片不允许出现只有背景的空屏，哪怕一帧。渲染后由 `detect_blank_frames.py` 检测，`repair_blank_frames.py` 用前一帧修复孤立空帧（只判真正的孤立单帧；"先满、后归零、再回满"这类逻辑问题由 `check_html_timing.mjs` 拦，见 §7.3）。
- **每一屏的主视觉由照片或设计过的 HTML 背景承担**。图像计划（H01P）逐屏决定 `role`：`full` 满屏底图、`inset` 内容块、`portrait` 视觉锚、`texture` 底纹、`html` 不生成照片、由 CSS 背景和排版承担。照片由本地 `generate_images.py` 调 GPT Image API 生成，HTML 用 `<img src="{{IMG:图片id}}">` 放进版面；无图屏写 `data-visual="html"` 和 `data-anim="bg"`。整片至少保留一张真实照片，图像不用于伪造产品界面。
- 安全区（黑帧 04，H02 写入提示词，`check_html_layout.mjs` 报告）：画布 1080×1920，所有内容距左右边缘 ≥ 90px、距顶部 ≥ 200px、距底部 ≥ 300px（底部留给字幕）。安全区之外只允许纯背景，不放任何内容元素。
- 视觉风格、色彩、字体搭配、版式和质感全部由模型根据内容决定，不套用固定模板，也不规定方向。若用质感层，用 `#stage` 伪元素实现，z-index 低于字幕 70，不新增带 `scene` 类名的 DOM 节点。
- 字体只用已声明 `@font-face` 的无衬线字体（PingFang SC、Noto Sans CJK SC、Microsoft YaHei 等），不引入未声明的衬线字体。
- **HTML 只做文字和动效，不画任何图形**：不用 canvas、Three.js、SVG、图标、插画、示意图、数据图表，也不画线条、分隔线、网格、刻度、进度条、色块、圆点、卡片、标签框、行/链结构。具象视觉由照片承担；`role=html` 屏是纯文字屏，靠字号、断行、对齐和留白承担画面，背景只有底色和光。
- 背景层若用 canvas，必须写在 `#background-layer` 内，通过 `hf-seek` 事件按 `e.detail.time` 重绘，不用 `requestAnimationFrame`/`setInterval`/`Math.random` 当驱动。`.scene` 外壳、`data-scene`、`data-sentence-ids`、`data-start`、`data-duration` 必须保留，字幕与时长同步依赖它们。
- 每屏两层：底层（照片，或底色与光）、顶层（文字）。无图屏不靠画结构撑画面，靠字级、断行、留白和一句够狠的话；只有小标题加几行小字、又没有照片的屏属于不合格。
- **每屏至少三层信息**：标题（主张）+ 支撑（1–3 行）+ 视觉锚（数字/标签/对比/可引用句）。只有标题和一句说明的屏视为内容不足，应拆屏或补支撑，不得靠放大字号和留白凑时长。
- **内容块垂直居中**：内容少时整体在安全区内居中，不允许顶到顶部 200px 处、下方空一大片。
- **元素间距**：标题/支撑/视觉锚之间至少 32px；图文各半时文字块与图片之间至少 48px；满屏图上的文字块与画面边缘保持 90px 安全边。

## 7. 动效要求

每个中段镜头必须包含语义相关元素级动画。整片不应出现长时间静止：每屏至少一次可见变化，变化由语义触发，不按固定秒数凑，优先使用：

- 信息逐项入场。
- 数字递增。
- 搜索结果逐条出现。
- 路径逐步点亮。
- 鼠标点击和页面状态变化。
- 局部放大或焦点标注。
- 语音关键词高亮。

动作工艺基线：

- 入场幅度由元素尺寸和构图决定，以“看得见”为准，不设固定像素上限，也不用个位数像素的微动凑数；单次时长由幅度决定，逐项 stagger 60–100ms；同一屏缓动不超过 2 种。
- 每个场景至少 2 个可寻址的组件级动作，其中至少 1 个必须是状态变化（数值、进度、选中、展开、路径点亮、状态标签切换）；只有位移加淡入不算。
- 每屏只设一个主运动（`priority=main`），其余为次级；次级在主运动落定后 80–160ms 跟随。
- 动效时间按真实词触发：`start_trigger` 为 `word:关键词` 的节拍写成 `at(cue('s04','关键词',1.2))`，由本地注入的 `window.__cue` 换算成秒，不手猜。
- 动作在场景内要分布开，不得全部挤在开头 0.5 秒；口播说到之前或同时，画面给出对应变化。
- 过场由转场设计节点逐切点决定：切在哪个语义停顿、用哪一族、动哪一层、多长，都不设固定值；硬切也是合法转场，不必每屏都加动画。
- 场景显隐由页面自己驱动（按 `data-start` / `data-duration` 计算），本地不再注入兜底运行时；页面没写驱动就是全部场景叠在一起，契约检查会拦。
- **同一 scene_id 只能出现一次，scene 只引用分镜里存在的 `sentence_ids`。** 单屏场景节点只输出自己那一屏；合并阶段按分镜去重、丢弃越界 scene 并校正句子锚点。成片不允许出现 0.12s 级别的闪屏，也不允许一屏停 7–8 秒后长时间静止：单屏时长应跟句子窗和内容量匹配，异常时先修分镜/合并，不要靠拉伸动画掩盖。

### 7.1 页面节奏与页面边界（2026-11）

- 页数、每页讲几句不设配额，由分镜导演按内容和口播决定；不要求“一页一句”或“一页三句”。
- 每一屏必须写 `data-voiceover`，逐字等于这一页实际说到的那段口播原文。合并阶段从分镜的 `voiceover_text` 自动注入，模型不用额外维护。
- 本地 `sync_video.py` 用这段原文在真实词级时间码里定位页面起点；页长 = 下一屏起点 − 本屏起点。不再按作者期时长在句子内部按比例切。
- 页面切换要落在真实口播的换气/语义停顿上。切在词中间，或一页只有 2 秒却塞 4 个信息点时，先修分镜，不要靠拉伸动画掩盖。
- **每屏第一帧是纯背景**（2026-11-11 改）：照片、组件、文字全部从无到有，由动效入场；允许首帧只有底色和光，但不允许首帧只有字幕。所有可见元素必须在场景开始后 1.2 秒内开始入场。
- 图片层不得在屏内出现 `opacity 1 → 0 → 1` 的回落；进入屏的视觉承担者不得先归零再淡入。转场只许一个方向。
- 转场脚本的位置必须是绝对秒：builder 第一行写 `timeline.__absolutePositions = true`，用 `__sceneStart(to_scene)` / `__cueAbs(...)`；不要把 `__cue()` 的相对秒直接当绝对位置，也不要用代理对象 + CSS 变量写 scene 的 `opacity`。

禁止：

- 静态 PNG 直接当作完整动效镜头。
- 只做整图缩放、循环呼吸、随机漂浮或无限粒子。
- `yoyo`、`repeat` 等往复或循环动作（黑帧 04 的 H02M 和 A10 都明令禁止，H03 会报警告）。
- 动效的方式、节奏和动作形态由动效设计师根据画面决定，不设动作类型配比。H03 只报告哪些组件没有任何动作（覆盖率），不规定做多少。
- 动效纪律（H02M 写入提示词）：不按 `scene_purpose` 发固定配方，动作由这一屏的内容和口播重音决定；每屏至少两种动作族（入场、状态、结构、绘制、空间、文字、模拟交互），全片至少覆盖五种；每屏结尾留一小段 hold；全片至少三种不同开场，并复用骨架定的 2–3 个母题动作。
- **文字出现方式完全交给模型**：不提供样式清单，不要求每屏按同一套顺序入场。只约束结果：相邻两屏的文字出现方式必须一眼看出不同；全片不同做法不少于 min(4, 屏数)；至少部分屏在 t=0 没有文字，由照片或设计背景先撑住；禁止把“半透明变实”或“浅灰变强调色”当入场，文字从不可见开始时必须同时有另一种看得见的形态变化。
- canvas / 三维图层不由 GSAP 驱动，改由 `hf-seek` 里的时间函数绘制；GSAP 只作用于 DOM 元素。
- 所有元素同时出现后长时间静止。
- 无语义的幻灯片硬切。
- 随机时间和无限循环。
- **对整屏图层做 `filter` 动画**（brightness/blur）：无头捕获会在滤镜起始帧拍到整帧黑屏，成片表现为单帧闪黑；压暗改用 opacity 或半透明遮罩。

动画必须由语音内容或明确时间线驱动。转场发生在语义停顿处，不在动作或关键词中间切断。

确定性质量门禁：

- 画面里出现的每个组件都要有自己的动作（进入 + 至少一次状态变化），整屏只有一个淡入等于没做动效；渲染后跑 `check_motion_profile.py --html index.html` 看逐屏报告，标"弱"的屏需要补主运动（只报告，不阻塞）；HTML 必须使用可寻址 GSAP 时间线的 `from/fromTo/to/set` 动作 API，循环批量生成的动作也要有明确目标和结束时间。
- `H03` 的 `motion_report_json` 会给出每组 `animated_elements / anim_elements` 与 `coverage`，未被任何动作命中的组件会列在 `uncovered` 里，作为人工复核信号（只提示，不阻塞）。
- 动效必须有目标、状态变化、开始/结束和语义理由；不能只有空泛的“出现”。
- 随机性只能发生在作者期变体选择（布局、组件、动效、过场各选一个变体），运行时禁止 `Math.random`、随机时间和随机颜色。
- 最终渲染前执行 `check_html_contract.py`、`check_html_timing.mjs`、`check_motion_variation.mjs`、`check_composition_variation.mjs`；渲染后执行 `check_final_video.py`。时间线检查拦整屏不可见、图片闪回和动作越界；动效差异只报告相邻同签名、文字/图片动作种类，不阻塞；构图差异默认只报告，加 `STRICT_COMPOSITION=1` 时相邻或首尾两屏同构会拦。技术时间轴、媒体时长、同步标记、动效时间线或无数字人零占位任一不达标就停止交付。

### 7.2 照片包裹、虚拟指针与背景动效（2026-11 放开）

此前正文一律不做图形。现在放开三样，各有明确边界：

- **照片包裹**：允许对照片块做圆角（≤30px）、整圈或单边描边（≤3px）、边缘受光、聚光跟随、轻微跟随倾斜（≤8°）。它是对已有照片的处理，不新增图形；**同一支片子只用一种包法**，不能每屏换。
- **虚拟指针**：原先靠鼠标 hover/move 触发的效果，改成由时间线给出指针坐标（归一化 0–1），再由 CSS 变量驱动视觉效果。视频里没有用户，指针是表演出来的，必须由 cue 驱动、有明确起止。
- **片头/过场背景动效**：仅限开场 3 秒内或两个场景之间，低对比、单次、不循环；正文屏仍以底色和光为主。禁止与字幕区重叠的强动效。
- **界面组件（卡片 / 网格 / 边框 / 图标 / 状态条）**：允许使用，但必须来自 `保留资料/动效库/` 的组件编号，由组件样式库提供类名与结构；模型只选编号、填文案和数据，不手写图形。组件样式同一支片子只统一一套（圆角、描边、间距），不同片子不复用同一套骨架。

仍然禁止：卡片、列表、图标、图表、进度条等具象 UI；canvas/WebGL 全屏背景铺满正文；无限粒子、随机漂移、循环呼吸。

实现白名单与展开代码见 `保留资料/动效库/能力卡.md` 与 `presets.json`；运行时为 `HTML视频项目/workflow_runtime/assets/vendor/motion-kit.js`，由 `sync_video.py` 在渲染前自动注入。

### 7.3 入场与图层所有权（2026-11-12）

「图片先以最终态闪一下、再入场一遍」和「元素在屏尾最后几毫秒才出现」是同一个根子：**同一层被两个地方写**，以及**入场被当成可选项**。

硬规则：

- **每个 `[data-anim]` 内容层（`media`、文字、组件、`scrim`）必须在自己屏内从不可见走到可见，走完一次入场**；屏的第一帧不得是它的最终态。不接受任何"直接存在"的内容元素。
- 唯一的例外是背景：`#stage` 的底色/光和本屏 `[data-anim="bg"]` 背景层必须第 1 帧就在（"背景直接存在"），不参与入场，也不允许晚于屏起点出现。
- **同一个元素只许入场一次**：不许先 `set opacity 1` 再 `fromTo 0→1`，也不许出现 `opacity 1 → 0 → 1`。
- **转场脚本只负责离场**：只写上一屏的推近、淡出、遮罩退开，在切点前落定；不得写进入屏任何 `[data-anim]` 的 `opacity` / `scale` / `clip-path` / 位移。硬切 = 这一刀什么都不写。
- 入场位置取屏内 0.15–0.6s；动效位置不得越过本屏结束，越界不再静默夹到屏尾，而是记违规并被门禁拦下。

拦截方式：

- `sync_video.py` 注入的 `scene-offset-runtime` 记录 `window.__motionViolations`：位置越界被夹到屏尾、转场在进入屏起点写透明度/缩放/遮罩。
- `check_html_timing.mjs` 逐帧（1/30）扫描每个 `data-anim`：首帧即最终态、没完成入场、`1→0→1` 闪回、背景不在屏起点，以及上面两类运行时违规，全部硬拦。
- `detect_blank_frames.py` 只判真正的孤立单帧（比紧邻前后两帧都暗、且两帧都亮）；多帧暗段和淡入淡出属于入场过程，不算，逻辑问题归 `check_html_timing.mjs`。

## 8. 口播、音乐和字幕

- `full` 使用 HeyGen 口播；`black-frame` 使用 MiMo TTS/提供音频。口播始终是主时间线。
- Dify 只生成 `voiceover_script` 和 HTML；MiMo TTS 在本地统一入口运行，音频落为项目的 `媒体/口播.mp3`。
- 字幕文案：默认按口播完整句子切分；把自写 SRT 放到 `字幕/手写字幕.srt`（或 `字幕/最终字幕.srt`）时，完全以该文件为准，跳过自动切句。
- 先确定最终语音，再由句子或词级时间码驱动场景、字幕和元素动画。
- `媒体/口播.mp3` 的实际时长是唯一主时钟。场景从作者期时间等比映射到真实口播时长；每个场景再通过 `data-sentence-ids` 与字幕 `data-sentence-id` 锚到对应完整句子的真实起始时间；元素动效的相对偏移和相对时长使用同一比例。禁止对已校准场景、字幕或媒体时间二次缩放。
- 同步后场景总时长、根 `data-duration`、口播、BGM、成片视频和成片音轨必须一致；字幕不得越过成片结束时间。渲染后执行 `normalize_final_audio.py`，再执行 `check_final_video.py`。
- 说到搜索、数字、流程或 CTA 时，对应视觉元素同步出现。
- 全片字幕按完整句子呈现：每个 `。！？!?` 结束的完整句子单独一条，不按字数截断或拼接半句。
- 默认字幕规格（本地注入，可改）：中下方 `bottom:13%`，水平居中，**文字宽度随内容自适应**（`width:auto`，上限 80% 画布宽度，多行时自动换行），字号 45px、行高 1.35、字重 700、白色文字；无底板、无描边、无圆角、无内边距，只用双层柔和黑色投影保证亮背景可读。字幕不得用整条背景板或全屏遮罩。
- `full` 不遮挡数字人和产品 UI，`black-frame` 不遮挡产品 UI。
- 背景音乐不能压过口播，自动补齐到实际成片时长。
- ASR/HeyGen transcript 只提供时间码；字幕文字必须使用已批准 `voiceover_script` 自动校正同音字和错别字。若没有 transcript，本地 ASR 只作时间码回退，最终仍需人工检查断句。
- 本地 ASR 会重试两次；仍失败且项目有 `口播文案.txt` 时，`sync_video.py` 按完整句子和字数比例把音频时长分配给字幕与页面，并写 `字幕/估算说明.txt`。这是应急模式，页面切点和动效 cue 只能近似，不能当成交付标准；修好 ASR 或补 `字幕/口播时间码.json` 后必须重跑。

## 9. Storyboard 与动效计划

分镜至少表达：

- `voiceover_text`
- `argument_id`
- `visual_source`
- `visual_brief`
- `on_screen_text`
- `transition`
- `sync_rule`

动效计划必须与口播 cue 对应，不能先列后续信息，也不能只给通用“淡入/缩放”。A10 给出的 `target` 就是单屏场景节点要写的 `data-anim` 名字，H02M 按同一批名字写选择器。

## 10. 最终质量门禁

检查分三级：**渲染器跑不起来、产物结构残缺、页面时间线断裂（整屏不可见/图片闪回）会拦流程**。拦截项：缺 `#stage`、缺字幕占位、没有 `window.__timelines`、没有 GSAP 动作、用了 `requestAnimationFrame`/`performance.now`、输出里残留工具调用文本、缺 `</html>`、`<style>`/`<script>` 开闭不配对、标签里属性引号未闭合、有口播句子找不到对应场景。版面、动效密度、构图、内容诊断、动作越界和动效同质化默认只报告，不阻塞渲染——成片优先，问题留给人看；构图一项可以显式打开 `STRICT_COMPOSITION=1` 变硬拦。`check_html_timing.mjs` 在渲染前逐 0.2 秒 seek，整屏不可见或图片 `1→0→1` 闪回直接拦。

内容侧另有一条门禁：A12 判 `rejected` 时 A16 拒绝打包，`package_error` 里列出原因；`needs_changes` 不拦，留给人工改。

上面这组拦截由 `check_html_contract.py` 在渲染前判定，任一命中就停止，不再"渲出来再说"：一条缺场景、动效归零或被截断的 HTML，渲出来只是几十秒黑片/静帧，人工复核也救不回来。

- [ ] 画布为 1080×1920；场景构图、布局手法（flex/grid/绝对定位/全出血）由模型自由设计。
- [ ] 实际时长符合内容需要，音画时长差小于 100ms。
- [ ] 口播、场景、字幕和元素动画逐句同步。
- [ ] 每个中段镜头建议至少一次可见语义动效，具体动作和密度由模型根据内容决定。
- [ ] 相邻两屏的文字出现方式不同，全片没有把“半透明变实 + 位移”当成唯一入场。
- [ ] 相邻两屏、首尾两屏不是同一套构图骨架；全片构图族不少于 min(4, 屏数)（`check_composition_variation.mjs`）。
- [ ] 每屏有 `data-voiceover`（逐字等于这一页的口播片段），页长由下一屏起点决定，不按作者期时长在句内切。
- [ ] 每屏第一帧就是纯背景（底色 + `bg`），随后 0.6 秒内内容开始入场；每个 `data-anim` 内容层都有且只有一次入场，没有"首帧即最终态"，没有 `1→0→1` 闪回（`check_html_timing.mjs` 逐帧拦）。
- [ ] 转场脚本没有写任何进入屏的层；硬切就是什么都不写。
- [ ] 转场脚本位置是绝对秒（`__absolutePositions` + `__sceneStart`/`__cueAbs`），没有裸 `cue()` 或代理对象写 scene `opacity`。
- [ ] 无图屏（`role=html`）带 `data-visual="html"` 和 `data-anim="bg"`，背景是设计过的结构，不是纯色空白；整片至少有一张真实照片。
- [ ] 每个时刻只出现一条完整句子字幕，句末标点完整，无截断和半句拼接。
- [ ] 首句就是主张，不是过程描述；全文只讲一个主张。
- [ ] `argument_coverage` 覆盖 `argument_order` 全部论点，没有漏讲。
- [ ] 没有时间线流水账，没有整句照搬素材（回看 `content_diagnostics` 的 `chronology_words` 与 `verbatim_ratio`）。
- [ ] 字幕位置、80% 最大宽度、45px 字号、1.35 行高和无底板文字符合固定规格。
- [ ] 回看 `check_html_layout.mjs` 的报告：文字有没有互相叠压、内容有没有出界（报告不阻塞渲染）。
- [ ] `full` 必须保留 HeyGen 数字人小窗，且不遮挡关键内容；位置和尺寸由本次构图决定。
- [ ] `black-frame`（无数字人模式）零占位，不包含数字人窗口、avatar 角色、数字人媒体、黑帧小窗、纯黑保留区或等价空白窗口。
- [ ] 示例数据明确标注，不冒充真实产品 UI。
- [ ] 数字、案例、英文词和多音字读音正确。
- [ ] 案例、价格、CTA 和产品事实已确认。
- [ ] 响度约 -14.5 LUFS，True Peak 不高于 -1.5 dBTP。
- [ ] 若项目提供 `npm run quality:video`，执行并通过。
- [ ] 最终保留 MP4、SRT/字幕时间码、最终口播和 storyboard JSON。

## 11. 运行时边界

- `workflow_runtime/` 只保存通用模板、脚本、资产和工具。
- 每个项目使用独立目录，不把运行结果写入 `workflow_runtime/`。
- `Dify输出/` 保存原始 TXT、统一 JSON 和解析后的 HTML/HeyGen 响应。
- 最终项目字幕保存在项目自己的 `字幕/` 目录。
